# Quick 260728-0vd: the drawer shell takes ownership of its own insets

## Why

One diagnosis behind four defects: **the shell supplies nothing, so each of the ~19 drawers has to
remember for itself.** That rule has no enforcement, and it has now measurably failed - the
transaction receipt pads vertically only, so its labels touch the panel's left edge and its values
slam the right one. Seventeen drawers have not been walked since the shell header change, so it may
have failed there too.

Sketch 067-A makes this urgent rather than cosmetic: with no section cards, **whitespace is the
only thing grouping drawer content**, so it cannot depend on whether someone typed it in that
particular drawer.

## Task 1: body inset

`kDrawerBodyPadding` = `fromLTRB(space10, space12, space10, space10)` - promoted from
`_SlippageForm`, the one drawer that got it right. Exposed as a `bodyPadding` parameter so a
drawer owning a **scrolling viewport** can pass `EdgeInsets.zero` and keep the inset on its own
`ListView`; that is the half of 07-06's prohibition that was correct.

Then: remove the inset from every caller that would otherwise double it.

## Task 2: footer inset and top rule

`kDrawerFooterPadding` = `EdgeInsets.all(space10)`, plus the `borderSubtle` top rule 030-B1
specified and that exactly one drawer implemented. No opt-out - a footer is never a scrolling
viewport.

## Task 3: the close button (walk finding)

`✕` has `padding: EdgeInsets.zero` with 36x36 constraints flush to the panel edge, so its hover
circle bleeds outside the drawer while the title sits 20 inside. Put the glyph on the title's axis:
title 20 from the left, glyph 20 from the right.

## Task 4: `View on Explorer`

Change to `gradientOutline` at Jakub's request. This contradicts the standing CTA-weight rule, which
names this button as the canonical `secondary` - raise it before changing anything rather than
letting the code and the written rule drift apart.

## One runnable check

`test/components/responsive_drawer_body_padding_test.dart`. Assertions are the **delta** between a
padded run and a zero run rather than absolute coordinates, so they survive a change to the toolbar
height, the panel radius or the hairline and fail only when the padding genuinely disappears. One
test pins the "caller passed nothing" case - the one that failed on the receipt - and one pins the
`✕` axis plus the fact that its box never reaches the edge.
