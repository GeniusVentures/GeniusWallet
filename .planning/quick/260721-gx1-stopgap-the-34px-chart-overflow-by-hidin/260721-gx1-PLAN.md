**The measurement.** Column at `:315` gets `BoxConstraints(0.0<=w<=597.0, h=6.5)` and needs 40.5
(6.5 + 34.0). That Column is `[Expanded(LineChart), Row(4 × IconButton)]`, so **40.5 is the Row's
rendered height** and the `Expanded` chart is at zero. The creator chain
(`… ← CryptoLiveChart ← Expanded ← Column ← Padding ← Padding ← DecoratedBox ← Container`) matches
`ChartDashboardView` → `DashboardScrollContainer`, i.e. the dashboard card, not token-detail.

**Why 40.5 and not 48.** `IconButton`'s M3 box floor is `kMinInteractiveDimension` = 48. The ambient
`VisualDensity` on desktop is `compact`, which subtracts 8 — the *same* -8 that collapsed
`navChipShell`'s chips to 32px during quick `260721-ed9`'s walk (see `nav_chip_style.dart:14,32`).
So the row measures ~40 on Windows and 48 under a standard-density theme. **Do not assume 48 and do
not assume 40 — reserve the larger (48) and let a test prove it is an upper bound.** Over-reserving
hides the row slightly earlier than strictly necessary, which is the safe direction; under-reserving
re-opens the overflow.

## The threshold, derived

```
zoomPanRowHeight    = kMinInteractiveDimension = 48   (density-independent upper bound of the Row)
minChartHeight      = GeniusWalletConsts.space32 = 64 (smallest slice that is still a chart)
zoomPanMinSlotHeight = 64 + 48 = 112
```

`minChartHeight = 64` is not a round number picked for looks. With the buttons hidden, the hover
crosshair + tooltip is the chart's ONLY remaining affordance. That tooltip renders two lines (11px
time + 14px price, `:413-439`) inside fl_chart's default tooltip padding — roughly 46px — and
`fitInsideVertically: true` (`:393`) clamps it into the plot area. 64 (space32) is the smallest token
that clears that plus the 2.4px line and its gradient fill. Below ~46 the tooltip has nowhere to go
and the card degrades to a sparkline with no readout.

## What happens BELOW the threshold — stated, not glossed

Hiding the Row removes the overflow. It does not create height. At the observed 6.5px slot the card
renders: coin-identity header, timeframe segment, hero price, and a **6.5px hairline** where the
chart should be. That is not a fixed card; it is a non-overflowing broken card.

**The chart deliberately gets NO floor.** A minimum height cannot be imposed from inside this widget:
a `SizedBox(height: 64)` inside a 6.5px slot overflows by 57.5, which is the same bug with a
different number. The only real fixes are upstream (the dashboard card must give the chart more
height — `dashboard_screen.dart` is out of scope this task and recently changed) or structural
(delete the row — the open product decision). Both are recorded in the todo, not silently absorbed.
