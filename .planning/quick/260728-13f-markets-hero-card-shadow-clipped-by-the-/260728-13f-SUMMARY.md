# Quick 260728-13f - SUMMARY

Jakub, from a live walk: *"jest ucięty market box"*, with an arrow at the hero card's bottom-right.

## Diagnosis

The Markets hero card carries `GWDecorations.surface(...)`, whose `boxShadow` is
`GeniusWalletElevation.card` - **blurRadius 16**, offset (0, 4). The page's data view wraps
everything in a `SingleChildScrollView` whose padding was `fromLTRB(0, space6, 0, space20)` -
**zero horizontal**.

A scroll viewport clips its content. With no horizontal inset the card's 16px shadow was sliced
flat against the viewport edge, so the card terminated in a hard vertical line instead of a soft
raised edge - i.e. it read as cut off.

This is the same class of defect quick **260720-gzq** fixed elsewhere, whose own note reads
*"shadow blurRadius 16 needs clearance"*.

## Why the fix is not simply "add padding"

The zero inset was **deliberate** and documented: *"No horizontal inset: the hero + table align with
the 'Markets' page title above them (which sits at the outer 12px gutter)"*. Adding padding to the
scroll view alone would have pushed the card 12px out of line with the title - trading a clipped
shadow for a misalignment.

So the gutter **moved** rather than grew:

| | Before | After |
|---|---|---|
| page `Padding` (outside the viewport) | 12 / 12 | **0 / 0** |
| `GWPageHeader` | inherits the outer 12 | own `symmetric(horizontal: 12)` |
| data view `SingleChildScrollView` | 0 / 0 | **12 / 12** |

Title, hero card and table all still land on one axis; the difference is that the card's 12 is now
*inside* the clipping viewport, so the shadow has room to render. 12 of the 16 blur - the last 4 are
below visibility at this alpha.

## Caveat - this was NOT confirmed on screen

`screencapture` has no screen-recording permission from this process, so the diagnosis is read out

below visibility at fractional scroll offsets (the `RepaintBoundary` there was an earlier attempt at
exactly that). Re-open with that hypothesis if so.
