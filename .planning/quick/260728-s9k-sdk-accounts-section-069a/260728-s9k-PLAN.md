# Quick 260728-s9k - PLAN

Sketch **069-A "One door"**, chosen by Jakub 2026-07-28 after a verification pass that turned up a
seventh finding the sketch did not have.

## Design work

1. **Footer: two CTAs to one.** `Expanded` × 2 in a 420px panel gives 186px each and *"Add with
   private key"* + icon needs ~210, so both labels ellipsize. One
   `GWButton(gradient, lg, expand)` labelled **Add account**.
2. **The method choice moves into a single merged dialog** as a segmented switch built to
   `CONVENTIONS.md`'s **Control track** recipe (`surfaceSunken` + `borderSubtle` hairline +
   `radiusPill` + 3px track padding + 2px chip gap). Both add paths share one dialog, one warning
   and one field.
3. **Unify the row menu.** One `MenuAnchor` on EVERY row, four items in one order - Set payout
   address, Copy mnemonic, Show recovery QR, Delete account - with inapplicable ones **disabled
   (`onPressed: null`), never absent**. `Copy mnemonic` / `Show recovery QR` stay gated on
   `getSelectedAccountMnemonic() != null` (a private-key import has no phrase). `Delete` is disabled
   on the active account, because the SDK genuinely refuses it. The bare red delete `IconButton`
   goes.
4. **QR dialog onto `GWDialog`** - it is the only one in the section still a raw `AlertDialog`. The
   white QR backdrop STAYS: mode-invariant on purpose, required for scanning.
5. **Warn row** above the recovery-phrase field and above the QR only. Not on delete - the delete
   copy already says it in words.

## Bugs to fix, all found while verifying the sketch against the code

- **A false success.** `_confirmDeleteSDKAccount` shows *"SDK account deleted"* unconditionally,
  immediately after `add(DeleteSDKAccount(...))`, without checking anything - and
  `_onDeleteSDKAccount` does `if (result == OK) { emit }` with **no else**, so a refusal is silent
  at both layers. A refused delete currently tells the user it worked.
- **A result read one frame early.** `_showSetPayoutAddressDialog` reads
  `state.setPayoutAddressResult` synchronously after `add(...)`. A bloc is asynchronous, so it
  reports the PREVIOUS attempt, or `null` on the first call after a fresh start.
- **A silent seed-phrase copy.** `Copy mnemonic` is
  `onPressed: () => {Clipboard.setData(...)}` and nothing else - no confirmation, no snackbar, where
  every other copy in the app confirms.
- **No payout validation.** The field posts any string.

## Component honesty

Everything else is an existing component: `ResponsiveDrawer`, `GWSelectRow`, `GWButton`
(`GWButtonSize.lg` + `expand` verified), `MenuAnchor`/`MenuItemButton`, `GWDialog`/`GWDialogAction`,
`GWTextField`.

**The segmented switch is NOT a component** - `CONVENTIONS.md` has the recipe and there are already
**four** private implementations (`_TimeframeSegment` ×2, the transactions filter track,
`_PresetChip`). Built inline to the recipe here, and a todo filed: building `GWSegmentedControl` now
would ship a component with one consumer, which fails the promotion test 065 and 068 both used.
