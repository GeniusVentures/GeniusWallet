## The one design property that matters: ONE-SHOT, AUTO-CLEARING

**Decision: the fault auto-clears the moment it is consumed. It is not a sticky toggle.**

This is not a style preference — get it wrong and the walk produces a false negative. The whole
premise of 05-07 is that `accountStatus` is the ONLY reachable failing status and that `LoadWallets()`
alone cannot clear it. If the injected fault persisted, pressing Retry would re-fail, the error branch
would re-render, and the walker could not tell "the Retry button is broken" from "the fault is still
armed" — which is precisely the failure mode the walk exists to detect. A one-shot fault makes the
observation unambiguous: press Retry, and the app either comes back (Retry works) or it does not
(Retry is broken).

Two corollaries the executor must honor:

1. **Arming SETS the counter to 1, it never increments.** An impatient double-press must not queue a
   second failure that would then eat the Retry.
2. **The arm button dispatches `FetchAccount()` itself, immediately after arming.** An arm-only
   button would need an app restart to take effect — and the singleton's state dies with the process,
   so an arm-only button would be *unusable*, not merely inconvenient. Arm-then-dispatch means the
   error branch appears the instant the button is pressed, on whatever screen the walker is on.

## Where the hook lives, and why release safety is not at risk

The hook lives in `lib/bloc/app_bloc.dart`, at the top of `_onFetchAccount`'s existing `try`
(`:166-171`). That is the only place that produces a genuine `accountStatus: AppStatus.error`, and the
handler already has the `try`/`catch (_)` that turns a throw into that state — so the injector only
has to make the call fail. It does NOT need to touch `emit`, the catch, the handler registration
(`:42`), or `GeniusApi`.

`kDebugMode` and `kShowDevTools` (`dev_flags.dart:15`, a `const bool.fromEnvironment`) are BOTH
compile-time constants, so `kDebugMode && kShowDevTools && <consume>` is a constant-false condition in
a release build and in any debug build without the define. Dart's compiler eliminates the branch
outright — the injector is never called, never linked in through this path, and `_onFetchAccount`'s
executed behavior is byte-for-byte what it is today. This is exactly the rule `dev_flags.dart`'s
docstring lays down ("always combine with `kDebugMode` at the call site"), and the ordering is
load-bearing: the two consts come FIRST so the impure `consume` call short-circuits away.
