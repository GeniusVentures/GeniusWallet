# Quick 260727-w58: GWKicker + migrating five labels

## Why

The uppercase section label exists in five places and was hand-written in every one. They agree on
weight (`w600`) and colour (`textSecondary`) and disagree on size (10 / 11 / 13) and tracking
(0.4 / 0.5 / 0.6 / 0.7 / 0.88). Sketch 065 posed the question; Jakub chose variant **C - two steps**.

The task also has a consumer: transaction receipt **154-A** needs this label for its `TRANSACTION` /
`NETWORK` sections, and sketch **066** makes it the foundation of the remaining fourteen drawers.
Without a component, those two jobs would have added a sixth and seventh value.

## Task 1: the component

`lib/components/cards/gw_kicker.dart` (new)

- `GWKicker(String label, {bool dense = false, Widget? trailing})`
- `static TextStyle GWKicker.style(GWColors gw, {bool dense = false})` - for call sites that need
  the type but not the widget
- default: 13 / w600 / letterSpacing 0.5 / lineHeight 18/13 / `gw.textSecondary`
- `dense`: 11 / w600 / letterSpacing 0.6 / lineHeight 16/11
- upper-casing belongs to the component; callers pass natural casing
- **no `rule` flag** - variant D (the hairline) was drawn and not chosen, so the code carries no
  parameter that nothing renders

## Task 2: migrate the five call sites

| File | How | Visual delta |
|---|---|---|
| `transactions_slim_view.dart` | whole widget, default | tracking 0.7 -> 0.5 |
| `token_info_screen.dart` `_buildSectionTitle` | whole widget, default | tracking 0.4 -> 0.5 |
| `markets_hero_card.dart` `_Stat` | whole widget, `dense` | **10px -> 11px** |
| `markets_table.dart` `_header` | `GWKicker.style(dense)` only | none - values identical |
| `gw_view_all_link.dart` | `GWKicker.style(dense)` + `height`/`color` | tracking 0.88 -> 0.6 |

The last two are interactive (sort state + arrow; hover + underline + arrow) and stay their own
widgets - a component that grew hover, an active state and two trailing geometries would stop being
a label.

## Task 3: one runnable check

`test/components/gw_kicker_test.dart` - pins both steps numerically AND asserts that
`GWKicker.style()` returns exactly what the widget renders. The second half is the real guard: two
call sites consume the static style instead of the widget, so if those paths ever diverge the drift
is back with a component's name on it.
