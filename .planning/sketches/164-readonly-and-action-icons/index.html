Sketch 164 · Read-only field + coin-page action icons

Two questions off the 2026-07-29 walk, both on the coin page, both about the same thing: a control has to say what it is before it says anything else. S1 asks how a value you cannot edit should look. S2 asks how the Receive / Swap actions should look when they sit next to a 26px coin name. Everything below is at 1:1 and built from the real tokens.

S1 · The read-only Token price

Today: a GWTextField with readOnly: true, a surfaceSunken fill, the component's default borderSubtle edge, the value at full textPrimary, and a bordered READ-ONLY chip in the suffix slot. The chip is doing the entire job of saying "not yours", because nothing else on the box says it - it is the same height, the same radius and nearly the same edge as the field directly beneath it, which you can type in.

The constraint that decides this

The obvious move - grey the value out - is not free. Measured against the fill it would sit on:

pairingdarklightAA body 4.5:1
textSecondary on surfaceSunken6.20:14.23:1 pass / FAIL light
textPrimary on surfaceSunken20.04:112.47:1 pass both
textPrimary54 on surfaceSunken (today's chip)6.03:1- pass

So "just grey the font" ships an AA failure in light mode at 4.23:1. Any variant below that dims the value has to carry that cost or pick a different fill; the ones that keep the value at textPrimary and change the frame instead have no such problem.

★ A · Detail row. Four reasons, in order of weight: it is the only variant where the control is not an input, which is a stronger statement than any label on an input can make; the card already ships that exact row one line below, so it costs no new language and no new component; it keeps the value at textPrimary and therefore has no light-mode contrast debt; and it removes a wart the code comments already complain about - a readOnly field still takes focus in Flutter, so today's box can be tabbed into and light up promising an edit that cannot happen.
Runner-up: C · Locked field. If the two-field symmetry of the Convert card is worth keeping - and there is a real argument that it is, since the card is a calculator and calculators have input rows - C is the cheapest honest version. It needs a light-mode answer for the dimmed value first.
Rejected: D · Prefixed. A box with no tag, no lock and a full-weight value is close to the state that made someone add the READ-ONLY chip in the first place. Removing the chip without replacing the signal re-opens the original defect.

S2 · The Receive / Swap action icons

Today both are GWButton.icon(variant: ghost, size: md) - 48x48, glyph 20px, textPrimary, transparent fill and no border at rest. Two separate things are wrong and they need separating, because fixing one does not fix the other.

1 · The glyph. Icons.qr_code_2 is a dense 2D matrix - finder squares plus a data field. Rasterised into 20px it stops being a QR code and becomes noise, which is exactly what the walk screenshot shows. 2 · The container. ghost draws nothing at rest, so both actions float beside a 26px coin name with no edge to say they are pressable.

★ C · Contained + brand glyph, with call_received for Receive. The container is the half that matters: a control identified only by its glyph has no resting boundary, and the walk found it by eye without being told to look. Tinting the glyph answers the "add some colour" ask without spending the one filled CTA a surface is allowed. The glyph swap is separable - take the container and keep qr_code_2 if the QR meaning is worth more than the legibility, but do not leave both as they are.
Runner-up: A · Contained, glyph unchanged. Everything C fixes structurally, none of the colour. Pick this if the brand tint on two secondary actions reads as too loud next to the price.
Rejected: D · Labelled pills. Not because it is wrong - it is the most legible option on the page - but because the identity row already carries a 26px name, a symbol, a network and a 30px price, and a third action appears on GNUS coins. Three labelled pills there is a toolbar competing with the heading.

What this sketch does NOT decide

The Markets hero chart. It is a different question with a measured blocker attached - the card grows by the chart's full delta, so any taller frame there is a layout decision, not a styling one - and it is written up separately rather than smuggled in here.
