030 · Status pill placement — design A (Status only)

Design A, three placements of the same Status pill. Only the pill's position changes; everything else is identical. Rendered at real size, real navbar, real rows, at ~1400px (fullscreen). Status = transactionStatus (completed·pending·failed·cancelled, transaction.dart:14). The empty band shows where the row's slack lands in each.

A1 · Status hugs the description left

The pill sits right after the token/action block (GNUS · Processing job → Completed). Reads as a property OF that transaction, close to what it describes. All the slack collects between Status and the amount, so the amount still anchors the right edge. Downside: the pills don't line up in a clean vertical column — each starts wherever its description ends.

A2 · Status beside the amount — FINAL alignment chosen

The amount column is a fixed width sized to the largest amount (all amounts right-align inside it, flush to the card edge). The Status pill is right-aligned a constant 12px (space6, the same gap as time↔coin) to the left of that column — so every pill's right edge lands on one vertical line (the dashed guide), no matter how wide the label is. Description grows to fill the middle. Left-side gaps are untouched.

A3 · Amount first, then Status far right

Amount stays where it is and Status moves to the very right edge, past the numbers. Gives Status the strongest end-of-row emphasis, but it pushes the amount off the right edge — the thing you just asked to be flush right no longer is, and a right-aligned money column that doesn't end the row reads oddly. Shown for completeness.
