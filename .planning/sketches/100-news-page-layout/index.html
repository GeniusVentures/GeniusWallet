100 · Crypto News — what is this page?

Every variant renders the same ten articles, with the same fields the RSS feed actually returns (title, description, pubDate, imageUrl, link). Photos are CSS gradients so the sketch needs no network. Search filters live — type in it. What changes between A, B and C is only what the page is for.

A · Dense feed

recommended reuses shipped components

Headline is the hero, photo demotes to a 104×72 thumbnail. Ten articles fit in one screen instead of four. Row hover is the lift chip from sketch 008 D — the same hover the nav and timeframe tabs already use — so the photo is never covered. The description finally appears as a one-line dek.

withdrawn — the live feed does not support it rail already designed in 021 + 022

Cost of each variant

A · Dense feed
Cheapest
Drops flutter_staggered_grid_view entirely — a ListView.separated replaces it. One dependency lighter. Search is a local where() over the already-fetched list; no network, no state store. Nothing new to parse.
B · Magazine
Cheap
Also drops the staggered grid: hero + GridView with a fixed aspect ratio. Keeps the photo-forward identity, so it is the smallest visual jump from what ships. Loses on density — still ~4 stories per screen at 1280.
C · Feed + rail — withdrawn
Cost is real, benefit measured to zero
Would need <category> parsing, a List<String> field on NewsArticle, and the rail widget — against three real categories, one of which holds 25 of 30 items. If a rail is ever wanted here, the axis has to be coins named in the title, not RSS categories. That is a feature with a matching problem attached, and it is out of scope for this round.
