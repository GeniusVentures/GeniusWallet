029 · Transactions — filling the wide-screen row

The problem: now that the amount is flush right, a fullscreen row has a cavern between the description (far left) and the amount (far right). Fill it with columns that carry real per-transaction data — all grounded in transaction.dart, nothing invented. Rendered at real size, real navbar, real rows, at ~1400px (fullscreen). These columns appear ONLY on the wide page; the narrow panel keeps today's compact two-part row.

Grounded fields: transactionStatus (pending·completed·failed·cancelled), fees, hash, timeStamp — all on transaction.dart:74-134.
Not added: Type (already the chip beside the token), Network/chain (no such field — only coinSymbol/isSGNUS, so it would be invented).

A · Status pill only lightest

One column: a Status pill in the cavern. This is the field you named, and it is currently jammed into the subtitle ("Card purchase · Failed") where it is easy to miss. Promoting it to a pill both fills the gap AND de-clutters the subtitle. Cleanest option; leaves most whitespace.

B · Status + Network fee recommended

Adds a right-aligned Fee column (fees) beside Status. Fee is real on every on-chain transaction and is exactly the number people scan a ledger for; giving it its own column stops it fighting the amount for the value-line. Two columns balance the row at fullscreen without turning it into a spreadsheet. A tiny column header (STATUS · FEE · AMOUNT) appears once at the top so the columns read as columns. Best balance.

C · Status + Reference + Fee densest

Adds a monospace Reference column — the truncated hash (0x9f…4a87), click-to-copy — the ledger-standard "which transaction is this". Three columns fill the widest screen fully, but it starts to read as a data table rather than a wallet, and the hash is a power-user detail most people never click. Take this only if the tab is meant to be a proper explorer-style ledger.

Below the breakpoint — unchanged

The extra columns are a wide-only affordance. Under GeniusBreakpoints.large (1024) the row collapses to exactly what ships today: no cavern to fill, so nothing is added and Status stays in the subtitle. One row widget, one boolean (wide) — same discipline the page already uses, no dimension derived from constraints.
