Sketch 177 - the Assets page

Home will show the top 5 holdings behind a View all. This is where that link lands. Every variant is clickable - filters, sorts, expanders and search all work. Use the FUNDED / EMPTY switch under each phone: Jakub's real wallet has every balance at zero, and a page that only looks right when full is a page that looks broken most of the time.

Why this page has to exist

Phase 25 caps the Home dashboard at top 5 assets so the page has one scroll instead of four. Transactions and Markets already have full screens to send you to - /transactions and /markets are real routes. Assets has nowhere to go. There is no /assets route today.

The screen almost exists already. CoinsScreen takes an isDashboard flag; when false it drops the section header and renders the full list. So this is mostly a route plus a layout decision, not a new screen from scratch.

The constraint that decides this
Every balance in the real wallet is 0.0000. Look at the phone on any tab and flip to EMPTY. A design that sorts by value, draws an allocation bar, or leads with a big total has nothing to say in that state - and that is the state Jakub actually sees today. The variants differ mostly in how gracefully they collapse when there is nothing to show.

The app also already ships a WCAG fix in this exact area: zero balances were painted at textPrimary38 (3.54:1, failing AA) and are now textPrimary80 (12.4:1). So "grey out the empty ones" is not available as a shortcut - it was just removed on purpose.

What every variant shares
  • A back row to Home, because this is a pushed screen, not a tab
  • Portfolio total with 24h change
  • Rows that open the coin page
  • The bottom bar stays - it is inside the shell
A - total, then everything
A - the plain list

Total at the top, then every asset the wallet knows about, GNUS first and the rest in fetched order. Exactly what CoinsScreen(isDashboard: false) renders today, given a page header and a total.

Try EMPTY. This is the variant's whole story: with no balances it becomes a wall of identical $0.00 / 0.0000 rows and the total says nothing.
Built from
  • exists everything - no new component at all
Cheapest by a wide margin. One route, one flag, a header. If the goal is only "View all has somewhere to land", this ships today.
But it answers no question beyond "what tokens exist". It cannot tell you what you hold without you reading every row, and it is the worst of the five when empty.
B - All / Holdings / Watch
B - one segmented filter

A GWControlTrack under the total: All, Holdings, Watch. Holdings shows only funded assets; Watch shows the zero-balance ones you could hold.

Tap the segments. Then flip to EMPTY and tap Holdings - the empty state is honest and specific there ("nothing yet, here is how to get some") instead of a wall of zeros.
Built from
  • exists GWControlTrack - its fifth consumer, same recipe as the timeframe segment and the transaction filter bar
  • exists CoinCardRow, totals helper
Strong fit with the app's own language. The transactions panel already filters exactly this way, so the gesture transfers. It gives the empty wallet a place to stand.
The cost is a control the user must discover and operate. With 6-8 assets, a filter may be solving a problem the list does not have - and "Watch" implies a watchlist feature that does not exist. Naming it wrong here would promise something the app cannot do.
C - the structure does the filtering
C - grouped by whether you hold it ★

Two sections. Your holdings, sorted by value, largest first. Then Other assets, collapsed behind a single row that says how many there are. No control to find, no state to remember.

Tap "Show 4 other assets". Then flip to EMPTY: the holdings section is replaced by a single honest sentence, and everything you could hold is still one tap away.
Built from
  • exists GWKicker section headers, GWCard, CoinCardRow, the totals helper
  • adapted the same two-section shape sketch 174 gave the accounts sheet (SDK Accounts / Your Accounts) - so this page and that sheet read as one system
  • new the expander row
It answers the question without being asked. "What do I hold and what is it worth" is the reason anyone opens an assets page, and C puts that at the top, sorted, with nothing else competing. The zero-balance tokens stay reachable but stop being noise.
It degrades best. Every other variant needs balances to make sense. C's empty state is a complete, non-embarrassing screen - which matters because that is today's real state.
One honest cost: a collapsed group hides things, and a user who does not realise USDC is behind the expander may think it is missing. The row states the count for exactly that reason - and it starts expanded when there are no holdings at all.
D - search and sort
D - search plus a sort control

A search field, and a sort link cycling Value → Name → 24h. The power-user answer.

Type in the search box and tap the sort link a few times - both are live.
Built from
  • exists CoinCardRow, the totals helper
  • new a search field on this surface, and sort state to persist
The list is too short to need this. A wallet holds 6-10 assets; search earns its place at 50+. Sorting by name is a rare want, and sorting by 24h is a markets question that /markets already answers properly.

Included because it is the obvious "make it a real page" instinct, and because seeing it makes clear how little it adds here. If the asset list ever grows past a screen or two, revisit it.

E - allocation first
E - portfolio, not list

Total, then an allocation bar showing what share each holding is of the portfolio, then the holdings. Treats the page as a portfolio view rather than an inventory.

Compare FUNDED and EMPTY. The bar is the most informative thing on this page when there is money, and the most awkward when there is not.
Built from
  • exists totals helper, CoinCardRow
  • new the allocation bar and its legend
Genuinely the most useful at a glance of the five, for a funded wallet. One look tells you concentration, which no list can.
Two problems. It collapses in the empty state - an allocation bar of nothing is a grey stripe. And with 2-3 holdings the bar tells you what the rows already told you, which is most wallets most of the time.

Worth revisiting once real portfolios exist. Not the first version of this page.

Where I land
★ C - grouped by whether you hold it. It answers the page's actual question ("what do I hold, what is it worth") at the top without asking the user to operate anything, it keeps every zero-balance token one tap away, and it is the only variant whose empty state is a finished screen rather than a degraded one. It also reuses the two-section shape sketch 174 gave the accounts sheet, so the two surfaces read as one system instead of two ideas.

Runner-up: B. If you would rather have an explicit control than an implicit structure, B is the same idea with a GWControlTrack doing the work - and that track is already the app's standard filter gesture. Take B over C if you expect people to switch views often. Rename "Watch" to something the app can honour.

Rejected: D. Search and sort for a list of eight. E is a good second version once portfolios are real; today its centrepiece is empty. A is the fallback if the answer is "just give View all somewhere to land this week" - it is genuinely one route and one flag.
