Where the two kinds of account come from

Checked in the code. Your model was right, but the difference runs deeper than "one earns, the other swaps" - these are two different systems that today sit in one list.

The biggest finding: these are TWO INDEPENDENT AXES, not two kinds of the same thing. Picking a wallet in the drawer only calls walletCubit.selectWallet() - that is, it says "what am I looking at". Which SDK account is active on the node is set by a completely different control: sdk_account_manager.dart:185 sends SelectSDKAccount → api.selectGeniusAccountAsync. The highlight in the list and the node's active account are two different states that can point at different accounts - and nothing in the UI says so.
Second: SDK accounts disappear without a word. app_bloc.dart:606-609 - if !connection.isConnected, the function returns the private wallets alone. SDK accounts evaporate from the list with no message. Tap the "Node connected" chip in the sheet to see it.

What I changed in the design

  • Two separate sections with headings instead of one list. Today _mergeSgnusWallet() glues them into [...sgnusWallets, ..._baseWallets] - SDK accounts sit on top, but with no marking at all.
  • One sentence of explanation under each heading - because "Super Genius Wallet 1" tells nobody anything.
  • Balances in their real units: minions in green for SDK, the network currency for private ones. A shared "$0.00" column would be a lie.
  • A separate "ACTIVE ON NODE" badge - it splits the two axes apart. Inactive SDK accounts carry a "Set on node" button. New
  • A disconnected state with an explanation, instead of a silent disappearance. New
  • The payout address visible in the SDK section - today it is hidden in _showSetPayoutAddressDialog. It is what joins the two worlds: node earnings land in your private wallet.
  • "View only" on a tracking wallet - because you cannot send from it.
  • No "Manage wallets" as a separate item - management is per row, as in account_drawer.dart.
Pick an SDK account in the sheet - the asset list switches to Minions, because the balance comes from the native SDK, not from RPC. This is not cosmetic: wallet_details_cubit.dart:198-206 really does use a different data source.
