073 · Small icon actions on the coin page

Jakub: “te małe ikonki mi się podobają i myślę, że to będzie nasza droga do pójścia” - so this is sketch 072’s rejected C direction, taken seriously and given five placements. Everything else on the page is 070-A and 071-B, shipped today.

The action set is 072’s, unchanged and non-negotiable: Receive (real), Swap (built, needs one line to wire), Bridge (real, GNUS only). No Send - it does not exist in the code. Use the Live actions switch: the count genuinely changes by which route you took into the page.

“Small” has a floor, and this app already set it

The glyph gets small. The target does not. GWButton’s sm size returns 44, and the line carries its own reason: return 44; // was 36 — touch floor (iOS 44). Someone already lowered it to 36 and reversed the decision. Going below 44 here would be re-making a mistake this codebase has already recorded.

So every variant below is a 44×44 hit area with a 20px glyph inside. That is what “small icons” can honestly mean: a small mark, a normal target. WCAG 2.5.8 (AA) asks for 24×24 as a minimum and 2.5.5 (AAA) asks for 44×44 - the app is already at the stricter one.
An icon-only button has to say its own name. With the label gone, the only thing carrying “this is Receive” is a glyph - so each one needs GWButton(tooltip:, semanticLabel:), both of which the component already has. Without them a screen reader announces nothing and a first-time user guesses.

Use the Labels switch. On hover is the compact version and the one the request implies. Always keeps a 10px caption under each glyph, costs 12px of height, and is the only version that works on a touch screen - where there is no hover to reveal anything.

The 1.32:1 edge is fine here, and the reason matters. A control’s boundary must clear 3:1 when the boundary is what identifies the control. On these buttons it is not - the glyph identifies them, at 10.9:1. This is the same argument GWSelectRow made on 2026-07-28: its selection tint measures 1.39 and its brand edge 1.60, and the check glyph at 6.81 carries 1.4.11 alone. Consistent, and written down there too.

Variant E is the exception worth watching: inside the grouped pill the buttons have no edge at all and sit on surfaceSunken, so the pill’s own outline is the only boundary - which is why E draws it at borderSubtle around the group rather than around each item.

Set “Live actions” to 1 and walk all five. That is the Markets route, which is the main way in, and today it is the state nobody has drawn. A single 44px glyph floating where a four-button bar used to be is the risk this whole direction runs - D and E take it worst, A and B absorb it because they sit inside a block that has other content.

Recommendation

★ A · Under the price. It costs zero new vertical height - the header's trailing slot is already as tall as the title block beside it, and the price + pill do not fill it - so the whole 74px action bar simply disappears from the page. Actions sit with the coin's numbers, which is what they act on, and with one live action it still reads as deliberate because the price is above it.

Runner-up: B · By the identity. The safest of the five and the best at one action, because a lone glyph under a name is a normal shape. It costs ~12px and it slightly miscategorises the actions as part of the title. Take this if A turns out cramped on the walk - the two are one Row apart.

Rejected: D · In the chart card. The prettiest, and it breaks on the state that is already shipped: the no-data page has no chart card (071-B), so the actions would move to a different place depending on whether CoinGecko covers the token - the same page, two layouts, for a reason the user cannot see.
