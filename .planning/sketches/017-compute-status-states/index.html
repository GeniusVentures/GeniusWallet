017 · Compute status — one component, nine honest states

Why this sketch exists. The shipped card has two status widgets stacked on top of each other (SGNUSConnectionWidget + SGNUSConnectionStatusWidget), and between them they cannot express three states the app actually enters. Worse, two of them render as something they are not:

1 · The 52.5% lie. sgnus_connection_widget.dart:85 draws a determinate CircularProgressIndicator from getInitializationStatus(). Measured over 161 polls / 40 s (spike 002, sketch 015): it reaches 0.525 at t=10.6 s and never changes again. A determinate ring is a promise that the number will reach 100. This one won't.

2 · The silent death. app_bloc.dart:193-196 — any exception from getProcessingStatus() cancels _processingTimer permanently and emits isProcessing:false. There is no path that ever restarts it. The UI then shows idle in grey: pixel-identical to a healthy node with nothing to do.

3 · The vanishing button. submit_job_dashboard_button.dart:25 → SizedBox.shrink().

Recommendation

A · Dot + label, with B's ring reserved for one place: the off-dashboard FAB. Rec

A is the only treatment that can tell the truth in all nine states. That is not a stylistic preference — states 3 (stalled) and 8 (telemetry dead) are states the app demonstrably enters, and B structurally cannot render them without lying, because a ring's whole grammar is "this will fill up". A drops the number and changes the word instead; the reader learns something true.

Where B still wins: at 56 px with no room for a label — which is exactly GWAiFab, the design branch's bottom-left floating action. Keep the ring there, and give the FAB the same rule: when there is no live percentage, no ring. Show the brain glyph with a small state dot instead.

Three code changes this design requires — flagging them now so they land in the plan, not as surprises:
1 · A stall detector: same percentage for N consecutive polls → switch state. Cheap; the poll already runs.
2 · A restartable processing timer. Today's permanent cancel() makes state 8's Retry impossible to wire — it needs an AppBloc event that re-arms the timer.
3 · The linked-wallet reason must reach the button. It already has both addresses (submit_job_dashboard_button.dart:22); it just throws the information away instead of rendering it.
