The txHash is never written to state. The tokens are burned, the user gets a red toast, and there is no hash anywhere. This state exists in shipped code today and has no design. Now it has one.

changed Shipped code drives both from one flag: isPurchaseable = jobCost != 0 && jobCost < gnusBalance (submit_job_screen.dart:65). Two consequences, both bugs:

Off by one. Strictly <, so a user holding exactly the cost is refused. It should be <=.

A false accusation. The same flag is false when jobCost == 0, so "cost not yet known" renders the line "* You do not have enough GNUS". The app tells a solvent user they are broke.

And the shortfall is now a number. Telling someone they are short without saying by how much makes them go and count it themselves.
