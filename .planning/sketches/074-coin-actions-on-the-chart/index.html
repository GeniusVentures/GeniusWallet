Verdict

The one finding that decides this

The chart card already owns an icon row. crypto_live_chart.dart:506 renders a centred Row of four IconButtons - zoom in, zoom out, back, forward - inside the same card. It is drawn in red in every panel above.

So putting wallet actions in that card means two icon rows in one box with categorically different consequences: one changes what you are looking at, the other moves money. Undo exists for the first and not for the second. That is not a spacing problem and no amount of alignment fixes it.

Worth knowing while you are here: those four icons are hardcoded Colors.white (a filed todo, 2026-07-21-chart-zoom-pan-icons-still-raw-colors-white), so in light mode they are white-on-light today. Any variant that sits next to them inherits that neighbour.
And the no-data page still has no chart card. Switch State → No market data. C1, D1 and D2 all put the actions inside a card that does not exist on that route - so they either vanish or have to be re-homed, which means the page has two different action positions for a reason the user cannot see. C2 is the only one of the four that does not move.

Recommendation

★ C2 · Above the card. It is the version of your idea that survives its own context: the icons sit on a section line outside the chart card, opposite a GWKicker, so they are visually “at the chart” without being in the box that already contains four icons with a different job. It is also the only one of the four that does not move on the no-data page - the section line stays, the card under it becomes the empty state.

Runner-up: D1 · Floating on the chart. Visually the best of the four - the glass treatment reads as premium and it costs zero height. Keep it in reserve for a version where the chart is a full-bleed hero. Not the pick because it shares a card with the zoom row and disappears on the no-data route.

Rejected: D2 · Shared bottom row. It looks like the tidy answer - one row, no new height - and it is the worst of the four: it puts Receive and zoom out on the same line, 6px apart, at the same size. The two things a user must never confuse end up as neighbours with identical affordance.
Honest note on my own recommendation. In sketch 073 I recommended A - under the price and it still wins on one measure the chart versions cannot match: it costs zero new vertical height, where C2 costs ~44px. If the page’s vertical budget matters more than the association with the chart, 073-A is still the better answer, and this sketch does not overturn it - it only shows the best version of the chart idea.
