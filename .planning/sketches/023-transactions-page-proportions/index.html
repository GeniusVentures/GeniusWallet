023 · Transactions page — vertical fit, fullscreen width, the All row

Both complaints check out against the code, and both are implementation slips rather than design decisions — which is good news, because it means the sketch does not have to be re-argued.

The vertical emptiness: transactions_slim_view.dart:346 uses CrossAxisAlignment.stretch, so both cards are forced to the full window height. Eleven rows is about 700px of list inside a 1400px card, and the rail has ~480px of content in the same 1400px box.
The missing separator: sketch 022 had All → rule → Type. The build does row(Filters.all) straight into _groupHeader('Type') with no rule, while the Status boundary above it does have one. Asymmetric by accident.

1 · Vertical fit — what the cards do when the list is short

All three at the same 1400px-tall window with the same 11 transactions. Scaled to 42%.

V1 · Stretch today
DashboardTransactionsSwap
Cards forced to window height. Two large empty boxes below the content. At fullscreen this is most of the screen.
V2 · Hug content Adapted
DashboardTransactionsSwap
One property: stretch → start. Each card ends where its content ends. With a long list the page scrolls, which is what a transactions history should do anyway.
V3 · Hug, then fill recommended
DashboardTransactionsSwap
V2, plus a floor. The list card hugs its rows but never gets shorter than the rail beside it, so the two cards stay visually paired instead of one dangling. Above the viewport it scrolls internally rather than growing the page.

Why V3 and not V2. V2 alone leaves a 480px rail next to a 210px list card when you filter down to one day — the rail then looks like the main content and the list like a footnote. V3's floor is the rail's own height, so the pair always reads as one object. It is still a bounded literal, not a value derived from constraints, so the freeze rule is untouched.

2 · Fullscreen width

At 2560px the 1280 cap leaves 640px dead on each side. But fix the vertical first and look again — much of what reads as "tragic at fullscreen" is the empty card height, not the side margin. These are the width options if it still bothers you afterwards.

OptionAt 2560pxCost
W1 · Keep 1280 recommended 640px margin each side, cards ~1280 wide. None. The row gains nothing past ~900px — the gap between the counterparty and the amount just grows. Margin is the honest answer to "there is nothing more to show".
W2 · Raise to xxl 1536 512px each side. One constant. Matches the Markets tab's cap. But it widens the gap inside the row, not the content — 15-05 measured that the row's useful width tops out well below this.
W3 · Widen the rail instead Rail 220 → 280, list unchanged. Uses width where there is content to use it (longer labels, no truncation risk). Small, and it makes the pair less lopsided at extreme widths.

3 · The All row

Four ways to seat it. All keep the counts, the active mark and the group order.

R1 · Rule after All what 022 said
Restores the sketch: All, hairline, Type…, hairline, Status. Symmetric with the Status boundary that already exists. Zero new vocabulary — it is the rule that was dropped.
R2 · All inside Type
Simplest structurally, but All is not a type — it spans Status too. Filing it under Type says something false about what it does.
R3 · Its own header
Gives All a "Show" kicker so all three groups are labelled. Consistent — but a one-item group reads as a heading looking for company.
R4 · Summary, not a filter recommended
Stops pretending All is a peer of the nine. It becomes the rail's total — big number, quiet caption — and doubles as the way back. The rule under it then separates a summary from a list, which is a boundary that explains itself.

R1 is the safe fix — it is one missing Divider, it matches the Status boundary, and it needs no new decision. R4 is the better answer to what actually bothered you: "All 11" sitting flush above a group header reads oddly because it is being drawn as a tenth filter when it is really the total. Making it look like a total removes the question instead of punctuating it — and it is also where the footer count went, so the number finally has a shape that says "this is the whole".
