The constraint that decides this. Four badge colours are already spoken for: green = money in, red = failed, amber = pending, slate = sent. Whatever Mint and Job get must stay distinguishable from all four at 18px, which is smaller than most colour intuitions assume. Two traps are flagged in red on the swatches below: brandSecondary #2BF5B4 sits only ~14° from statusSuccess #0AD89C — at badge size they read as the same green, so Mint would merge into Received. And any amber-adjacent choice collides with Pending.

Mint badge colour

TransactionType.mint — tokens created into the wallet. It is value arriving, which argues for green; but green already means "received", and a mint is not a transfer from anyone.

Processing-job badge colour

TransactionType.process — a GNUS compute job. It has no direction: it spends compute and returns a result. The only row type that is activity, not money.

All badges together — the confusability check

This is the test that matters: not "is this colour nice" but "can I tell these six apart at a glance, at 18px, in both themes".
