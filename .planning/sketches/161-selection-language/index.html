161 · Selection language

One mark for "this one is selected", across the whole app

Token Selector 1 is picked - the list in one 154-A card. Open question: what marks the selected row. Today it is a gradient tint fill; the ask is whether a gradient underline is better, and whether one component can carry selection everywhere. Each treatment below is applied to the picker and to the four other places in the app that already mark something as chosen - switch and watch both at once.

The mark shipped The underline is not a proposal, it is a shipped component with an exact spec, used identically in two places: responsive_overlay.dart:386 (nav tabs, 002-B) and submit_logs_screen.dart:713 (feedback chooser, 064-B). 3px, brandCta, rounded top r3, brandPrimaryStrong at 50% with blur 10, 200ms. Both files carry the same comment.
Precedent 022-B2 The underline was already chosen for a vertical list - the transactions filter rail, "the navbar's active-tab mark copied outright: w700 label never recoloured, 2px gradient rule beneath, glyph untouched". So the instinct has a precedent in this project, on a column of rows, not just on a tab strip.
Against it explicit HANDOFF.json records the opposite decision for exactly this case: roll 064-B out to "transactions filter chips, markets timeframe tabs, web tab strip - NOT to list pickers, 032-A1 decided those separately and differently". This sketch reopens that, which is legitimate - but it is a reversal, not a gap.
Geometry measured The filter rail has no dividers and no card. This list has both. A 3px underline sits at the row's bottom edge - which is exactly where the next row's 1px borderSubtle divider is. Press Mark the clash to see the two lines meet. In a tab strip there is nothing below the tab; in a list there always is.
