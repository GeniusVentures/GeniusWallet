The argument this change knocks out, stated before any pictures. Sketch 183 shipped scheme F - the wallet keeps a hairline chip, the hamburger goes bare - on one specific claim, quoted from its README: "the wallet icon holds a value - which wallet, and through the 16px badge which chain - and its content changes when that value changes. The hamburger holds nothing." That asymmetry is the whole reason F beat scheme A (both chipped) and scheme C (both bare), and the shipped HeaderMenuButton doc restates it in the code.

A generic wallet glyph has no value in it. Its pixels are identical for every wallet, every chain and every state but one. It is strictly less identifying than the avatar it replaces, which at least varied by currency. So both controls are now the same kind of object: a value-free door to a sheet - and the similarity F said "is not there" is now there. By F's own reasoning the pair should match, which points at 183 scheme C, the fallback Jakub already reserved when he said let's try 183F, and fall back to 183C later if it turns out badly.
