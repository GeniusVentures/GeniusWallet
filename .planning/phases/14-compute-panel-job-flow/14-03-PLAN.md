  <files>lib/components/data/gw_status_dot.dart, test/components/gw_status_dot_test.dart</files>
  <behavior>
    - With no trailing value the row lays out at its minimum width, matching how the two shipped pill
      forks use it.
    - With a trailing value the row fills its width and pushes the trailing value to the far end.
    - With no label colour supplied the label renders in the primary text token, not in the dot's
      colour. That single parameter is what lets one widget serve a coloured-label pill and a
      neutral-label status row.
    - The rendered row measures 18 logical pixels tall.
    - A trailing percentage that changes does not shift the label, because the trailing value carries
      tabular figures.
  </behavior>
  <action>
Create `lib/components/data/gw_status_dot.dart` exporting a stateless `GWStatusDot`.

Parameters: a required dot colour, a required label, an optional label colour defaulting to the
primary text token, an optional trailing value string, and optional size and gap defaulting to the
shipped values.

**Adopt the shipped geometry verbatim.** Both existing forks are a 6 logical-pixel circle, a 5-pixel
gap, and the label at the medium label type at weight 600 -
`transaction_displays.dart:99-113` and `banxa_components/order_status_style.dart:87-99`. Taking those
exact numbers is what makes this an extraction rather than a new invention, and it is also what keeps
the row at an 18px line box, which the height budget in plan 07 depends on.

The component owns: the circle, the gap, the label's type, the trailing value's type, and the row's
main-axis sizing. The trailing value renders at the same type as the label with tabular figures, so a
ticking percentage does not make the label jitter sideways.

The component does NOT own a pill, a wash, or any padding. Both shipped forks wrap it in their own
decorated container and pass their foreground colour as the label colour; the compute panel passes no
label colour and gets the primary text token. Say that in the class doc comment - it is the design
decision that makes one widget serve both.

Main-axis sizing: minimum when there is no trailing value, otherwise fill and space the two ends
apart. The pill forks need the former, the compute tile needs the latter.

The label takes a single line with ellipsis overflow. A wrap would add a second line box and break
the height budget silently, and this file sits in a component directory that other dashboard code
imports.

Write the class doc comment in the house style used by `gw_kicker.dart:6-13` and
`gw_warning_note.dart:10-13`: name the forks it was extracted from with their file paths, state that
their migration is deliberately out of this phase's fence and which phases own them, and note that
the geometry was copied rather than chosen so those migrations are a zero-repaint change.
  </action>

  </verify>

`GWStatusDot` renders a 6px dot, a 5px gap and a label at the medium label metric. The test asserts
the 18px height, the two main-axis modes, and that an absent label colour yields the primary text

  </done>
