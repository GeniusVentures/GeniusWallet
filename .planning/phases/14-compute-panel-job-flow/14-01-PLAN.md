<task type="auto" tdd="true">
  <name>Task 2: The pure eight-state resolver and its view model</name>
  <files>lib/dashboard/compute/compute_state.dart</files>
  <behavior>
    - Given no selected wallet, the result is the no-wallet state regardless of every other input.
    - Given a disconnected SGNUS node AND a wallet address that differs from the node's, the result
      is disconnected, not not-linked. This precedence is the point: `wallet_overview.dart:179`
      passes an empty string for the node's wallet address when there is no connection, so without
      this ordering every wallet tests as "not linked" and the user is falsely accused.
    - Given a connected node whose wallet address is empty, the result is never not-linked. The
      emptiness guard is new in this phase.
    - Given the processing feed flagged unavailable, the result is unavailable, and it outranks
      starting-up, processing and ready.
    - Given an init percentage below 1.0 and no higher-ranked condition, the result is starting-up.
    - Given a job that finished inside the completion window, the result is job-complete; outside the
      window it decays to ready. Both never resolve at once.
    - Given `isProcessing` false and a leftover percentage of 87.0, the view model shows no bar and
      no percentage readout. The bar is derived from the state, never from a percentage being
      non-zero.
    - The eight view models are pairwise distinct as tuples.
  </behavior>
  <action>
Create `lib/dashboard/compute/compute_state.dart`: pure Dart, no Flutter import at all. Model it
directly on `lib/dashboard/bridge/bridge_cta_state.dart` - the same doc-comment discipline, the same
"colour mapping stays at the call site" split, the same top-of-file explanation of the precedence
rule.

Declare `enum ComputeState` with exactly eight members covering: no wallet, not linked, starting up,
ready, processing, job complete, status unavailable, disconnected.

**Ship eight members, not nine.** The stalled state is parked as a backlog item
(`.planning/todos/pending/2026-07-29-stall-detector-needs-a-traced-processing-feed.md`) because its
threshold cannot be chosen honestly until the processing feed is traced. Do NOT declare an
unreachable ninth member: an enum value nothing can return would silently weaken the exhaustive
distinctness guard in Task 3 and would mislead the next reader into thinking the detector shipped.
Instead put a `ponytail:` comment at the enum naming the ceiling - the state is absent because its
detector is parked, not because the design lacks it - and naming the upgrade path as the todo file.

Declare `enum ComputeDotRole` with neutral, warning, success, brand and error. An enum, not a
`Color`: it is what keeps this file Flutter-free and it is exactly what `bridge_cta_state.dart`'s
header comment prescribes. The panel maps roles to `GWColors` tokens where the theme is in scope.

Declare `enum ComputeLink` with none, chooseWallet, switchWallet, seeNodeStatus and retry, plus a
label accessor returning the affordance text from the copy contract at `14-UI-SPEC.md:775-783`.

Write `ComputeState resolveComputeState({...})` taking only plain values - whether a wallet is
selected, whether the node reports itself connected, the node's wallet address, the selected wallet's
address, whether the processing feed is flagged unavailable, the nullable init percentage, whether
the node is processing, and a nullable elapsed `Duration` since the last job finished.

Enforce this precedence in exactly this order, top wins, one guarded `if` per rung with the body on
its own line: no wallet, disconnected, not linked, unavailable, starting up, processing, job
complete, ready. Document why disconnected outranks not-linked directly above that rung, citing
`wallet_overview.dart:179` - a future reader who reorders these two re-introduces a false accusation.

Write `ComputeStatusView viewForComputeState(...)` returning a plain data class carrying: the dot
role, the label, the nullable sub-line, the link, whether a bar renders, the nullable bar value
normalised to 0.0-1.0, the nullable trailing value, whether the balance tile shows its fiat sub-line,
and whether the panel CTA is enabled.

Bind the strings from the copy contract at `14-UI-SPEC.md:769-784`. The starting-up sub-line takes
the SDK's own status message as a parameter and falls back to a static string when that message
arrives empty - nothing has ever read that message in a shipped build, so an empty value is reachable
and must not render a blank line.

Three rules the type system should carry rather than a comment:

The bar value is non-null if and only if a bar renders, and the trailing percentage is emitted under
the same predicate. A percentage without a bar is forbidden; a bar without a percentage is
impossible. Only starting-up and processing render a bar.

Take the two percentage feeds on their native scales and normalise inside this function. The
initialization feed is already 0.0-1.0 (`packages/genius_api/lib/src/genius_api.dart:81`); the
processing feed is 0.0-100.0 (`packages/genius_api/lib/ffi/genius_api_ffi.dart:1116-1118`). Two
feeds, two scales - divide the processing one here so no call site can get it wrong by a factor of
one hundred.

The balance tile's fiat sub-line is the negation of whether a bar renders. That single predicate is
what keeps the tallest state inside the height budget; derive it here so plan 07 cannot forget it.
  </action>

  <name>Task 3: The precedence test and the distinctness test</name>
  <files>test/dashboard/compute_state_test.dart, test/dashboard/compute_state_distinct_test.dart</files>
  <action>
Two plain test files in the style of `test/dashboard/bridge/bridge_cta_state_test.dart`: no mocks, no
`pumpWidget`, no bloc harness, no fixtures.

`test/dashboard/compute_state_test.dart` proves the ladder. One test per rung showing that rung wins
when it should, and - more importantly - four precedence tests showing it wins over the rung below
it. The four that matter, because each encodes a bug this phase closes: disconnected outranks
not-linked when the node's wallet address is empty; unavailable outranks ready; unavailable outranks
starting-up; job-complete outranks ready inside the window and decays to ready outside it.

Add the emptiness guard case: a connected node reporting an empty wallet address never resolves to
not-linked, whatever the selected wallet is.

Add the stale-percentage trap as its own named test: with the node not processing but a percentage of
87.0 still present in the inputs, the resulting view model renders no bar and carries no trailing
percentage. Name the test so the reason survives - this is a reachable and permanent condition in
`lib/bloc/app_bloc.dart:184-191`, where the percentage is emitted only inside the processing branch
and can therefore outlive the job that produced it.

Add the scale test: an initialization reading of 0.525 and a processing reading of 52.5 must both
produce a bar value of 0.525. That one assertion is the whole defence against the hundred-times error.

`test/dashboard/compute_state_distinct_test.dart` is success criterion 1 expressed as one assertion.
Build the view model for every member of `ComputeState.values`, collect a tuple of the fields a user
can actually perceive - dot role, label, sub-line, trailing value, whether a bar renders - into a
Set, and assert the Set's length equals `ComputeState.values.length`. Copy the exhaustive-enum shape
from `test/dashboard/bridge/bridge_cta_state_test.dart:223-230`.

Because it iterates `values` rather than a hand-written list, this test fails automatically if
someone later adds a state without differentiating it - including whoever un-parks the stalled state.
Say that in a comment above the assertion.

Add one further assertion in the same file for the specific pair the phase exists to separate: the
unavailable and ready states must differ on the dot role, the label AND the sub-line, not merely on
one of them. Today both render the same grey word (`lib/components/sgnus/sgnus_connection_widget.dart:125-127`).
