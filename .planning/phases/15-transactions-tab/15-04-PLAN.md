<objective>
Turn the width the page already has into the filter control it should have had, without touching
the panel and without inventing a single new colour.

Purpose: the `⋯` overflow menu exists ONLY because a 376px dashboard panel cannot show nine
filters. A 1280px page can. Sketch 020-B's insight is that `_menuItem`
(`transactions_slim_view.dart:498-551`) already renders exactly glyph + label + live count at a
40px row — so the rail is not a new control, it is those same rows in a `Column` instead of a
popup. Sketch 022 then settled the one genuinely open question, the active mark: **B2, the navbar's
active-tab mark copied outright** — bold white label, 2px gradient rule beneath, glyph untouched —
rejecting 020's invented `brand-fill`, a gradient count (the counts are computed over the
*unfiltered* list on purpose, so a gradient numeral would promise a motion that never comes) and a
gradient wash (~1.3:1, under WCAG 1.4.11's 3:1, and it collides with the hover fill).

One genuinely new row: **All**. `_menuItem` has no All — you clear by tapping the active filter
again, which is invisible. A rail has room to say it, and it is the natural home for the total
count that currently lives in the panel's footer.

Output: two private widgets and one `page` flag on `TransactionsSlimView`, plus the test file that
pins the three states and the light-mode contrast.

Requirements covered: TT-02 (filter rail), TT-03 (rail states).

NOTE: per `./CLAUDE.md` this repo's commit gate is held by the user. Do NOT create commits.
</objective>
