<objective>
Stop the two rows where money did not simply move from printing a dash where the number belongs,
without letting either of them claim the balance changed.

Purpose: `transaction_utils.dart:356-366` gives BOTH a failed transaction and a processing job
`amount = '—'` and demotes the real number to the small grey value line. Sketch 021 §2 measured
what that costs: a job genuinely spends `tx.fees` and that GNUS genuinely leaves the wallet, so a
dash is not caution, it is a missing fact. This plan **amends 12-02 deliberately** — 12-02's dash
was the right fix for the doubled `$0.00` it replaced, and the wrong fix for the number.

Sketch 021 recommended dropping the sign on a failed row so the amount could not assert movement;
sketch 022 records that Jakub overruled it — print the real signed amount, let the status carry the
truth. **That override holds only because the `Not charged` value line stays.** With `− 0.75 ETH`
at full weight and no value line, a wallet that never lost 0.75 ETH reads as if it did. Do not
drop that line.

Output: the amount/tone/value block of `txRowContent` restructured from "dead status first, type
second" into "type first, dead-status OVERRIDE second", plus the tests that pin both halves.

Requirements covered: TT-06 (amount honesty).

NOTE: per `./CLAUDE.md` this repo's commit gate is held by the user. Do NOT create commits.
</objective>

  <action>
Restructure `:350-385` so the type branches run FIRST and the dead status is applied as an
override afterwards. Concretely: delete the leading `if (isDead) { … }` arm so the chain becomes
`if (process) … else if (swap) … else { … }`, compute `amount`/`tone`/`exactAmount`/`valueLine`
from the type as usual, and THEN, in a single trailing block:

    if (isDead) {
      tone = TxAmountTone.none;
      valueLine = 'Not charged';
    }

`amount` and `exactAmount` are deliberately left as the type branch computed them — that is the
whole point of the restructure. **Only `tone` needs to lose its `final`** — it is the one variable
now assigned twice. `amount` is still definitely-assigned exactly once (every arm of the
if/else-if/else chain assigns it, and the override does not), so leave it `final`; widening it to
`var` would be a gratuitous loosening of the one guarantee that stops a future edit forgetting an
arm. Do not otherwise reshape the function.

**Why an override and not a fourth branch.** The literal reading of the instruction — "failed
prints the real signed amount" — has a hole for `TransactionType.process`: a failed job has no
transfer amount at all, so a dedicated failed-branch would have to re-derive the fee and the two
copies would drift. Running the type first means the failed job automatically prints the same
`− 0.002 ETH` its completed twin does, and gets `Not charged` on top. One rule, no duplication.
Record this in a comment — a future reader will otherwise "simplify" it back into a leading gate.

**The tone decision, and why it differs from Task 1's.** A dead row keeps `TxAmountTone.none` ->
`gw.textSecondary`. This is the plan making a call, so the comment must carry the argument:
  - The money did NOT move. `outgoing` -> `textPrimary` is the same ink a successful spend uses,
    so a failed row at that weight is indistinguishable from a completed one when scanning the
    column, which is exactly the double-counting sketch 021 §2 objected to.
  - `incoming` -> `statusSuccess` GREEN on a failed receive would be actively false: green is this
    app's success colour and the transaction failed.
  - `none` -> `textSecondary` measures 6.0:1 dark (`#8A8F9D` on `#0C0E14`) and 6.3:1 light
    (`#5A606E` on white) — AA text passes in both appearances, so quiet here is not weak.
  - Together with `Not charged`, the row states three unambiguous facts: the amount, that nothing
    was charged, and (via the badge and the `· Failed` subtitle) that it failed.

**Do not touch** the `Not charged` string, the badge resolution, or the subtitle status append.
`Not charged` is load-bearing (sketch 022) and is the only thing stopping a full-weight
`− 0.75 ETH` from asserting a balance change.

Add a `ponytail:` comment on the override naming its ceiling: a dead transaction re-uses the
completed row's amount derivation wholesale, so if a future type ever needs a genuinely different
"attempted" amount there is no hook for it; the upgrade path is a per-type attempted-amount field
on `TxRowContent`, not another leading branch.
