<objective>
Stop the empty block drifting to the vertical midpoint of a tall slot, without disturbing the
adaptive compact tier that already lives in this widget.

Purpose: `gw_empty_state.dart:129` returns a bare `Center`, and both transactions call sites hand
it an `Expanded` (`transactions_slim_view.dart:208`). Sketch 020 measured the result: in the

branch (`dashboard_screen.dart:491`), the design gallery (`design_gallery_screen.dart:757`) and

change.

Add one constant beside the existing metrics block:

`static const double _anchorSearchHeight = 480;` — with a comment carrying the RULE and its
provenance (sketch 021 §3, decision locked in sketch 022): *centre within the slot, but never
search more than 480px for the middle.* Say explicitly that it is a fixed literal, not a fraction
of the incoming height: a proportional anchor would derive a dimension continuously from
constraints, which is the class of thing commit `37639d5` banned (see the `<risk>` block).

Then replace the `return Center(child: Padding(...))` at `:129` with a bounded, guarded form.
Hoist the existing `Padding > Column` subtree into a local `final Widget content = ...` (moved
verbatim — do not retype the children) and return:

  - when `isHeightBounded` is FALSE: `Center(child: content)` — today's tree, unchanged. This is
    the gallery branch, and it is the entire reason the guard exists: `Align`/`ConstrainedBox`
    under an infinite height would let the `ConstrainedBox` hand its child a tight-ish 480 and
    inflate a widget that currently sizes to its content.
  - when TRUE: `Align(alignment: Alignment.topCenter, child: ConstrainedBox(constraints: const
    BoxConstraints(maxHeight: _anchorSearchHeight), child: Center(child: content)))`.

Read that inner-to-outer, and put this reading in the comment because it is the non-obvious part:
the inner `Center` centres the block inside whatever height it is given; the `ConstrainedBox` caps
that height at 480; the outer `Align` pins the capped box to the top of the real slot. In a slot
SHORTER than 480 the cap does not bind, the box fills the slot, and the result is exactly today's
`Center` — which is why nothing regresses where the current layout is already fine.

**Reason about the compact interaction explicitly, in a comment, because a reviewer will ask.**
The `ConstrainedBox` sits INSIDE the `LayoutBuilder`, so `constraints.maxHeight` — the value
`isCompact` is computed from — is untouched by the cap. Compact selection therefore reads the REAL
slot height exactly as it does today. And the two ranges cannot overlap: compact fires below 192
(or 256 with an action) while the cap only binds above 480, so no slot exists in which the cap
could push a full layout into compact or hold a compact layout out of it.

Pin that last sentence with code rather than prose: extend the existing `assert` (or add a second
one immediately after it, whichever keeps each message readable) with
`_anchorSearchHeight > compactHeightThreshold`, message along the lines of *the anchor cap must
stay clear of the tier that selects compact, or the cap could become the thing choosing the
layout*. Keep it constant-only so it stays unfirable at runtime, exactly like the existing assert.

Do NOT change: the compact constants, the threshold arithmetic, `hasAction`, the `Column`
children, the `maxLines`/`overflow` compact clamps, or the `GWButton` action block.

**One correction to make while you are in that constant block.** The `ponytail:` comment at `:66-69`
claims *"no current call site renders `GWEmptyState` without a message today"*. That is false and it
matters: `dashboard_screen.dart:491` is `GWEmptyState(title: "No market data available")` with no
message, no icon override and no action — and it is precisely the short-slot call site that 15-06
Checkpoint B step 7 gates on. Correct the sentence to name that call site and keep the rest of the
ceiling note intact: the base threshold (192) assumes the title+message shape, so that title-only
instance in a ~114px card is already in the band the comment describes. Do not change the
threshold arithmetic to "fix" it — the compact tier already handles that card correctly; only the
claim is wrong.

<risk>
**The freeze rule (commit `37639d5`) applies directly here.** This widget already owns a
`LayoutBuilder`, which is the shape that froze the app once: a dimension derived continuously from
`maxHeight`. The value added by this plan is a fixed literal (480) and the branch it feeds is a
BOOLEAN (`isHeightBounded`) — both bounded sets. Do NOT make the anchor proportional
(`maxHeight * 0.35`), do not reach for `FittedBox(scaleDown)`, and do not size the icon or the
title from the slot. Guard: `test/chart/compact_price_font_size_test.dart`.

**This is a shared component with five call sites.** The regression surface is Assets, the
dashboard Markets error card, the design gallery and both transactions branches — none of which
this phase walks in isolation. Task 2's three-shape coverage is the substitute for walking them
all; 15-06 spot-checks Assets and Markets live.

**Do not put a scroll view around `GWEmptyState`** anywhere in this plan. `dashboard_screen.dart:479`
carries an explicit note that doing so hands the internal `LayoutBuilder` an infinite `maxHeight`
and permanently disables the compact tier, forcing a ~192px layout into a ~114px card.
</risk>
