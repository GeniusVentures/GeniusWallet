  <read_first>

  <files>tool/check_brace_style.sh</files>

  <action>
    Add `--fix` to the existing gate rather than writing a second script. The fixer and the gate MUST
    share one detector: two implementations of "what counts as a violation" will drift, and the
    version that drifts quietly is the one that corrupts a file.

    `--fix` rewrites only the case it can rewrite safely, and **refuses everything else, printing
    what it refused**:

    *In scope for automatic rewrite* — the condition, the body statement, and its terminating `;`
    all sit on one physical line, and there is no `else` on that line:
      `if (cond) stmt;`  →  `if (cond) {` / `  stmt;` / `}`
    with the inserted lines carrying the original line's leading indentation. Do not attempt to get
    the indentation exactly right; `dart format` normalizes it in Task 2.

    *Explicitly out of scope — report, never rewrite:*
      - Any `if` with an `else` on the same line. Bracing one branch and not the other is a
        correctness hazard, and there are few enough of these to do by hand.
      - Any braceless `if` whose body spans more than one physical line. Finding the statement's
        real end needs depth tracking across parens, brackets, braces AND string literals; getting
        that subtly wrong silently moves code out of the `if`.
      - Anything inside a comment, a string literal, or a collection-`if`. The 22-02 detector already
        excludes these; `--fix` inherits that exclusion by construction.

    Add self-test cases for `--fix` to the existing `--self-test` mode: for each in-scope case,
    assert the rewritten text; for each out-of-scope case, assert the file is **byte-identical**
    afterwards and that the case was reported as refused. Silent refusal is as bad as a bad rewrite.

    `--fix` must be idempotent: running it twice produces the same file as running it once. Assert
    that in the self-test too.
  </action>

  <verify>

  </verify>

    - `--fix` and the gate use one shared detection function — a reviewer can see there is exactly
      one place that decides what a violation is.
  </acceptance_criteria>
