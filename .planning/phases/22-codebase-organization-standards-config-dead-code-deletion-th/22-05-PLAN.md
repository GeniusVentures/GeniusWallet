      1. `unnecessary_const`
      2. `prefer_const_declarations`
      3. `prefer_const_literals_to_create_immutables`
      4. `prefer_const_constructors`
      5. `use_colored_box`

    This group is separated from Task 1 because `const` is not purely cosmetic — it changes widget
    identity and therefore rebuild granularity. That is a performance improvement, never a behaviour
    change: a `const` widget is only permitted where every argument is already a compile-time
    constant, so nothing that reads `Theme.of(context)` or any runtime value can be affected.
    `use_colored_box` replaces a `Container` whose only argument is a colour with `ColoredBox`;
    identical paint, one fewer layer.

    **Flag forward, do not act:** where a widget becomes `const` because its colour argument is a
    compile-time `GeniusWalletColors` constant, that `const` will have to come back off in 22-10 when
    the site moves to the appearance-aware `context.gw` accessor. This is expected and is not a
    reason to skip the fix now. Note it in the SUMMARY so 22-10 is not surprised by a wave of
    "invalid constant value" errors.

    Run the full test suite after `prefer_const_constructors` specifically, before committing it —
    it is the largest of this group and the only one with any interaction with widget-test pumping.
  </action>
