    Work the residue list. Each refusal has one of three shapes and one correct treatment:

    **Const-expression sites.** The enclosing expression is `const` and `context.gw` is a runtime
    read. Drop the `const` and migrate. Dropping a `const` costs a rebuild-identity optimisation and
    buys appearance correctness; that trade is correct every time here. If the widget is genuinely
    hot-path and losing `const` matters, say so in the SUMMARY rather than leaving the colour behind.

    **Context-free sites** — static fields, top-level constants, controllers, painters, models.
    Two treatments, choose per site:
      - If the value is consumed by a widget, push the read down into the widget's `build` and pass
        it (or nothing — let the widget read it itself). This is the preferred fix and is usually
        small.
      - If it genuinely has no widget (a pure data class holding a display colour), leave it reading
        the primitive layer and record it. `lib/theme/` will still expose the primitives to
        `lib/theme/`-internal and explicitly-recorded consumers after 22-12; that allowlist is what
        22-12 encodes. Do not invent a service locator or a global to get a context — that is an
        unrequested abstraction and it reintroduces the caching bug.

    **`lib/theme/` sites.** Leave them. That is the token layer reading its own primitives.

    Commit per directory, as 22-10 did. Goldens must remain byte-identical through this task —
    nothing here is a visual fix.
  </action>

    low-contrast one.

    contrast ratio in both modes and record it in `22-11-CONTRAST.md`: component, state, mode,

    large text and non-text UI). Any pair that lands below its threshold is not done. This repo has a
    precedent for exactly this: a UI-SPEC-prescribed pairing was measured at 1.96:1 and substituted.

    image**. For each, write one line in `22-11-CONTRAST.md` saying what changed and why it is

    and needs investigating, not blessing.
