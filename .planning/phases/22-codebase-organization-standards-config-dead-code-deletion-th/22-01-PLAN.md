<environment>
**The Flutter SDK is NOT on `PATH`.** Prefix every shell session that runs `flutter` or `dart`:

- bash:       `export PATH="/c/Users/User/Documents/Projects/GNUS/flutter/flutter/bin:$PATH"`
- PowerShell: `$env:PATH = "C:\Users\User\Documents\Projects\GNUS\flutter\flutter\bin;$env:PATH"`

Skipping this produces "command not found", which reads like a compile failure and is not one.
This has burned this project before.

`flutter analyze` exits **non-zero on infos** (`fatal-infos` defaults to true, unlike `dart analyze`).
The measured baseline entering this plan is **319 issues**. Do NOT write a check that expects exit 0.
Compare counts, not exit codes.

If a build fails on a locked DLL, a `genius_wallet.exe` is still running — kill it first.
</environment>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → build output | Deleting a file that is reachable only at runtime (reflection, asset lookup, conditional import) breaks a shipped binary without failing analysis |
| pubspec → dependency resolution | Removing a dependency can silently change a transitive version pin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-01 | Denial of Service | deleted `lib/` files | medium | mitigate | Two-way reference check (package path AND basename) per file, plus a full `flutter analyze` + `flutter test` gate after every task. Dart has no reflection-based widget loading in this app, so the static check is sound. |
| T-22-02 | Tampering | `pubspec.lock` | low | mitigate | Regenerate via `flutter pub get` and review the lock diff; reject any change that alters a version of a package this plan did not remove. |
| T-22-03 | Information Disclosure | `22-01-DELETIONS.md` | low | accept | The record contains file paths and LOC only — no secrets, no key material. |
</threat_model>
