<objective>
Capture a pixel baseline of the design-system primitives **before** the theme consolidation and
component extraction touch them. This ordering is locked: research (LeanCode's 4-level framework)
and the phase context both place goldens ahead of the design-system work because they are the only
mechanism that catches the spacing, alignment and theme drift an assertion-based widget test cannot
see.

`golden_toolkit` is confirmed discontinued with no named successor. `alchemist` (Betterment,
verified publisher, MIT, built with Very Good Ventures) is the de-facto replacement, and its
decisive property for this repo is that CI goldens render text as Ahem coloured blocks — so a
Windows developer and a Linux CI runner produce identical bytes and font rendering cannot flake.

Purpose: build the safety net the rest of Phase 22 is verified against.
Output: alchemist wired, a golden test covering the primitives in both appearance modes, and
committed CI goldens.
</objective>

    Add `alchemist` to `dev_dependencies` at the version approved in Task 1. Run `flutter pub get`
    and review the lock diff: reject any change to a version of a package this plan did not add.

    Create `test/flutter_test_config.dart`. Flutter's test runner picks this file up automatically
    for every test in `test/` — that is why it is one file and not a per-test setup helper.
    Configure:

      - **CI goldens enabled, platform goldens disabled by default.** CI goldens use the Ahem font
        (text renders as coloured blocks), which is the whole reason this suite cannot flake between
        a Windows dev machine and a Linux runner. Platform goldens render real text and are
        machine-specific.
      - **A fixed render environment:** pinned surface size, `devicePixelRatio` of 1.0, animations
        disabled, and the app's real fonts loaded so metrics match production layout.
      - **Theme supplied explicitly per test**, built the same way `theme.dart` builds it, so the
        `GWColors` extension is registered. A golden rendered without the extension registered will
        silently fall back and lock in the wrong colours — that is the failure mode to design out.
      - **Golden file location** under `test/goldens/goldens/`, with a naming scheme that puts the
        appearance mode in the filename so light and dark files sit adjacent and a reviewer can see
        both changed.

    Add the platform-golden output directory to `.gitignore`. Platform goldens must **not** be
    committed — research is explicit on this, and a committed platform golden turns every CI run
    into a false failure.

    Leave a `ponytail:` comment on the config noting the deliberate ceiling: this suite covers
    design-system primitives only, not screens, because components still in active iteration
    generate noise instead of signal.
  </action>
