    `non_constant_identifier_names`, `constant_identifier_names`. Roughly 26 issues.

    **Logging.** Replace each `print` with `debugPrint`, which is stripped in release and rate-limits
    rather than truncating. Before replacing any of them, read what is being printed. If any of them

    like it removes something a caller needs, it does not — the analyzer proved otherwise. If
    deleting one changes a class's constructor shape, stop and record it rather than adjusting call
    sites, because that is API change, not cleanup.

    **Naming.** Rename non-conforming identifiers to `lowerCamelCase` (locals/members) and
    `lowerCamelCase` for constants per Effective Dart. These are private-scope renames; if any turns
    out to be public API used across files, rename every reference in the same commit.

    **Doc comments.** `unintended_html_in_doc_comment` fires where a doc comment contains bare
    angle brackets that get parsed as HTML. Wrap the offending text in backticks. Do not reword the
    comment's meaning.

    **`library_private_types_in_public_api`.** A public member exposes a private type. Prefer making
    the type public if it is genuinely part of the API; prefer changing the member to private if it
    is not. Do not add a wrapper type — that is an unrequested abstraction.

    Commit per rule family.

  <action>
    Four rule families, ~50 issues. Each has a specific correct fix and a specific tempting wrong one.

    **`unawaited_futures` (~17) — the trap.** The obvious fix is to add `await`. **Do not.** Adding
    `await` serializes work that currently runs concurrently, which changes execution ordering and
    can change what the user sees and when. That is a behaviour change and this phase forbids it.
    The correct fix is `unawaited(future)` from `dart:async`, which states "this is intentionally
    fire-and-forget" without altering scheduling. If a particular site genuinely *should* be awaited,
    do not await it here — record it in `22-06-SEMANTIC-DELTAS.md` as a Phase 23 candidate and wrap
    it in `unawaited()` for now.

    **`use_build_context_synchronously` (~5) — the one sanctioned semantic delta.** Add
    `if (!context.mounted) { return; }` immediately after the `await` and before the context use.
    This is the canonical fix and its only effect is on the path where the widget was disposed
    mid-await, which currently throws. Preventing a crash is a change, however small, so **every
    instance goes into `22-06-SEMANTIC-DELTAS.md`** with file, line, and the awaited operation.
    Note the brace form — the guard body goes on its own line, per the rule 22-04 just enforced.

    **`avoid_dynamic_calls` (~20).** Concentrated in `coin_gecko_api.dart` (6), `banxa_model.dart` (5)
    and `read_asset.dart` (5) — all JSON decoding. Replace the dynamic call with an explicit access
    through a typed local, e.g. decode into `Map<String, dynamic>` and read fields with the type you
    expect. **Preserve current failure behaviour exactly:** if the code today silently yields null or
    an empty result on a malformed payload, the typed version must do the same. Do not introduce a
    throw where there wasn't one — an API that starts throwing on a field the server renamed is a
    crash in production, and hardening the parse is Phase 23-06's error-handling work, not this plan's.
    Note any site where you had to think about this in the deltas document.

    **`deprecated_member_use` (~8).** Migrate each to its documented replacement. Four are in
    `coin_telegraph_api.dart`; the rest are single hits in design-system inputs. Where the
    replacement's default differs from the deprecated member's default, pass the old value explicitly
    rather than accepting the new default. That is the whole risk in this family.

    Finally: drive the count to **0** and confirm `flutter analyze --no-pub` **exits 0**. That exit
    code is the deliverable — it is what 22-08 wires into CI.
  </action>
