# Phase 38 — UI Design Contract

> Visual and interaction contract for the account tree switcher. Generated by gsd-ui-researcher
> (unattended run — no user available; every open call favours reusing a component or gate this
> exact file family already shipped, reasoned out below).
>
> **THIS PHASE RESTRUCTURES PHASE 35'S DRAWER; IT DOES NOT REDRAW IT.** Phase 35 built two sections
> ("Sending from" / "Node running as") in `account_drawer.dart`'s `_AccountDrawerBody`. Phase 38
> collapses them into one "Accounts" section whose rows can nest, using the exact row shapes,
> badges, colours and menu items Phases 34/35/37 already shipped. The only new visual elements are
> (1) a chevron for expand/collapse, (2) an "On node" tag replacing "ACTIVE ON NODE", (3) indentation,
> and (4) one new menu item, "Run node as this". Everything else below is a reuse instruction.

## Spacing Scale

The established `GeniusWalletConsts.space*` set. One new usage (`space12`), no new value.

| Token | Value | Usage on this surface |
|-------|-------|------------------------|
| space2 | 4px | Chevron→avatar gap |
| space3 | 6px | Badge→badge gap when "Selected" and "On node" both show on one row |
| space4 | 8px | Badge→trailing-content gap (unchanged from Phase 34/35) |
| space6 | 12px | `GWSelectRow`'s own row padding (unchanged, component default) |
| space10 | 20px | Drawer outer `ListView` padding (unchanged) |
| **space12** | **24px** | **New here: per-depth indent.** One own account's children sit `space12` to the right of their main's leading edge, applied via an outer `Padding(left: depth * space12)` around the row — `GWSelectRow` itself is not modified. |

**Indent ceiling (a `ponytail:` decision, not a CONTEXT item):** indent stops growing past depth 2
(48px). D-09 already caps the *data* walk at one pass over the user's own accounts; this caps the
*rendering* the same way — a third-level chain (rare: it needs three of the user's own accounts
linked in a row) still nests correctly but stops eating horizontal space, which is what D-12's
phone-width constraint actually requires. Upgrade path: an SDK by-child query would make an
unbounded depth cheap to read AND cheap to indent proportionally.

**Exceptions (space3, space6, space10 fall outside 4/8/16/24/32/48/64) — none introduced here**,
inherited unchanged from `GWSelectRow`/`GWRowBadge`/the drawer's existing `ListView` padding
(`account_drawer.dart:538`), exactly as Phase 35/37 already cited them.

## Color

60/30/10 discipline, all via `GWColors`. No new token.

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` | Drawer/panel background (unchanged) |
| Secondary (30%) | `surfaceWell` / `surfaceSunken` | Panel fill; the flat-list note's container (`_AccountSectionNote`, unchanged) |
| Accent (10%) | `brandCta` gradient (via `GWSelectRow.selected`'s existing check glyph + tint) | **"Selected"** — reused verbatim from `GWSelectRow` (`gw_select_row.dart:80-84,161-171`); no new mechanism |
| Accent, second use | `brandSecondary` | **"On node"** tag label (renamed from "ACTIVE ON NODE", same token, `account_drawer.dart:395`) |
| Warning | `statusWarningText` | "SDK PENDING" tag (unchanged) and the SWT-06 lock tooltip icon (unchanged) |
| Destructive | `statusErrorText` | "Delete" / "Revoke" menu items (unchanged) |
| Secondary text | `textSecondary` | Section caption title, row subtitles, chevron icon, locked/disabled row and menu-item foreground at `withValues(alpha: 0.5)` (unchanged dimming recipe, `sdk_account_manager.dart:210-212`) |
| Primary text | `textPrimary` | Row titles |

**Accent reserved for:** the selected row's own check/tint (nothing paints it manually — it is
`GWSelectRow.selected`) and the "On node" tag label. **Not** for the chevron, **not** for a foreign
leaf child's balance text, **not** for any menu item other than a destructive one's own
`statusErrorText`. No new contrast pairing needs fresh math — every pairing above is measured and
shipped in Phase 34 (`34-02-SUMMARY.md`), Phase 35 or Phase 37.

| `AccountTreeRow` model + `buildAccountTree(...)` (new) | `lib/account/account_tree.dart` | **Pure function, no SDK/BuildContext** (Claude's Discretion — testable without a live node). ## Screen Contracts

### The switcher drawer (`AccountDrawer.show`, both desktop chip and mobile pill entry points — unchanged)

```
ListView (padding: space10)                                    — unchanged outer shell
├ [if includeNetwork] Network field + header                   — unchanged (Phase 35)
├ _AccountSectionHeader('Accounts', <merged caption>)           — ONE header, D-01
├ [if node down / registrations read failed, D-11]
│    _AccountSectionNote('Child wallets show while the node is running.')
├ …AccountTreeRow list, flattened respecting collapse state:
│    for each top-level row:
│      [chevron if isMain] AccountAvatar/icon  Title            Selected? On node? SDK-PENDING?  balance  ⋮
│        [if isMain and expanded] …its children, indented one `space12` per depth (capped at 2)
├ (or, list is empty entirely) _AccountSectionNote('No wallets yet.')  — unreachable in practice, D-08 of Phase 35 kept the branch
└ [footer, shell-owned] GWButton('Add wallet', gradient, lg, expand)  — unchanged (Phase 35)
```

**Visual focal point:** unchanged from Phase 35 — the row carrying the "Selected" check/tint, because
the drawer still answers "which account am I sending from" first. The chevron and the "On node" tag
are the second read, not the first: nesting is a navigation aid, not the headline.

**Row order:** own wallets in their existing order (`appState.wallets`, sgnus-typed entries excluded
as today), each followed immediately by its own registered-as-child own accounts (recursive, D-09),
then any of the user's own SDK accounts never claimed by a main, in `appState.sdkAccounts` order —
i.e., exactly today's two lists' internal orders, interleaved by ownership rather than concatenated
by section.

### Desktop chip / mobile pill (unaffected)

No visual change. `AccountSwitcher`'s tooltip string (`account_switcher.dart:46`,
`'Sending from $label · $nodeStatus'`) is unchanged — it already names both selections without
implying they are one list, so nothing about the tree restructuring requires editing it.

## UI Considerations

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Whole tree, node down or registrations read fails | ✅ covered | D-11's flat-list note renders once; the own-wallet/SDK rows underneath still render flat (no nesting attempted), never a blank panel. |
| empty | No wallets at all | ✅ covered | `_AccountSectionNote('No wallets yet.')` — unreachable in practice, kept unchanged from Phase 35. |
| loading | Registrations read in flight when the drawer opens | ✅ covered (N/A by construction) | Same reasoning Phase 36/37 already gave: the SDK call is synchronous on the main isolate — there is no async gap to show a spinner for. | zero-one-many | 0, 1, or N of the user's own accounts registered as children of another | 🧪 backstop | { statement: "Each own account nests under exactly the first main that lists it, appears once, and a cycle or a second registering main stops recursion at the first placement without duplicating or infinite-looping the row list", verification: backstop } |
| zero-one-many | 0, 1, or N foreign (not-owned) children under an expanded main | ✅ covered | Reuses `ChildWalletRow`'s existing `ListView.separated` shape and lock/badge treatment verbatim — already proven at N children on `/child-wallets`. |
| overflow / long-text | Row title, tags, balance and chevron all present at once, narrow phone width | ✅ covered | Balance already gets a bounded/ellipsised width once any badge shows (Phase 34's fix, `account_drawer.dart:402-416`), unchanged; the chevron adds a fixed 18px+`space2` that the indent ceiling (Spacing, above) budgets for. |
| partial | An own account that is BOTH someone else's registered child AND itself a main to further children | ✅ covered | Nests once under its own main (per its placement) while still rendering its own chevron and its own children beneath it, one level deeper — the model in Component Inventory carries `depth` recursively, not a single parent/child flag. |
| locked | "Run node as this" while SWT-06 applies | ✅ covered | Same tooltip/toast reason and same `ChildOperationsCubit.hasPendingFrom` check the pre-merge SDK row already used (`account_drawer.dart:529-535`) — no new lock mechanism. |
| locked | Fund/Recover/Revoke on a foreign leaf row mid-pending | ✅ covered | Identical to `child_wallets_screen.dart`'s existing per-kind locks — reused, not reimplemented. |
| dev-mock | Every CHILD WALLETS dev preset (`none`/`oneChild`/`threeChildren`/`queryError`/`nodeNotRunning`, plus Phase 37's write-mode presets) | ✅ covered | The tree's registrations pre-read is dev-gated through the identical `DevMockChildWallets` path `ChildWalletsCubit` already uses (D-14) — every preset that drives `/child-wallets` drives the switcher's nesting identically, with no separate preset set to keep in sync. |
