This is a research and evidence task. It writes one document and touches no code.

**Start from what is already known — do NOT re-derive it.** REQUIREMENTS.md's GAP-02..06 already name
5 groups covering 10 files:
- Settings screen (`lib/settings/settings_screen.dart`) — GAP-02
- SDK account manager (`lib/account/sdk_account_manager.dart`) — GAP-03
- Select-wallet-type onboarding (`lib/onboarding/existing_wallet/view/select_wallet_type_screen.dart`,
  `wallet_routes.dart`) — GAP-04
- Banxa additions (`banxa_orders_history.dart`, `banxa_payment.dart`, `screens/banxa_buy_screen.dart`)
  — GAP-05
- Misc (`components/wallet_overview.dart`, `components/loading.dart`,
  `dashboard/home/widgets/transaction_displays.dart`) — GAP-06

This phase's own diff independently confirms `components/loading.dart` and
`components/wallet_overview.dart` are develop-only with zero Alex analog — consistent with GAP-06, and
both are shadow-name hazards this phase documented (`03-SHADOW-NAMES.md`). Note that connection in the
inventory: GAP-06's two files are exactly two of the three files a later phase could silently swap.

**The method (UI-SPEC §7.2). The known 10 are `lib/components/`-scoped or pre-named; GAP-01's job is
the WHOLE app.**

1. **Enumerate.** Every screen-level file develop ships: every route target in `lib/navigation/router.dart`,
   plus every sub-view reachable from them. Not just `lib/components/`.
2. **Diff.** For each, check whether `GeniusWallet-3514` has a file at the same logical path/role. Use
   the same three-way diff technique the UI-SPEC §1.1 used — `git diff --diff-filter=A|M|D --name-only
   develop..origin/ui-redesign-3.514 -- <dir>`, and `comm` across the two trees — scoped to the
   relevant directories (`lib/settings/`, `lib/account/`, `lib/onboarding/`, `lib/banxa/`,
   `lib/dashboard/`, `lib/tokens/`, `lib/squid_router/`, `lib/reown/`, `lib/screens/`, `lib/web/`,
   `lib/submit_job/`, `lib/wallets/`, …), not just `lib/components/`.
   **Record the command and its output for every claim.** A "no Alex analog" verdict with no diff
   behind it is a guess, and UI-SPEC §7.3 requires evidence matching §1.1's rigor. This is the same
   discipline `02-VERIFICATION.md` established: a row with no observation behind it is FAIL, not PASS.
3. **Split** every no-analog surface using REQUIREMENTS.md's own test, verbatim:
   - **Mechanically re-skinnable** — the surface's existing structure, item order, wording and
     behavior can receive `gw_*` primitives / Phase 2 tokens with **zero IA change**. Record as "in
     scope, ready", and name the owning phase per the ROADMAP's per-area assignment.
   - **Needs a structural/product decision** — applying the design language would require moving
     items, reordering, merging/splitting screens, or adding/removing capability. Record as "deferred
     to product" **with the specific structural question, written verbatim and left unanswered.**
4. **Name the primitives.** For every "mechanically re-skinnable" surface, name which `gw_*`
   primitive(s) from the 50 this phase ported it will need.

**Hard constraints — these are REQUIREMENTS.md's, not suggestions:**
- **Never decide a structural question here.** If applying the design language requires restructuring
  to look right, stop, leave that part as-is, and record it for product. "Shipping an invented
  structure nobody signed off is worse than an obvious gap product can prioritise."
- **Never invent a layout, a screen, or a surface Alex never drew.**
- **Do not force the count to 12.** The ROADMAP's "12 develop features" is an unverified estimate;
  REQUIREMENTS.md's named groups sum to 10 files across 5 groups. Report the real, evidenced number
  and, if it differs from 12, say so plainly and explain the discrepancy rather than padding or
  trimming to match.
- **Do not pull WIRE-02 scope in.** `lib/ai/`, `lib/preferences/`, `lib/tokens/address_book.dart`,
  `lib/tokens/convert_section.dart` and the NFTs tab are Alex-only features develop does not have —
  they are the opposite of a gap (design with no develop surface) and are out of scope for this
  milestone entirely. If the enumeration surfaces them, mark them out-of-scope-WIRE-02 and move on.
  </action>
