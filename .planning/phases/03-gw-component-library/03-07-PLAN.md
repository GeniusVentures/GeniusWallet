Two additions to the gallery, both first-of-their-kind in this repo.

**A. The `GWCanvasBackground` section (DS-04 part 2).** Add one `_Section` titled `Canvas background
(noise texture)`, following the file's existing `_Section(title:, child:)` pattern, wrapping a small
demo area in `GWCanvasBackground`.

`GWCanvasBackground` lives in `lib/theme/genius_wallet_decorations.dart:168` and consumes
`AssetImage('assets/images/textures/noise.png')`. Phase 2 ported the class but **deliberately never
instantiated it** (`02-UI-SPEC.md` §1.3 note 3) because the asset was not bundled. Plan 03-01 bundled
it. **This is the first instantiation anywhere in this repo**, and therefore the first moment DS-04 is
actually testable.

Note the disambiguation the ROADMAP's wording invites: criterion 2 says "`gw_mesh_background` renders
its texture", but `GWMeshBackground` is **procedural CustomPaint with no asset dependency at all**.
`GWCanvasBackground` is the texture consumer. Demo both, in separate sections, and let the SUMMARY
state which one criterion 2 is really about.

Do not instantiate `GWCanvasBackground` anywhere a non-dev-gated build could reach. The gallery is
the only permitted call site this phase.

**B. Import the closure canary.** Add `import 'package:genius_wallet/dev/generated_closure_canary.dart';`
and reference its exported list once (e.g. a debug-only `_Section` that renders
`Text('${kGeneratedClosureCanary.length} generated widgets in closure')` — use the actual symbol name
plan 03-04 chose).

This matters more than it looks. Per UI-SPEC §2.8, Dart only compiles what is reachable from an entry
point, so with nothing importing the 9 `.g.dart` files, **even a full `flutter run` would not compile
them.** Importing the canary from the (dev-gated, but reachable) gallery makes the Dart front-end
compile those libraries for real. That upgrades the `.g.dart` gate from "the analyzer resolved the
symbols" to "the compiler accepted the file bodies" — a build error in any of the 9 now detonates
here, in Phase 3, instead of in Phase 6.

It still does **not** prove they render — nothing calls `build()` on them. Do not claim otherwise, and
do not mount them in the gallery. Plan 03-10 records the render gap honestly.
  </action>
