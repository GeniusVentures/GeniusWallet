<task type="auto">
  <name>Task 3: Build the closure canary — the gate the analyzer cannot otherwise provide</name>
  <files>lib/dev/generated_closure_canary.dart</files>
  <action>
The problem this solves, stated plainly: `analysis_options.yaml:5` excludes `lib/**/*.g.dart`, so
`flutter analyze` reports 0 errors even if all 9 generated files are broken. And per UI-SPEC §2.8,
nothing reachable from `main.dart` imports any of them this phase — Dart only compiles what is
reachable, so **even a full `flutter run` would not compile them.** Without this task, the 9 files
land completely unchecked by anything, and the first evidence would arrive in Phase 5/6/7.

The UI-SPEC's position is that render correctness genuinely cannot be established this phase, and
that is correct and stands — nothing calls `build()` on these. But the SPEC also asks (§2.8) that the
plan "at minimum prove the closure is complete — nothing references a file that isn't being ported".
This task does that mechanically instead of by inspection.

**Write `lib/dev/generated_closure_canary.dart`:**

- It is a plain `.dart` file, **not** a `.g.dart` file, so the analyzer's exclude does not apply to
  it. That is the entire trick: the analyzer will not check inside the generated files, but it will
  fully check this file's references INTO them. An unresolvable import, a missing class, a renamed
  symbol, or a constructor whose signature moved all become hard `flutter analyze` errors here.
- It imports all 9 `.g.dart` files and the 4 additive `custom/` siblings from Task 1.
- It exposes a single top-level `const List<Type>` (or `final`, if any entry forces it) naming every
  public class the set exports — at minimum: `IsactiveFalse`, `IsactiveTrue`, `GeniusBackButton`,
  `IncorrectPin`, `Recoveryword`, `RegistrationHeader`, `WalletInformation`, `WalletPreview`,
  `WalletsOverview`, plus the `custom/` classes. **Read each ported file for its actual exported class
  name — do not guess from the filename.** Parabeac's class names do not always match their file
  names, and a guessed name that happens not to exist will show up as an analyzer error, which is the
  system working, but a guessed name that exists on the WRONG class would silently weaken the gate.
- Prefer a `Type` literal per class (`WalletInformation`, not `WalletInformation(...)`). A `Type`
  literal resolves the symbol and forces the library to be imported and analyzed, without needing to
  satisfy constructors that require live dependencies like `WalletDetailsCubit`. Where a constructor
  IS trivially satisfiable, you may additionally add a `Widget Function()` closure that calls it —
  that upgrades the gate from "class exists" to "constructor signature is what callers expect". Do
  this where it is free; do not contort the file to force it.
- **Never call `build()` and never mount any of these widgets.** The canary is a compile/analyze
  gate, not a render test. Claiming render correctness from it would be exactly the unearned PASS
  `02-VERIFICATION.md` was written to prevent.
- Head comment must state: what it gates, why (`analysis_options.yaml` excludes `.g.dart`), what it
  explicitly does NOT prove (that any of these render — no `build()` is called, no widget is
  mounted), and that it is dev-only. Name `03-SHADOW-NAMES.md` for the `WalletsOverview` shadow.
- Plan 03-07 imports this canary from the design gallery. That makes the set **reachable from an
  entry point**, so the Dart front-end compiles the generated libraries for real during
  `flutter run` — which upgrades the gate again, from "analyzer resolves the symbols" to "the
  compiler accepts the file bodies". Do not make it reachable from anything that is not dev-gated.

Then verify the closure completeness claim mechanically: extract every `package:genius_wallet/...`
import across the 9 `.g.dart` files and their 4 additive siblings and assert each resolves to a file
that exists in the tree right now. Record the resulting list in the SUMMARY — that is the evidence
for UI-SPEC §2.8's "dependency closure: verified closed", re-derived rather than inherited.
  </action>
