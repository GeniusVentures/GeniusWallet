<objective>
Collapse the dashboard's per-section loading into the one gate the splash now stands in front of, so the
dashboard appears complete instead of assembling itself in front of the user.

Purpose: this is success criterion 2, and it is the half of this phase the user actually asked for twice —
"a dashboard that appears complete". The splash (13-03) already waits for wallets, account, markets and
chart before it hands over, so by the time this screen builds, the data its sections fetch is warm in the
same Hive cache they read. What remains is to stop those sections from rendering their own loaders on the
way in, and to make the dashboard's existing gate cover the one leg the splash's status line does not name.

Two traps sit in the obvious version of this change, and both are worse than the problem being fixed:

1. **Widening the gate into a LIVE condition.** `_onRefresh` and `_onRetry` both call `getCoins()`, which
   emits `coinsStatus: loading`. A gate that watches that field forever will collapse the whole dashboard to
   a full-screen `LoadingScreen()` every time the user pulls to refresh. The gate must latch: it decides
   whether the dashboard has been REVEALED, not whether data is currently in flight.
2. **Deleting only the skeleton in the chart.** `crypto_live_chart.dart` has two loading cues driven by the
   same `_hasData` flag — the `PulsingSkeleton` that 13-CONTEXT E2 names, and a `'Loading...'` price string
   forty lines away that it does not. Removing one leaves the other, and a dashboard that says "Loading..."
   in the price slot has not met SC2 no matter how clean the chart body looks.

The prerequisites landed earlier on purpose: 13-01 made `coinsStatus` settle on every reachable exit
(previously a rejected holdings read stranded it on `loading` forever, which under this gate is a permanent
hang), and 13-02 bounded every CoinGecko request (13-RESEARCH Pitfall 6: deleting a loader while its fetch
can still hang means showing nothing indefinitely instead of a spinner — strictly worse). Neither is
re-litigated here; both are consumed.

Output: one shared gate, three loaders gone, and a refresh that still shows the dashboard.
</objective>
