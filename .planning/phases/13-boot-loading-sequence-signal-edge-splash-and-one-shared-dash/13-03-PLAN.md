<objective>
Replace the boot screen that lies with the one from sketch 015 — Signal Edge — and give it a closing run
that is true at every frame.

Purpose: this is success criterion 1. Today `lib/components/loading.dart:24` renders
`LoadingAnimationWidget.flickr`, a real `AnimationController` that nobody is ticking, because the Dart main
isolate is blocked for ~9.6s inside `GeniusSDKInitWithMnemonic`. The asset is not broken — the promise is.
A spinner asserts motion; when it cannot deliver, the app reads as hung. The fix is not a better spinner
(M1: nothing can animate before the freeze lifts, and M2 settled that moving the init off-isolate does not
change that). The fix is a composition that promises nothing it cannot deliver, and then a genuine closing
beat once the isolate is free.

The two ways this plan can silently fail are both recorded, and both are cheap to get right and expensive
to notice later:

1. **The mode-invariance trap.** `GWMeshBackground`'s `baseColor` defaults to
   `GeniusWalletColors.surfaceBase` — a getter that flips with appearance — and it paints that base as the
   first child of a `StackFit.expand` Stack, covering the Scaffold entirely. So a boot screen that
   correctly pins its Scaffold dark still turns light-grey in light mode the moment the mesh is added.
   The parameter to defeat this already exists; it just has to be passed. And the trap is wider than
   13-RESEARCH's Pitfall 1 states: `GeniusWalletTypography`'s style getters bake
   `GeniusWalletColors.textPrimary` — another flipping getter — as their default colour, so a bare
   typography token on this screen carries the same bug in the text layer.
2. **The shadow-import bookkeeping.** Dropping the `Loading` import from this file changes the canonical
   `Loading` importer set that `tool/verify_additive_boundary.sh` matches EXACTLY. Verified on the current
   tree: the recorded list has 19 entries and includes `lib/screens/splash.dart`. Removing the import
   without editing that list flips a passing guard to failing, which reads as this phase breaking the
   shadow boundary when it did the opposite. 13-RESEARCH does not mention this; it was found by running
   the script.

The sequencer's structure, where the minimum hold lives, and whether gate state sits in `AppBloc` or in the
splash are all listed under Claude's Discretion in 13-CONTEXT. The decision taken: the splash owns it,
locally, driving the plain-Dart `BootSequence` built in 13-02. `AppBloc` gains no field and no event — the
splash is the only consumer of this timeline, and a bloc field would be state that exists solely to be read
by one widget, once, per session.

Output: the routed boot screen wearing Signal Edge, a truthful closing run, and a shadow-name baseline that
still tells the truth.
</objective>
