<objective>
Re-skin the order-details card and its sole host page — the one pair 09-RESEARCH says cannot be
split across plans, because the banner-severity plumbing spans both files.

This pair carries the phase's only genuine paint DEFECT rather than merely dated paint:
`order_details_card.dart`'s status is a two-way ternary with no error branch at all, so a declined,
expired or failed order is painted the same amber as one that is merely pending. 09-UI-SPEC's
Interaction rule 7 authorises extending it to the full four buckets — the status string is
unchanged, only its paint gains the branch it was missing.

Purpose: bring order details onto the shared status ladder and the shipped tinted-banner recipe,
and give the page the same error vocabulary the orders list gets in 09-02.
Output: both files re-skinned in place with the banner tone plumbed as a semantic token, plus a
widget test pinning all four status buckets and the three banner severities.
</objective>
