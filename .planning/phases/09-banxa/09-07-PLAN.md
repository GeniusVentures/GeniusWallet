<objective>
Close the phase honestly: install the standing gate that keeps the re-skin from rotting, and write
down what this phase did not deliver before anyone reads it as finished.

09-VALIDATION.md is blunt about what a re-skin can actually pin: not visual fidelity, not the
sandbox, not light mode — but it CAN pin that the pre-redesign literals are gone, that the shipped
tokens are used, and that each surface still builds. That gate is worth more than any single
widget test in this phase, and it belongs at the end, once all ten files have landed.

The second half matters as much. 09-CONTEXT's `<scope_reduction>` states plainly that Phase 9 as
scoped does NOT satisfy all four of its ROADMAP criteria. This plan writes that down in the place
verification will look, so the phase closes with recorded gaps rather than an unearned pass — the
same pattern Phase 5 and Phase 8 used.

Purpose: make the re-skin durable, and make its limits legible.
Output: `test/banxa/banxa_reskin_literals_test.dart` and
`.planning/phases/09-banxa/09-OUTSTANDING.md`.
</objective>

  <action>
Write `test/banxa/banxa_reskin_literals_test.dart` as a Dart test, not a shell script. Phase 6 used
a shell script for its equivalent gate; a Dart test is the better instrument here because it runs
inside `flutter test` — so it is part of the sampling loop 09-VALIDATION.md defines, and it works
identically on the Windows host this project builds on.

Structure it as one const map from file path to that file's allowlist, then a single
`testWidgets`-free `test()` per concern, iterating the map. Keep it small: read each file with
`File(path).readAsStringSync()`, split to lines, drop lines whose trimmed form starts with a
comment marker, and match against the forbidden patterns. Dropping comment lines is not optional
— a bare count over unfiltered source lets a file's own explanatory header trip its own gate,
which is a self-invalidating check.

The forbidden set, from 09-UI-SPEC's Interaction rule 4 and 09-RESEARCH's per-file inventory: any
reference to Flutter's `Colors` class, plus `GeniusWalletColors.deepBlue` and
`GeniusWalletColors.lightGreenSecondary`. Scanning for the whole `Colors` class rather than an
enumerated list of shades is deliberate — it catches the next literal someone reaches for, not
just the ones that happened to be there in July.

The allowlist has exactly two entries and each carries its reason inline, because an allowlist
without a reason decays into a mute list:
- `checkout_qr.dart` — one white container: the QR's quiet zone, mode-invariant by design per the
  shipped drawers convention. Assert it is present exactly once, so it cannot be removed.
- `banxa_buy_screen.dart` — one black-alpha scrim: a temporary full-screen block, mode-invariant
  by construction. Assert it is present exactly once.

Add the two companion checks from `<behavior>`: every file takes the fail-soft live `GWColors`
read (this is the phase's defence against the const-widget-does-not-re-skin defect class), and no
file still contains a raw Material button widget. For the live-read check, exempt only files that
genuinely have no colour to read after their re-skin — inspect the landed code to decide, and put
each exemption in the allowlist with its reason. Do not exempt a file because the assertion is
inconvenient.

Ten file paths are hardcoded. That is intentional: a glob over `lib/banxa/` would silently pick up
the four D-05 drawers that belong to Phase 21 and start gating files this phase does not own.
