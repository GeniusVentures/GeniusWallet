# Phase 37 — UI Design Contract

> Visual and interaction contract for child write operations and the pending-operation model.
> Generated by gsd-ui-researcher (unattended run — no user available; every open call is made in
> favour of reusing an existing dialog/toast/badge/field pattern already shipped in this exact file
> family, with the reason recorded).
>
> **THIS PHASE ADDS ACTIONS TO AN EXISTING SCREEN; IT DOES NOT INVENT A NEW DIALOG LANGUAGE.** Every
> dialog, field, button variant and toast below already ships on `develop` — `GWDialog` (5 call
> sites in `sdk_account_manager.dart` alone), the exact-decimal amount field (`send_screen.dart`),
> and the "observe the list, don't trust the call" toast idiom (`_confirmDeleteSDKAccount`,
> `showAddSdkAccountDialog`). This document locks which of those pieces compose Fund/Recover/
> Revoke/Detach/Move/Register, the pending-badge component two files now need (promoted, not
> duplicated), and the SWT-06 lock's visual treatment on the switcher this phase does not otherwise
> touch. `36-UI-SPEC.md` explicitly reserved zero accent use on `/child-wallets` and predicted that
> `_ChildWalletRow` would become a drop-in `GWSelectRow`-shaped row "once an action exists" — this
> is that promotion.

## Spacing Scale

The established `GeniusWalletConsts.space*` set (already on develop). No new numeric value is
introduced by this phase.

| Token | Value | Usage on this phase's surfaces |
|-------|-------|------------------------|
| space2 | 4px | Gap between a pending badge and its "Check again" link |
| space3 | 6px | Gap between a row's trailing balance and its pending badge, when both are present |
| space4 | 8px | Gap between the "This account" card's two action buttons; menu-icon gap (unchanged, `sdk_account_manager.dart` pattern) |
| space6 | 12px | Dialog content's internal gaps (amount field → summary line; list → "Enter an address" row); "This account" card's own padding (unchanged from Phase 36) |
| space8 | 16px | Gap between a confirmation dialog's message and its content; gap between the main-picker's list and its footer row |

**Exceptions (space3=6px, space6=12px, space10=20px fall outside the canonical 4/8/16/24/32/48/64
set) — none introduced or changed by this phase.** All three are pre-existing
`GeniusWalletConsts.space*` tokens (`lib/theme/genius_wallet_consts.dart:26,28,30`), inherited
unchanged from the components this phase composes rather than authored here — `GWDialog`'s own
`padding: EdgeInsets.all(GeniusWalletConsts.space10)` (`gw_dialog.dart:61`) and
`_RowBadge`'s existing `space4`/`2` padding (`account_drawer.dart:153-156`, itself unchanged by the
promotion below). This phase adds no new spacing value.

## Color

60/30/10 discipline, all via `GWColors`. No new token is added by this phase — this is the first
phase to actually SPEND the accent budget `36-UI-SPEC.md` explicitly reserved as zero on this
screen.

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` | Page background (unchanged) |
| Secondary (30%) | `surfaceWell` | Identity banner + "This account" card fill (unchanged from Phase 36); `surfaceOverlay` dialog scrim (`GWDialog.show`'s own default) |
| Accent (10%) | **`brandCta` gradient, via `GWButtonVariant.primary`** | Reserved for exactly the constructive submit action in each write dialog — "Fund" / "Recover" / "Register" / "Set address"-style confirms. `GWButtonVariant.primary` already paints the brand CTA gradient app-wide (`gw_button.dart:124-138`, "App-wide primary CTA now paints the brand CTA gradient"), so no new accent mechanism is introduced — this phase simply spends the budget the read-only phase left unspent. **Never** on Cancel, never on a menu trigger, never on the row's own content. |
| Destructive | `statusError` fill / `statusErrorText` foreground | Revoke / Detach / Move confirm actions (`GWButtonVariant.destructive`) — grouped per D-08's explicit "worded as irreversible" instruction, matching `_confirmDeleteSDKAccount`'s existing destructive dialog exactly |
| Warning (pending/lag) | `statusWarningText` | Pending and "Not confirmed yet" badge labels — the same token `_RowBadge`'s existing "SDK PENDING" label already uses (`account_drawer.dart:420`), so a user who has seen that badge once already knows what this one means |
| Secondary text | `textSecondary` | Lock-reason tooltips, dialog secondary copy, disabled menu-item foreground (unchanged `_menuItem` treatment, `sdk_account_manager.dart:210-212`) |
| Primary text | `textPrimary` | Dialog titles, row content, confirmation sentences |

**Accent reserved for:** the constructive submit button in exactly four dialogs (Fund, Recover,
Register, and the main-picker's "Continue" once a target is chosen) — nothing else. **Not** for
Cancel, **not** for the "Check again" link (ghost/`textPrimary`, a utility action, not a CTA), **not**
for the row menu's trigger icon (stays `textSecondary`, matching `SDKAccountRow`'s existing "More
actions" trigger), **not** for Revoke/Detach/Move (destructive, styled with `statusError`, never the
brand gradient — mixing the two would read as "this is good AND this is dangerous" on the same
button). This is a deliberate, narrow spend: `36-UI-SPEC.md` reserved the whole budget for "the
write actions Phase 37 adds" — this table is that reservation being spent, once, on the single
submit action per flow.

No new color pairing needs fresh contrast math: `statusWarningText`, `statusError`/`statusErrorText`,
`textSecondary`, `textPrimary` and the `brandCta` gradient (via `primary`) are all pre-measured,
existing pairings already verified in this exact file family (`_RowBadge`'s own SDK-PENDING use,
`_confirmDeleteSDKAccount`'s destructive dialog, every existing `GWDialog` primary action).

## Copywriting Contract

### Dialog titles & confirmation bodies (D-08)

| Action | Dialog title | Body (names both accounts) | Primary action |
|--------|-------------|------------------------------|-----------------|
| Fund | "Fund {childName}" | "From {mainName} to {childName}." + the amount field (see below) — the sentence renders BEFORE any amount is typed, so both accounts are named regardless of field state | "Fund" (`primary`) |
| Recover | "Recover from {childName}" | "From {childName} to {mainName}." + the amount field | "Recover" (`primary`) |
| Revoke | "Revoke child?" | **"Revoke {child}? It will no longer be a child of {main}."** (D-08, exact string) | "Revoke" (`destructive`) |
| Detach | "Detach from main?" | "Detach from {main}? {account} will no longer be a child of {main}." (D-08's irreversibility wording, applied to the child-side twin of Revoke) | "Detach" (`destructive`) |
| Move | "Move to another main?" | "Move to {newMain}? {account} will no longer be a child of {oldMain}." (D-08 groups Move with Revoke/Detach as irreversible-for-the-current-registration) | "Move" (`destructive`) |
| Register | "Register as a child?" | "Register {account} as a child of {main}? {account} will be controlled by {main} until detached." | "Register" (`primary`) |

Every dialog's secondary action is **"Cancel"** (`ghost`, unchanged idiom).

### Amount field (Fund / Recover — D-07)

Reuses `send_screen.dart`'s field byte-for-byte: `GWTextField(label: 'Amount', hint: '0.0',
keyboardType: TextInputType.numberWithOptions(decimal: true), suffix: Row([Text('GNUS'), MAX
GWButton]))`. Validation copy is `send_cubit.dart`'s own wording, ported to GNUS's fixed 6 decimals:

| Condition | Error text |
|-----------|-----------|
| More than 6 decimal places | **"GNUS supports up to 6 decimal places."** (send_cubit.dart:508's template, `$symbol supports up to $decimals decimal $places`, with `symbol='GNUS'`, `decimals=6`) |
| Empty on submit | **"Enter an amount."** (send_cubit.dart:517's "Enter an amount to send." shortened — this field has no recipient half to name) |
| Zero or negative | **"Enter an amount greater than zero."** |
| Exceeds the paying side's balance | **"{Main/Child} doesn't have that much GNUS."** (Fund: main's balance; Recover: the child's balance — mirrors `send_cubit.dart:578`'s "Your $symbol balance doesn't cover this amount." pattern) |
| "MAX" button | Fills the field with the paying side's exact GNUS balance string — same `cubit.useMax` idiom as Send (`send_screen.dart:223`) |

### Pending / not-confirmed badges (D-14, plain words)

The badge shows a **kind-specific present-participle phrase** while pending, and the literal
**"Not confirmed yet"** after the D-12 timeout. There is no persistent "done" wording — see
`UI Considerations`, row "done" state, for why that is a resolved decision, not an oversight.

| Kind | Pending badge text | Not-confirmed badge text |
|------|--------------------|---------------------------|
| Register | "Registering…" | "Not confirmed yet" |
| Fund | "Funding {amount} GNUS…" | "Not confirmed yet" |
| Recover | "Recovering {amount} GNUS…" | "Not confirmed yet" |
| Revoke | "Revoking…" | "Not confirmed yet" |
| Detach | "Detaching…" | "Not confirmed yet" |
| Move | "Moving to {newMainName}…" | "Not confirmed yet" |

The not-confirmed badge is always paired with a **"Check again"** ghost/`sm` `GWButton` (D-12's
"Check again" action), `space2` to its trailing edge.

### Resolution toasts (the real "done" signal — D-11)

Fired once, through the existing `showToast` idiom (`ToastType.success`), the moment the registry
observes the real signal — never on submission alone:

| Kind | Toast |
|------|-------|
| Register | "Registered as a child of {main}" |
| Fund | "Funded {amount} GNUS to {child}" |
| Recover | "Recovered {amount} GNUS from {child}" |
| Revoke | "Revoked {child}" |
| Detach | "Detached from {main}" |
| Move | "Moved to {newMain}" |

An immediate (non-OK) submission failure is **never** shown as a pending badge (D-12) — it is a
`ToastType.error` toast naming the SDK's reason, same shape as `_confirmDeleteSDKAccount`'s "The SDK
refused to delete that account." (`sdk_account_manager.dart:431`).

### Empty picker (no other SDK accounts)

"You have no other SDK accounts. Enter an address instead." — the list section is replaced by this
one line; the manual-entry field is still reachable and becomes the picker's only path, matching
the empty-state honesty rule every other list in this app already follows (`GWEmptyState`'s own
convention, applied inline here because the picker is a dialog, not a screen).

### Dev-bubble additions (D-17)

New buttons inside the existing `CHILD WALLETS` `_Section` (`dev_tools_bubble.dart:1181`), after the
five read-only presets and before "Clear": **"Writes confirm"**, **"Writes time out"**, **"Writes
fail"** — tooltips state plainly what each does, matching the five existing buttons' tooltip
register-of-record style (e.g. "STICKY until Clear; an open Child wallets screen follows it.").

## Screen Contracts

### `/child-wallets` — extended (child rows + "This account" card)

```
GWScreen(appBar: AppBar('Child wallets'), scroll: false)
└ Column
  ├ "This account" card (surfaceWell well, ALWAYS rendered)
  │   [36px avatar] [Expanded: mainName / mainAddress / status line / pending badge]
  │   [trailing: 1 or 2 secondary GWButtons, wrap at narrow width] [refresh IconButton]
  ├ SizedBox(space8)
  ├ Expanded(
  │     ListView.separated(ChildWalletRow — now with a trailing MenuAnchor + optional badge)
  │     (or) GWEmptyState / GWErrorState — unchanged from Phase 36
  │   )
  └ [if populated or connected-empty] lag note — unchanged from Phase 36
```

- **Focal point, "This account" card:** the status line ("Child of {main}" / "Not registered as a
  child") — the card's job is to answer "what is MY account's own position," and that sentence is
  read before either action button, mirroring `36-UI-SPEC.md`'s identity-banner-title precedent.
- **Focal point, child row menu:** the enabled items' labels at full `textPrimary`/`statusErrorText`
  weight against a locked sibling's dimmed, tooltipped treatment — a user opening the menu expecting
  an unavailable action should see, at a glance, which item is greyed and reach for the tooltip.
- Every action on this screen (Fund/Recover/Revoke on child rows; Register/Detach/Move on "This
  account") runs as the account the node is CURRENTLY running as (Fund/Recover/Revoke are main-side
  and this screen only exists while running as the main; Register/Detach/Move are child-side and
  "This account" always describes the running account itself). The switch dialog (D-06) exists for
  the case where the running SDK account changes elsewhere WHILE this screen stays open (its subject
  address is fixed at open time via the route's `extra` — `router.dart:208-226` — and can drift from
  a later switch) — see Component Inventory's "Switch dialog" row.

### Fund / Recover dialog

```
GWDialog(title: 'Fund {child}')
├ Text: 'From {main} to {child}.'          — always visible, names both accounts (D-08)
├ SizedBox(space6)
├ GWTextField(Amount, suffix: GNUS + MAX)   — send_screen.dart's exact field
└ actions: [Cancel (ghost), Fund (primary)]
```

**Focal point:** the amount field — it is where the keyboard focus lands on open and where the
user's attention belongs; the "From/to" sentence sits above it, read once, not re-read per
keystroke.

### Revoke / Detach / Move dialog

```
GWDialog(title: '{Verb} {noun}?')
├ Text: '{Verb} {target}? It will no longer be a child of {other}.'   — D-08 wording
├ [Move only] GWWarningNote('The child keeps its current balance; nothing is transferred...')
└ actions: [Cancel (ghost), {Verb} (destructive)]
```

**Focal point:** the confirmation sentence itself — specifically the two account names inside it,
since confirming WHO is affected matters more here than which button is pressed.

### Register dialog / main picker

```
GWDialog(title: 'Register as a child?' | 'Move to another main')
├ [picker mode] Column
│   ├ …otherOwnAccounts.map(GWSelectRow)     — selected tracks in-dialog choice
│   ├ Divider
│   └ GWSelectRow('Enter an address', trailing: chevron_right)   — switches to field mode
├ [field mode] Column
│   ├ '‹ Back' link
│   └ GWTextField(Address, hint: '0x…', errorText: ...)
└ actions: [Cancel (ghost), Continue (primary, enabled once a target exists)]
```

Picking "Continue" from the picker immediately opens the Register/Move confirmation dialog above,
pre-filled with the chosen target — two dialogs in sequence, never merged, so the picker's own
Cancel always returns to a clean state.

**Focal point:** the list of the user's own linked accounts — legible identities, read first — with
"Enter an address" visually secondary (a plain trailing row, not a filled control), so the safer,
pre-verified path is what the eye finds before the free-text escape hatch.

### Switch dialog

```
GWDialog(title: 'Switch to {account}?')
├ Text: 'This action needs to run as {account}, not the account the node currently runs as.'
└ actions: [Cancel (ghost), 'Switch and continue' (primary)]
```

**Focal point:** the account name inside the title and message — the one thing this dialog exists to
tell the user before anything switches (per Specifics: "The switch dialog names the account it will
switch to").

### Switcher — "Node running as" section (`account_drawer.dart`, extended)

No structural change. Each `SDKAccountRow` gains the optional `lockedReason` per the Component
Inventory row above. **Focal point, locked row:** the dimmed content plus the small lock glyph —
together they should read as "not available right now" before a user reaches for the tooltip or
attempts the tap that would otherwise switch the node.

| partial | A child with a pending Fund and an idle Revoke simultaneously | ✅ covered | D-15 locks by (kind, target), not by target alone — Revoke stays available on a row whose Fund is pending, taken literally from CONTEXT rather than inferring a broader cross-kind lock it does not state. |
| partial | "This account" card mid-Move (old registration still true until resolved) | ✅ covered | The status line keeps reading "Child of {oldMain}" (the list-based truth) alongside the "Moving to {newMainName}…" badge until the real signal lands — never claims the new state early. |
| overflow / long-text | Long main/child/new-main names inside a confirmation sentence | ✅ covered | Dialog message `Text` wraps normally (no `maxLines`) — a confirmation is meant to be fully read, the same reasoning `36-UI-SPEC.md` gave the lag note; only ROW titles (not dialog prose) get `maxLines: 1`. |

| locked | SWT-06, a timed-out (not-confirmed) operation | ✅ covered | D-16: "Timed-out operations do not lock" — the moment a badge flips to "Not confirmed yet," the corresponding SWT-06 lock (if it was the only pending op from that account) releases; the row un-dims. |
