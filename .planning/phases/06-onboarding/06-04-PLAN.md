<objective>
Re-skin the import path — the shared `PasteField` (UI-SPEC §4.7) and the four-tab
`ImportSecurityScreen` that mounts it (§4.6) — and close the one genuine security gap this phase's
research surfaced.

Purpose: ROADMAP Phase 6 criterion 1's import half (import-wallet renders in the redesign skin and
completes end to end) and SCR-02's key-safety clause on the import path.

Sequencing: `PasteField` is edited FIRST because `ImportSecurityScreen` mounts four of them; the parent
then lands on a child that already exists in its final form.

**The PasteField hardening is PLANNED, not deferred — and it is a deliberate behavior change on a
port.** UI-SPEC §3.6 recommends it without mandating it, and §9.2 allows filing a todo instead. This
plan takes the stronger option, for reasons worth stating rather than assuming:
- `PasteField`'s `TextFormField` is where a user TYPES OR PASTES an existing mnemonic or private key.
  Flutter defaults both `autocorrect` and `enableSuggestions` to `true`, so that key material can be
  handed to the OS predictive-text / spell-check / IME-learning system while being entered. On a
  desktop wallet this is a real, if quiet, key-material leak.
- The phase goal is "create or import a wallet **with no loss of key safety**", and SCR-02 names key
  safety explicitly. AGENTS.md's laziness rule carves out security by name.
- The change is two named parameters on a `TextFormField` that already exists. No structure moves, no
  IA changes, no copy changes, no widget is swapped to obtain it.
- It cannot be obtained by a `GWTextField` swap: `GWTextField` does not expose either parameter today,
  and adding them there is a shared-primitive change outside this phase's file scope. So the fix goes
  directly on `PasteField`'s own `TextFormField` — the minimal, local option (§4.7).
It is nonetheless a behavior addition, not a pure re-skin, so it is recorded here, in the task action,
in the threat register, and must be restated in the SUMMARY.

Re-skin, never restructure (§1): develop's `Center`/`ConstrainedBox(small * 0.8)`/`Column` tree,
`PasteField`'s `Stack` + `Positioned` paste-button layout, the four-tab `DefaultTabController` shape and
the `Form`/`GlobalKey` validation wiring are all locked. Alex's `paste_field.dart` is a READ-ONLY
reference for its container decoration only.

Appearance-color access path (04-02/04-04 discipline): appearance-aware colors read via
`final gw = Theme.of(context).extension<GWColors>() ?? GWColors.dark();`; `brandPrimary` as a CURSOR
colour is mode-invariant and stays on the static getter (a cursor is decorative, not text-on-fill, so
the light-mode brand-as-text trap does not apply).

Output: a hardened, token-correct `PasteField` and a token-correct four-tab import screen, with every
import dispatch, validator and failure surface preserved.
</objective>
