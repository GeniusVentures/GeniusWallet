## Blocking constraints — discovered through actual failure this session

**`severity: blocking` — a resuming agent must internalise these before acting.**

1. **Re-measure audit findings before acting on them.** Three of this session's audit findings were
   **wrong**, and were only caught because the planner re-measured:
   - `GWTimeframeSegment` was called a "character-identical 150-line duplicate". It is **not** —
     different label arrays (`['24H','7D','30D','1Y']` vs `['1H','1D','1W','1M','1Y']`) and different
     track colours. The extraction was refused.
   - `GWCopyRow` was called "3 forks". It is **2** — below the Rule of Three floor. Refused.
   - Raw colour references were reported as 114. Actual total is **525**; the 114 was the
     `Colors.white/black/grey` subset, itself actually **83**.
   Treat any count in a planning doc as a hypothesis until re-run.

2. **The Flutter SDK is OFF `PATH`.** It lives at
   `C:\Users\User\Documents\Projects\GNUS\flutter\flutter\bin`. Every flutter/dart invocation needs
   `export PATH="/c/Users/User/Documents/Projects/GNUS/flutter/flutter/bin:$PATH"` first. Omitting it
   yields "command not found", which this project has **previously misread as a compile failure** —
   that is the origin of the long-standing false belief that `flutter test` doesn't compile.

3. **`flutter analyze` exits NON-ZERO on infos.** `flutter_tools` sets both `fatal-infos` and
   `fatal-warnings` to `defaultsTo: true`, unlike `dart analyze`. Judge by issue COUNT, not exit
   code, until the count is genuinely 0. An audit agent reported "exit 0" this session; direct
   measurement showed exit 1.

4. **The analyzer resolves the NEAREST `analysis_options.yaml`,** not the repo root one.
   `packages/genius_api/` has its own, so root excludes never applied there — the root's
   `packages/genius_api/lib/proto` entry had done nothing for its entire existence. Fixing this alone
   took analyze from 408 → 85.

**`severity: advisory`**

5. **Security gates can pass vacuously.** Two were found broken this session:
   `check_no_new_key_logging.sh` only diffed working tree vs index — always empty on a fresh CI
   checkout, so it would have passed unconditionally forever (now has `--scan-tree`).
   `check_onboarding_seed_safety.sh` CHECK 4 text-matched the *unbraced* `if` form and broke when
   22-04 braced it. When touching a gate, prove it still **fails** on an injected violation.
6. **`verify_additive_boundary.sh` is wired NON-BLOCKING in CI** — it has 2 pre-existing Phase 8/16
   false positives that would make the job red on day one. Documented in `../22-.../deferred-items.md`.
