<objective>
Finish the colour consolidation: close the primitive layer so nothing outside the theme library can
reach the raw palette, tokenize the two remaining raw-value families (the monospace font family,
reached by string literal from seven files, and the hardcoded stops in `GWDecorations`), and land the
CI gate that keeps it that way.

The locked decision is explicit: **do not delete the legacy palette class** — demote it. It is the
primitive layer in the Material 3 primitive → semantic → component model, and the value of that split
is lost the moment a screen can import the raw palette.

Purpose: one way to read a colour, enforced by the compiler rather than by a rule in a document.
Output: genuinely-private primitives, a mono type token, de-hexed decorations, and a scoped
raw-colour gate wired into CI.
</objective>

    **Monospace family.** The bundled mono font is reached by raw string literal from seven files —
    seed phrases, addresses, transaction hashes, log output, job payloads. A typo in one of those
    strings silently falls back to the platform default, and the fallback is proportional, which
    breaks the character-column alignment those screens depend on for verification. There is no
    runtime error and no test failure; the user simply reads a seed phrase in the wrong font and does

    the same complete style, add that style as the token instead of the bare family name — the same
    Rule of Three that governs component extraction. If they genuinely differ, the token is the family
    name and each site keeps its own size and weight.

    Dart has no package-private visibility, so "private to the theme layer" cannot be a naming
    convention — a convention is exactly what got the repo here. Use the language.

    Make `gw_colors.dart` the library and `genius_wallet_colors.dart` a `part` of it. The raw values
    then become genuinely private: underscore-prefix them and the compiler makes them unreachable from
    any other library. A `part` file carries no imports of its own, so move
    `genius_wallet_colors.dart`'s imports up into `gw_colors.dart`.

    Sequence it so the tree compiles at every step:

      1. **Clear the last readers first.** Migrate the six `test/` files onto `GWColors` — read through
         `theme.extension<GWColors>()` where a pumped theme exists, or `GWColors.dark()`/`.light()`
         where the test is a pure value assertion. Do this as its own commit, with the full suite green,
         BEFORE touching visibility. `test/theme/theme_contrast_test.dart` in particular reads several
         members and 23-03 just extended it; migrating it is mechanical but it is the file most likely
         to hide a subtlety, so do it deliberately rather than with a search-and-replace.
      2. Re-run the repo-wide search. The only remaining readers must be inside `lib/theme/` plus
         whatever `23-03-SUMMARY.md` recorded as a deliberate survivor. If anything else appears,
         migrate it first — do not proceed with an outstanding consumer.
      3. Convert the file to a `part`, moving imports.
      4. Underscore-prefix the public members and update the theme-internal consumers (`theme.dart`,
         `GWDecorations`, `nav_chip_style.dart`, and `GWColors`' own factories).
      5. Delete any member that now has zero references. A private member nobody reads is dead code,
         and this is the first moment the compiler can prove it. Deletion over addition.

    **Do not delete the class.** Do not flatten the file into `gw_colors.dart`. It is the primitive
    layer and it carries the measured contrast rationale for many values; the split is the point.

    **Preserve every doc comment**, including measured contrast ratios and `ponytail:` notes. They are
    the record of why a value is what it is, and a value whose reason is gone gets "simplified" back
    into a failure.

    For any deliberate survivor outside the theme library that genuinely cannot take a `BuildContext`,
    expose exactly the field it needs through `GWColors` or one narrow named accessor. Do not re-open
    the whole palette for one consumer.

    If the appearance global is still read by the primitive getters, that is fine and unchanged — the
    primitives are allowed to know about appearance. What changes is that nobody outside the library
    can call them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| theme library → application code | The primitive layer must be unreachable from screens, or the semantic layer is advisory |
| CI gate → merge | A gate scoped too narrowly gives false assurance; scoped too widely it gets disabled |
| font family string → secret display | Seed phrases and addresses render in the mono family; a silent fallback to a proportional font changes how a user verifies what they are looking at |

| T-23-19 | Tampering | primitive layer reachable by convention only | high | mitigate | `part`/`part of` plus underscore-prefixing makes the compiler the enforcement. Binary and unfakeable — a strictly stronger guarantee than any visual check. |
| T-23-20 | Denial of Service | demotion breaking six test files mid-change | medium | mitigate | The six readers are enumerated in advance from `23-02-RESIDUE.md` and migrated in their own green commit BEFORE visibility changes. |
