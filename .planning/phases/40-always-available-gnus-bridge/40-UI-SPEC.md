# Phase 40 - UI Design Contract

> Visual and interaction contract for the always-available GNUS Bridge entry. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 40-CONTEXT.md (D-01..D-15), 40-RESEARCH.md, six decisions locked by the user in the ui-phase session, and a read of `lib/theme/`, `gw_button.dart`, `compute_panel.dart`, `coin_card_row.dart`, `token_info_screen.dart`.

## Spacing Scale

All values are existing `GeniusWalletConsts` tokens (`lib/theme/genius_wallet_consts.dart`), verified against the file. Naming convention in that file: the token number is half the pixel value (`space2` = 4.0, `space4` = 8.0, `space6` = 12.0, `space8` = 16.0). The pixel values below are the declared scale; the token names are only the code handles.

| Token (code name) | Value | Usage in this phase |
|-------------------|-------|---------------------|
| `space2` | 4px | Gap between the button (or button row) and its caption, on the dashboard and /assets |
| `space4` | 8px | Gap between the job button and Bridge in the dashboard row; gap between the coin-page Wrap and its caption; /assets horizontal inset (`kGWRowWall`, which is `space4`) |
| `space6` | 12px | See exception below |
| `space8` | 16px | not used |

Exceptions: one, 12px (`space6`). It appears in exactly two places and this phase introduces neither value:
1. /assets bottom inset under the Bridge entry reuses the existing `kGWRowSeparatorGap` (12px, the gap every Assets row already keeps above its divider; pinned by the row-rhythm tests). Keeping it means the divider rhythm below the GNUS row is unchanged.
2. The gap above the dashboard CTA row is the existing `SizedBox(height: space6)` in `ComputePanel`, inherited and unchanged.

12px is a multiple of 4, so it is on the 4-pt grid. `space3` (6px, the repo's one half-step) is not used.

Fixed heights that already exist and are reused: `GWButtonSize.sm` is 44px (the touch floor). Caption line box is 18px (13px at height 18/13).

## Typography

This phase adds no type role. Button label and caption are the same existing style.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Button label (`GWButtonSize.sm`, `labelMd`) | 13px | 500 | 18px (1.38) |

| Body / Heading / Display | not used | - | - |

Total for the phase: 1 size, 1 weight, both inherited. Line-height is the repo's `labelMd` metric, which is also the compute panel's sub-line metric (18px), so the height budget below uses a measured number.

Do NOT use `GeniusWalletTypography.bodySm` for the caption. It bakes `fixedTextSecondary` (`#8A8F9D`, mode-invariant) as its colour, which is 3.3:1 on the light elevated surface unless overridden. The caption always passes `color: gw.textSecondary` explicitly and reads `gw` inside `build`.

## Color

No new surface. The Bridge entry sits on the surfaces each host already paints.

| Role | Dark | Light | Usage |
|------|------|-------|-------|
| Dominant (60%) | `surfaceBase` `#0B0D12` | `#DCE0E6` | /assets and coin page canvas |
| Secondary (30%) | `surfaceElevated` `#0C0E14` | `#FFFFFF` | Dashboard compute card |
| Accent (10%) | `GeniusWalletGradient.brandCta` `#0AD89C` to `#0AAEE6` | same | Enabled Bridge border and label only |
| Destructive | not used | not used | - |

Accent reserved for: the border and label of the enabled Bridge button (`gradientOutline`), exactly as Send, Receive and Buy already use it. The caption never uses an accent. The disabled Bridge button uses no accent.

### Caption contrast (token `gw.textSecondary`)

Measured with the WCAG relative-luminance formula against the exact surface hex values in `genius_wallet_colors.dart`.

| Surface | Dark | Light | Threshold |
|---------|------|-------|-----------|
| `surfaceBase` | 6.01:1 | 4.75:1 | 4.5:1 text |
| `surfaceElevated` | 5.97:1 | 6.30:1 | 4.5:1 text |

All four pass AA. Light mode on `surfaceBase` is the tightest at 4.75:1 (the /assets and coin-page canvas), so the caption must not be dimmed, alpha-blended or moved to another token. Forbidden for the caption: `textMutedOnSunken`, `textDisabled`, `textTertiary`, any `textPrimary<NN>` below 70, `GeniusWalletTypography.bodySm`'s baked colour.

### Button appearance per state

| State | Variant | Size | Appearance |
|-------|---------|------|------------|
| Enabled | `GWButtonVariant.gradientOutline` | `sm` | Brand-gradient border and label, transparent fill (D-06, same as the coin page today) |
| Disabled | `GWButtonVariant.tertiary` | `sm` | Neutral: `surfaceElevated` fill at alpha 140, `borderSubtle` hairline, `textPrimary` label at alpha 140. No gradient. |

`BridgeButton` picks the variant from the gate: `enabled ? gradientOutline : tertiary`. One ternary, no boolean flag on the widget, same label, icon, size and height in both states, so the row never reflows when the gate flips.

This is a deliberate departure from the coin page's current look. Today that page never shows a disabled Bridge (it hides it, or dims `gradientOutline` when `balance == 0`), so every disabled Bridge the user has seen is the faded outline. The new neutral look replaces it, for the contrast reason below, and the coin page adopts it too so all three surfaces agree.

Why not `gradientOutline` when disabled (decision, measured by arithmetic on `gw_button.dart:217-239,346-362`): the disabled outline is dimmed twice. The label colour is set to alpha 140 and then the srcIn ShaderMask applies the gradient at alpha 140 again, so the label lands at about 30% alpha and the border at 55%.

| Disabled `gradientOutline` | Label (green stop / blue stop) | Border |
|----------------------------|-------------------------------|--------|
| Dark, `surfaceElevated` | 1.92:1 / 1.68:1 | 3.78:1 / 3.00:1 |
| Light, `surfaceElevated` | 1.24:1 / 1.33:1 | 1.46:1 / 1.70:1 |
| Light, `surfaceBase` | 1.15:1 / 1.25:1 | 1.26:1 / 1.48:1 |

In light mode that is effectively invisible, which defeats the phase goal ("Bridge can always be found"). The neutral disabled treatment measures:

| Disabled `tertiary` label | Dark | Light |
|---------------------------|------|-------|
| On `surfaceElevated` | 6.20:1 | 4.11:1 |
| On `surfaceBase` | 6.20:1 | 3.96:1 |

Floor for this contract: disabled label at least 3:1 in both modes (disabled controls are exempt from WCAG 1.4.3, but the repo rule is that disabled stays visibly distinct and legible). Disabled is told apart from enabled by four independent channels, not alpha alone: neutral vs gradient colour, no gradient border, a reason caption underneath, and the semantic disabled flag. The flat-neutral disabled look also matches how the adjacent "New processing job" button already disables (`flatDisabled` in `GWButton`).

## Copywriting Contract

Terminology: Earning / earning wallet. Never node, SDK or minting (D-10). Sentence case, ends with a full stop, straight apostrophes.

| Element | Copy |
|---------|------|
| Button label (all surfaces, all states) | `Bridge` |
| Primary CTA | `Bridge` |

### Reason captions (one per gate state; exact strings)

Rank is the resolver precedence adopted from RESEARCH (top wins). The static captions (every row except `gnusElsewhere`) are at most 36 characters so they fit one 13px line in the narrowest pinned panel (290px wide, 264px content, about 40 characters). The `gnusElsewhere` caption varies with the network name and may ellipsize on that panel (see the note below the table).

| Rank | Gate state | Caption |
|------|------------|---------|
| 1 | `noWallet` | `Select a wallet to bridge.` |
| 2 | `viewOnly` (view-only wallet and SDK account view) | `View-only wallets can't bridge.` |
| 3 | `child` | `Child wallets can't bridge.` |
| 4 | `switching` | `Switching earning. Try again soon.` |
| 5 | `notStarted` | `Start earning to bridge.` |
| 6 | `notEarning` | `Only the earning wallet can bridge.` |
| 7 | `wrongNetwork` (selected network has no RPC, for example Super Genius) | `Can't bridge on this network.` |
| 8 | `checking` | `Checking your GNUS balance.` |
| 9 | `gnusElsewhere` | `GNUS is on {network}. Switch network.` |
| 10 | `noGnus` (also the result when the other-network probe fails) | `You have no GNUS to bridge.` |
| 11 | `enabled` | no caption, no reserved space |

- `{network}` is `Network.name` verbatim from `networks.json` ("Base", "Ethereum Sepolia", "Base - Sepolia"). If the resolver has no name, the fallback is `GNUS is on another network.` (27 characters), never an empty slot.
- Deliberate shortening: the user's example sentence ("Your GNUS is on Base. Switch network to bridge.", 47 characters) cannot fit one line at 264px. The contract keeps its meaning (names the network, tells the user to switch) in 34 to 44 characters. The longest same-class case, `GNUS is on Ethereum Sepolia. Switch network.`, is 44 characters and ellipsizes on the narrowest panel only; the full text is still in the semantics label and the name comes first.
- All captions are distinct and non-empty (iterate `BridgeGateState.values`, same idiom as `compute_state_distinct_test.dart`).
- One function owns these strings (D-04). The caption widget and the submit-time refusal both read it. No surface hard-codes a reason.

| Element | Copy |
|---------|------|
| Empty state heading / body | not applicable. The zero-balance case is the `noGnus` caption above. |
| Error state (submit-time refusal in `BridgeScreen`, D-13) | Error toast, `type: ToastType.error`, title `Can't bridge`, message = the same caption string for the current gate state. `bridgeOut` is not called, no receipt is shown, the CTA returns from "Bridging..." to its normal state. |
| Error state (stale tap on a surface) | No toast. The tap is ignored and the button re-renders disabled with its caption on the next frame. |
| Destructive confirmation | none in this phase. Bridge itself keeps its existing flow. |

## Layout and Interaction Per Surface

### Focal point per surface

| Surface | Anchor (what draws the eye first) | Bridge's role |
|---------|-----------------------------------|---------------|
| Dashboard compute card | `New processing job`: the one filled gradient CTA, left, widest | Secondary. Outline, right, narrower. When the job button is disabled (flat tint) the balance tile above becomes the anchor and Bridge is still secondary. |
| /assets | The GNUS `CoinCardRow` itself (title, price, holding) | Subordinate to the row: small outline button tucked under it at the row wall, no fill. It never competes with the row's amount column. |
| GNUS coin page | `Swap`: the one `gradient`-filled action in the row | Peer of Send, Receive and Buy: same outline weight, fourth in order. Disabled Bridge recedes to neutral and does not pull the eye from Swap. |

Nothing in this phase adds a second filled control to any surface.

### 1. Dashboard wallet overview (compute card)

- Structure: the existing `New processing job` button and Bridge share one `Row` at the bottom of the compute column. Order is job left, Bridge right.
  - Job button: `GWButton primary sm expand`, wrapped in `Expanded`.
  - Gap: `SizedBox(width: space4)`.
  - Bridge: `BridgeButton`, intrinsic width, `sm` (44px). Both buttons are 44px tall, so the row costs no extra height.
- Caption: below the row, `SizedBox(height: space2)` then the caption, full card content width, left-aligned flush with the job button's left edge. Absent when enabled.
- `ComputePanel` takes two new optional params (`bridge`, `onBridge`). When `bridge` is null the row is the old full-width job button, so the five other `ComputePanel(` call sites compile and render unchanged.
- Height budget (locked): `kDashboardPanelSlotHeight` 340 to 360.

| | Before | After |
|---|--------|-------|
| Slot | 340 | 360 |
| Content budget (`slot - 2 * (space6 + 1)`) | 314 | 334 |
| Tallest state | 306 | 306 + 4 + 18 = 328 |
| Slack | 8 | 6 |

Comments naming 340 and 314 in `dashboard_screen.dart`, `wallet_overview.dart` and `compute_panel.dart` must be updated with the constant.

- Narrow and mobile behaviour:
  - The row never wraps and never stacks. Bridge keeps its intrinsic width; the job label (already `Flexible` with ellipsis inside `GWButton`) is what gives way.
  - Width arithmetic at the 290px pinned case (264px content): job button about 142 (label about 118 plus 24 padding), Bridge about 86 (icon 16, gap 4, label about 42, padding 24), gap 8, total about 236, so about 28px spare and no ellipsis at text scale 1.0. These are estimates, not a pump.
  - Below that (a 320dp phone at large text, content under about 236px) the job label ellipsizes before Bridge does. No horizontal overflow at text scale 1.3 at 290px: Bridge is about 99, job gets the rest and ellipsizes.
  - Fallback if the pumped 290px test shows the job label ellipsizing at scale 1.0: drop the leading icon from `BridgeButton` on all three surfaces (not a per-surface flag). Do not shrink the font and do not stack the buttons.
  - Phones: the panel is uncapped in height (one-column dashboard), so only the width rules apply there. Desktop is the only capped slot.

### 2. /assets page (GNUS row only)

- The dashboard panel's asset list (`coins_screen.dart`) is untouched (D-14).
- Placement: inside the `_body` loop, between the GNUS `CoinCardRow` and its `Divider`. `CoinCardRow` is not edited (its anatomy is pinned by row-rhythm tests, and it must not gain a second tap target).
- Which row: the first coin whose symbol is `gnus` (case-insensitive), regardless of address. On a network with no RPC (Super Genius) that is the native coin, and Bridge shows disabled with the `wrongNetwork` caption. Enabling and opening `/bridge` still require a non-empty contract address (D-15), decided by the gate, not by this placement rule.
- Geometry: `Padding(left: kGWRowWall (8), right: kGWRowWall (8), bottom: kGWRowSeparatorGap (12, the declared spacing exception))`, content `Column(crossAxisAlignment: start)` of `BridgeButton` (left-aligned, intrinsic width, `sm`), `SizedBox(height: space2)`, caption. The row's own 12px bottom padding supplies the gap above the button.
- Layout shift: the caption slot collapses when the gate is enabled and no space is reserved. Rows below the GNUS row move by 22px (4 + 18) when the gate flips between enabled and disabled. Accepted: it happens at gate resolution, not under the user's finger, and no animation is added.

### 3. GNUS coin page

- Bridge stays in `_CoinActionRow` between Receive and Buy. Condition changes from `isGnusBridgeEnabled && canSendFrom(...)` to `pageSymbol == 'gnus'` (the test Buy already uses). It is rendered always, disabled when the gate says so, never hidden.
- Variant and size as above (`gradientOutline` enabled, `tertiary` disabled, `sm`), with the existing `Icons.alt_route`.
- Caption: on its own line directly below the `Wrap`, `SizedBox(height: space4)` above it (matches `runSpacing`), left-aligned. It is not a Wrap child, so a 36-character caption cannot widen a Wrap item.
- Because the caption sits under the whole button row, every caption contains "bridge" or "GNUS" or the word "network" so it is self-explanatory when the Wrap has wrapped onto two lines on a phone.
- 360px, both modes: no overflow (extend the existing 360px loop in `buy_entry_points_test.dart`).
- Opened from Markets with `marketData` GNUS: Bridge is shown with the gate for the Selected wallet and network, never gated on `selectedCoin`.

### Interaction rules (all surfaces)

- Label stays `Bridge` (D-06). Tapping it only opens the existing `BridgeScreen`. No burn happens from these entries, and there is no new confirmation, review step or dialog: the burn is still confirmed and submitted by the existing `BridgeScreen` flow (amount entry, its CTA ladder, the `Bridge` submit button, the receipt), unchanged apart from the submit-time gate re-check.
- Enabled tap: re-read the gate, call `selectCoin(gate.coin)`, push `/bridge`, then `getCoins()` on return (the shared `openGnusBridge` handler).
- Disabled tap: nothing. No toast, no tooltip, no ripple (GWButton already suppresses ink and uses the basic cursor when `onPressed` is null). The reason is the caption, visible without hover (D-09).
- Hover and press: enabled uses `GWButton`'s existing `gradientOutline` overlay (faint brand tint). No custom hover.
- Keyboard: the disabled button is not focusable (no `onTap`). Its reason stays reachable through the caption's own semantics node.
- No `Tooltip`, no `tooltip:` argument on the button.
- Motion: none added. The variant swap uses `GWButton`'s existing `AnimatedContainer` (`GeniusWalletMotion.fast`).

## Semantics (screen readers)

Flutter has no describedby. A disabled `InkWell` exposes no button or disabled state on its own, so `BridgeButton` wraps `GWButton` in one explicit node:

- `Semantics(button: true, enabled: gate.enabled, label: 'Bridge', hint: <caption string> when disabled, excludeSemantics: true, onTap: <open handler> only when enabled)`, `excludeSemantics: true` so the inner visual "Bridge" text does not read twice and the node, not `GWButton`, owns the announcement. Do not also pass `GWButton.semanticLabel` (it would merge with the inner text).
- `BridgeReasonCaption` is a plain `Text` and stays its own semantics node (not excluded). Reason: some users switch spoken hints off, so the reason must exist as readable content, not only as a hint. Result: focusing the button reads "Bridge, button, dimmed, {reason}"; swiping on reads the caption once more. That duplicate is accepted.
- No live region. Gate changes follow user actions elsewhere (an earning switch, a network switch) and an announcement on every change would be noise on an idle dashboard.
- Enabled: no hint, no caption node.

Pinned by the widget test: the button's semantics data has `isButton`, `hasEnabledState`, `isEnabled == false` when disabled, label `Bridge`, hint equal to the caption; `find.bySemanticsLabel(caption)` finds the caption; one match per caption on each surface.

## Acceptance Checks the Planner Must Carry

1. Contrast: `gw.textSecondary` on `surfaceBase` and `surfaceElevated` at least 4.5:1 in both modes (4 assertions). Disabled `tertiary` label at least 3:1 composited over both surfaces in both modes.
2. Disabled `BridgeButton` has no gradient and a label colour that is `textPrimary` at alpha 140; enabled has the `gradientOutline` shader. Same height (44) and same label in both.
3. Every gate state renders a caption except `enabled`; the Bridge button exists on all three surfaces in every state (never absent).
4. Each static caption renders on one line (no `didExceedMaxLines`) inside the 264px content width at text scale 1.0.
5. Dashboard: row fits at 290 and 320, slot constant is 360, tallest state plus caption at most 334.
6. Semantics as pinned above.
7. A grep or test that no surface hard-codes a reason string outside the one resolver file.

## Flags for Planner and Checker

1. Inherited light-mode weakness, not introduced here. Enabled `gradientOutline` measures 1.40:1 to 2.56:1 (border and label) on the light surfaces, because `GWButton` always masks with `brandCta`. Send, Receive and Buy have the same issue today. This contract keeps `gradientOutline` for the enabled state because D-06 locks it. Consequence: in light mode the disabled neutral label (about 4:1) can read stronger than the enabled gradient label. The caption and the semantic state still tell them apart. Recommended separate todo, outside this phase: let `GWButton`'s outline mask use `GeniusWalletGradient.brandCtaText(gw.surfaceMenu)` (light collapses to `#0A6885`, 4.76:1 and 6.30:1), which fixes every outline button at once, and remove the double-dimming on disabled outline. If the checker blocks on this, that todo is the fix, not a change to this phase's variant.
2. The disabled-state numbers in the Color section are computed from the code's alpha arithmetic and the token hex values, not from a pump. The widget test in check 1 is what confirms them.
3. The 290px fit numbers are estimates (Inter 13px advance widths). The pumped test decides; the icon-drop fallback is pre-approved above.
4. `BridgeScreen` refusal (D-13) reuses the caption function, so copy edits land in one place.
