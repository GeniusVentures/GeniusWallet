<objective>
Re-skin the two signing-path drawers to 033-B1 and prove they are behaviourally
identical afterwards.

This is the one plan in the phase where the visual work is the smaller half. The
larger half is the proof. `ApproveTransactionDrawer.show` and
`ApproveDappConnectionDrawer.show` each return a `Future<bool?>` that
`handle_dapp_requests.dart` and `reown_connect_button.dart` branch on to decide
whether to sign. Three outcomes exist - approve, reject, and dismissal - and all
three must survive a chrome change untouched.

Purpose: 033-B1's border reduction on the two drawers that most need calm, with
a test that fails if the approve/reject contract ever moves.
Output: three re-skinned files and a contract test.
</objective>

## Decision: the 033-B1 fiat line is dropped, loudly

`drawers-final/README.md` records 033's fiat line carrying a `*` meaning "the
price feed exists but is not wired to this drawer". 21-CONTEXT says: keep the
marker or wire it deliberately, do not quietly drop it.

It is being dropped, and this is the not-quiet part. Wiring a live price into a
signing screen is new data on the signing path, which the fence forbids. Keeping
an unwired starred number means printing a fiat figure next to an amount a user
is about to authorise, with a footnote explaining it might be wrong - which is
worse than printing nothing. So this plan prints nothing, and the decision is
recorded here, in the plan summary, and in a comment in
`send_transaction_details.dart` naming what it would take to add it back
(a price read at the `handle_dapp_requests` layer, as its own task, in a phase
that owns that file). This is the only element of a decided sketch this phase
does not implement.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote dApp -> drawer identity | `dappName`, `dappUrl`, `dappDescription` and `iconUrl` all come from the connected peer's session metadata. The peer is untrusted by definition. |
| dApp -> transaction parameters | `to`, `from`, `value`, `gas`, `maxFeePerGas`, `maxPriorityFeePerGas` arrive in the session request and are formatted upstream in `handle_dapp_requests.dart`. |
| drawer -> signing decision | The drawer's `Future<bool?>` is the sole input to whether the wallet signs. |
| `iconUrl` -> `Image.network` | An attacker-supplied URL is fetched by the wallet when a signing prompt opens. |
