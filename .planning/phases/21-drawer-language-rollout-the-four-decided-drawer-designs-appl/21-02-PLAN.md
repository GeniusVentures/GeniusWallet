<objective>
Convert the one list picker that is still hand-rolled.

D-04 names six list drawers. Measured at HEAD `08f6df5`, four of them already
consume `GWSelectRow` (Select Network, Your Accounts, SDK Accounts, the token
picker), a fifth — the `coins_screen.dart` "Assets" drawer — **does not exist**
(`Assets` is a `GWSectionTitle` rendered inline on the dashboard, and
`coins_screen.dart` has exactly one drawer, the Receive one). That leaves
exactly one: the bridge destination picker, which still paints selection as a
`borderStrong` rectangle around a `surfaceMenu` `ListTile` with a plain
`Icons.check`.

That treatment is the one 068-A measured and rejected: the border is 1.60:1 on
the drawer panel and the tint 1.39:1, so on this row the only thing carrying
selection above 3:1 would be the glyph — and its glyph is an untinted
`textPrimary` check with no ShaderMask, i.e. the same shape an unselected row
could plausibly show. `GWSelectRow` already solved this, has four consumers and
its own contrast-reasoned test.

Purpose: the fifth and last 032-A1 call site, so the pattern is finished rather
than mostly-finished.
Output: one converted picker, one private widget deleted, one behavioural test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chain metadata -> row label | `network.name` and `network.iconPath` come from the bridge network list, not from user input, but they are unbounded strings rendered in a fixed-width panel. |
| row tap -> destination chain id | The tapped row sets `toNetwork`, which becomes `destinationChainId` on a real `bridgeOut` call. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-01 | Tampering | destination chain selection | high | mitigate | The tap closure is carried over verbatim and Task 2 asserts the tapped network is the one that lands. A re-skin that silently reordered or mis-keyed the list would change which chain a bridge sends to. |
| T-21-02 | Denial of Service | unbounded `network.name` | low | mitigate | `GWSelectRow` ellipsises its title; the hand-rolled row did too. No regression, and the shared row is the stricter of the two. |
| T-21-03 | Spoofing | selection state not visible | medium | mitigate | The whole point of the change: the shared row's gradient check carries 1.4.11 on its own where the old border did not, so a user cannot mistake which chain they are bridging to. |

No package-manager installs in this plan. No new dependency.
</threat_model>
