<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wallet address -> QR payload and rendered text | The address is the value a user checks before someone sends them funds. A mis-rendered address loses money. |
| clipboard | The copy action writes the address to the system clipboard. |
| network name -> the amber note's sentence | The network name is interpolated into rendered copy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-26 | Tampering | address chunking | critical | mitigate | A chunking bug that drops, reorders or duplicates a character would show a user an address that is not theirs. The round-trip assertion in Task 1 - reassembled groups equal the input exactly - is the specific guard, and the short and empty cases stop it throwing on edge inputs. |
| T-21-27 | Tampering | clipboard payload | critical | mitigate | The copy path must keep writing `widget.address`, never the rendered or chunked form. Named explicitly in Task 1's acceptance criteria. Showing chunks while copying chunks would paste an unusable address. |
| T-21-28 | Information Disclosure | full address now rendered instead of truncated | low | accept | A receive address is public by design - it is the value the user is about to hand out. Showing all of it is the requirement, not a leak. Shoulder-surfing a receive address gains an attacker nothing they could not get by being sent it. |
| T-21-29 | Spoofing | QR contrast | high | mitigate | The QR's unconditional light backing is required to survive (finding 16/6). A dark-on-dark QR that fails to scan pushes users to type an address by hand, which is where transcription errors happen. |
| T-21-30 | Denial of Service | long network name in the amber note | low | accept | Unchanged from today; the note's text already sits in a `Flexible`. This plan does not touch it. |

No package-manager installs in this plan.
</threat_model>
