  <files>lib/dashboard/home/widgets/transaction_utils.dart, test/dashboard/transaction_utils_test.dart</files>
  <action>
Add to `transaction_utils.dart` (keep the existing `getExplorerUrl` and `formatAmount` exactly
as they are — `formatAmount` has another consumer):

`String formatTxAmount(String raw)` — the clamp the ROADMAP locks. Behaviour, in this order:
  - `double.tryParse(raw)`; if null, or `isNaN`, or `isInfinite`, return `raw.trim()` unchanged.
    This is both the honest fallback and the layout-starvation guard: a hostile or malformed
    amount must not reach a number formatter that could emit an unbounded string.
  - value == 0 -> "0.00".
  - `value.abs() >= 1000` -> `NumberFormat('#,##0.00')` — exactly 2 decimals, grouped.
    `123456789.123456789123456789` becomes `123,456,789.12`, which is the symptom sketch 010
    named as setting the panel's width.
  - `0 < value.abs() < 0.000001` -> the literal string `<0.000001` (prefixed with the sign for
    negatives). Six decimals of a value that small render as all zeros, which states nothing.
  - otherwise -> `NumberFormat('#,##0.00####')` — minimum 2, maximum 6 decimals, grouped, so
    `0.75` stays `0.75`, `0.0042` stays `0.0042` and `3.5` reads `3.50`.
  Return the magnitude WITHOUT a sign or symbol; the caller composes those.

`String? exactTxAmount(String raw)` — returns `raw.trim()` when it differs from
`formatTxAmount(raw)`, else null. Null means "the displayed value is already exact, do not
attach a tooltip". Deliberately returns the RAW MODEL STRING, not a re-rendered double:
re-formatting through `double` is what would lose the precision this exists to preserve.

`String sanitizeCoinAsset(String symbol)` — lowercase, keep only `a-z0-9`, truncate to 12 chars,
return `''` when nothing survives. `coinSymbol` is attacker-chosen and today's code interpolates
it straight into `assets/images/crypto/${coinSymbol.toLowerCase()}.png`. Callers must use this
before building that path and fall back to the neutral dot on an empty result.

`double? fiatValue({required String symbol, required double amount, required Map<String, double> pricesBySymbol})`
— pure: looks up `symbol.toLowerCase()`, returns `price * amount`, or null when the symbol is
unknown. Null means "no price is known", which the row renders as an ABSENT line — never as
`$0.00`. Inventing a zero is the same failure sketch 010 flagged on the failed row.

`Map<String, double> livePricesBySymbol()` — the one impure function here. In order:
(1) if `kDebugMode` and `DevMockHoldings.instance.marketData` is not empty, map it to
`{symbol.toLowerCase(): currentPrice}`; (2) else if `Hive.isBoxOpen(marketDataBox)`, fold the
box's values into the same shape; (3) else return `const {}`. The `isBoxOpen` guard matters
twice — it keeps unit tests from needing a Hive binding, and it keeps a pre-init frame from
throwing. Add a `ponytail:` comment: this reads the cache the Assets panel already fills and
adds NO network call of its own, so a transaction in a coin the wallet does not hold simply has
no fiat; the upgrade path is a shared price provider if that ever becomes a real gap.

`String formatFiat(double value)` — reuse the existing
`NumberFormat.currency(symbol: '\$', decimalDigits: 2)` shape already used in
`transaction_displays.dart` and `transactions_slim_view.dart`; declare one module-level
formatter here so those two files can drop their private duplicates later.

Then extend `test/dashboard/transaction_utils_test.dart` with a `formatTxAmount` group asserting
at minimum: `123456789.123456789123456789` -> `123,456,789.12`; `1200` -> `1,200.00`;
`0.75` -> `0.75`; `0.0042` -> `0.0042`; `3.5` -> `3.50`; `0` -> `0.00`; `0.0000001` ->
`<0.000001`; `not-a-number` -> `not-a-number`; and that `exactTxAmount` is non-null for the
9-decimal case and null for `0.75`. Add a `sanitizeCoinAsset` case for a traversal-shaped input
(something containing path separators and dots) proving only `a-z0-9` survives, and a
`fiatValue` case proving an unknown symbol returns null rather than 0.
  </action>

`TxRowContent txRowContent(Transaction tx, {required Map<String, double> prices})`:

BADGE — status wins over type, because a pending or failed transaction is first of all pending
or failed: `pending` -> `TransactionBadgeKind.pending`; `failed` or `cancelled` ->
`TransactionBadgeKind.failed`; otherwise map the type — `transfer` (and a NULL `type`) ->
`sent`/`received` by `transactionDirection`, `mint` -> `mint`, `process` -> `job`, `escrow` and
`escrowRelease` -> `escrow`, `purchase` -> `purchase`, `swap` -> `swap`.

TITLE (010-A token-first: the asset is the headline) — for `swap`, the two symbols joined by a
right arrow, e.g. the from-symbol, a space, U+2192, a space, the to-symbol, falling back to
`coinSymbol` when either is null; for everything else, `coinSymbol`.

ACTION (the quiet chip beside the headline) — `transfer`/null: "Sent" or "Received" by
direction; `mint`: "Minted"; `escrow`: "Escrow locked"; `escrowRelease`: "Escrow released";
`process`: "Processing job"; `purchase`: "Purchased"; `swap`: "Swapped". These replace the bare
strings `Completed job` and `Swapped` that today are the entire row for those types.

SUBTITLE — one line of real context, never a repeated relative time:
`transfer` sent -> `WalletUtils.getAddressForDisplay(recipients.first.toAddr)`; received ->
the same on `fromAddress`; `mint` -> "Minted to wallet"; `escrow` -> "Locked in escrow";
`escrowRelease` -> "Released from escrow"; `process` -> "Job " plus
`WalletUtils.getAddressForDisplay(hash)`; `purchase` -> "Card purchase"; `swap` ->
the from-amount and from-symbol composed through `formatTxAmount`.
Then, and ONLY when `transactionStatus != TransactionStatus.completed`, append a middot
separator and the capitalised status name. That single append is the entire implementation of
"status rendered only when it is not the happy path" — a completed row must produce a subtitle
with no status token in it at all.
Guard `recipients` for emptiness everywhere; it is a list from an untrusted source and
`recipients.first` throws on empty, which today's code does unguarded.

AMOUNT + TONE + VALUE LINE — in this precedence:
  1. `failed` or `cancelled` status -> amount is an em dash (U+2014), tone `none`, valueLine
     "Not charged". This kills the doubled `$0.00` sketch 010 named.
  2. type `process` -> amount is an em dash, tone `none`, valueLine = the fee amount through
     `formatTxAmount(tx.fees)` plus the coin symbol plus " spent". A processing job has no
     transfer amount by nature; the dash is deliberate, not missing data.
  3. type `swap` -> a plus sign, a space, `formatTxAmount(toAmount ?? '0')`, a space, the
     to-symbol; tone `incoming`; valueLine = fiat of the TO side.
  4. everything else -> sign is a plus for `received`/`mint`/`escrowRelease`/`purchase` and a
     U+2212 minus for `sent`/`escrow`, then `formatTxAmount(recipients.first.amount)` and
     `coinSymbol`; tone `incoming`/`outgoing` to match; valueLine = fiat of `coinSymbol`.
  Use U+2212 (real minus) rather than a hyphen so the amount column aligns under tabular
  figures. `exactAmount` = `exactTxAmount` of whichever raw string fed the amount, null for the
  dash cases.
  In cases 3 and 4 the valueLine is `formatFiat(...)` when `fiatValue` returns non-null and
  NULL otherwise — an unpriced coin drops the line rather than printing a zero.

ICON SYMBOLS — `[fromSymbol, toSymbol]` (non-null, sanitised) for `swap` so the identity can
show BOTH tokens as the ROADMAP requires; otherwise a single-element list with `coinSymbol`.
Run every element through `sanitizeCoinAsset` here so the widget never touches a raw symbol.

TIME — `txTimeLabel(tx.timeStamp)` from Task 3.

Notably ABSENT from `TxRowContent`: the fee. `Fee:` is deliberately not part of the resting row
any more — it repeated on all eight rows and was never the reason the panel is opened. It moves

<task type="auto">
  <name>Task 3: Day grouping and the per-row timestamp</name>
  <files>lib/dashboard/home/widgets/transaction_utils.dart, test/dashboard/transaction_utils_test.dart</files>
  <action>
Replace the information-free repetition sketch 010 measured (eight rows all reading `a day ago`)
with a real hierarchy: a day separator carrying the date once, and a real clock time per row.

`String txTimeLabel(DateTime ts)` -> `DateFormat.Hm().format(ts.toLocal())`, i.e. `18:42`.
24-hour is deliberate: it is fixed-width under tabular figures, where a locale `h:mm a` string
varies in width and the amount/time columns are the tightest part of the narrow panel. Record
that as a comment so it is not "localised" into a regression later.

`String txDayLabel(DateTime day, DateTime now)` -> "Today" when the two share a calendar day in
local time, "Yesterday" for the previous calendar day, `DateFormat('d MMM')` (e.g. `18 Jul`) for
any other day in the same year, and `DateFormat('d MMM y')` when the year differs. Compare
calendar days, not `Duration` deltas — a 23-hour delta can straddle midnight and a 25-hour one
can not.

`class TxDay { final DateTime day; final String label; final List<Transaction> items; }` and
`List<TxDay> groupTransactionsByDay(List<Transaction> txs, {DateTime? now})`:
sort a COPY descending by `timeStamp` (never sort the caller's list in place — it is a bloc/
stream-owned list), bucket by local calendar day, emit buckets newest-first with items
newest-first inside each. `now` defaults to `DateTime.now()` and exists so the test is not
time-of-day dependent.

Test additions: a group that builds transactions across three calendar days with an injected
`now`, asserting the labels come out "Today", "Yesterday" and a `d MMM` date; that ordering is
newest-first at both levels; that an empty input yields an empty list; that the input list is
not mutated; and a `txTimeLabel` case asserting the 24-hour shape. Add one case where two
transactions are 23 hours apart but on different calendar days, proving the day comparison is
calendar-based and not a duration.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RPC / chain / Banxa -> `Transaction` fields | `coinSymbol`, `recipients[].amount`, `fees`, addresses and `hash` are all attacker-influenceable strings |
| Hive `marketDataBox` -> fiat line | A cached price is data written by an earlier network response |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Tampering | `sanitizeCoinAsset` -> `assets/images/crypto/<symbol>.png` | medium | mitigate | Today the symbol is interpolated raw into an asset path. Restrict to `a-z0-9`, cap at 12 chars, empty result falls back to the neutral dot; unit-tested with a traversal-shaped input |
| T-12-02 | Denial of service | `formatTxAmount` | high | mitigate | An unbounded / NaN / infinite amount string driving text layout in a height-starved panel is the shape of the freeze fixed in `37639d5`. Early return on unparseable, hard 2-dp clamp above 1000, hard 6-dp cap below; unit-tested |
| T-12-04 | Repudiation | status append in `txRowContent` | high | mitigate | If the non-happy-path branch regresses, a failed spend renders as a successful one. The per-status test asserting a pending/failed subtitle carries the status and a completed one does not is the enforcement |
| T-12-09 | Spoofing | fiat line from cached prices | low | accept | A sender can pick any `coinSymbol`; an unknown symbol yields NO fiat line rather than a fabricated `$0.00`, so the failure mode is absence, not a wrong number |
