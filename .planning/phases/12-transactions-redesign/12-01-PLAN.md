<objective>
Build the badge foundation the whole phase paints with: one glyph/colour table covering all
seven `TransactionType` values plus the two non-happy-path statuses, and one 18px badge widget
that renders it.

Purpose: sketch 010's diagnosis is that the panel reads as several different apps because three
transaction types have no shared identity at all. The badge is that identity. It also has to be
one table, not scattered ternaries, because 12-03 (the row) and 12-04 (the filter chips) must
show the SAME glyph for the same concept or the filter stops looking like it filters the list.

Output: `transaction_badge.dart` (kind enum + spec table + widget), one new colour token, one
SVG asset, and a test that proves the AA claim rather than asserting it in a comment.

Requirement covered: TX-02 (badge system).

<task type="auto">
  <name>Task 2: Create the badge spec table and TransactionBadge widget</name>
  <files>lib/dashboard/home/widgets/transaction_badge.dart</files>
  <action>
Create ONE new file holding the phase's single source of truth for badge identity. Keep it
small and declarative — this is a lookup table plus a painter, not a framework.

Public API:

1. `enum TransactionBadgeKind { sent, received, mint, job, escrow, swap, purchase, pending, failed }`.

2. An immutable `TransactionBadgeSpec` value holding: `Color fill`, `IconData? icon`,
   `String? svgAsset`, `String label`. Exactly one of `icon`/`svgAsset` is set — assert that in
   the constructor.

3. `TransactionBadgeSpec badgeSpec(TransactionBadgeKind kind, GWColors gw)` returning, per kind
   (fill / glyph / label), sourced from the ROADMAP Phase 12 table and sketch 014's live rows:
   - `sent` — `GeniusWalletColors.statusNeutral`, `Icons.north_east`, "Sent"
   - `received` — `gw.statusSuccess`, `Icons.south_west`, "Received"
   - `mint` — `GeniusWalletColors.brandTertiary`, `assets/images/pickaxe.svg`, "Mint"
   - `job` — `GeniusWalletColors.brandPrimaryStrong`, `Icons.dns`, "Job"
   - `escrow` — `GeniusWalletColors.statusNeutral`, `Icons.lock`, "Escrow"
   - `swap` — `GeniusWalletColors.statusNeutral`, `Icons.swap_horiz`, "Swapped"
   - `purchase` — `gw.statusSuccess`, `Icons.credit_card`, "Purchased"
   - `pending` — `GeniusWalletColors.statusWarning`, `Icons.schedule`, "Pending"
   - `failed` — `gw.statusError`, `Icons.close`, "Failed"
   `received`/`purchase`/`failed` take their fill from the appearance-aware `gw` extension, the
   rest from the mode-invariant statics. `swap` and `purchase` are not in the ROADMAP's badge
   table because it only enumerates the seven locked ones — their fills/glyphs come from
   sketch 014's live TX rows (swap = Slate + the swap arrows, purchase = success + card) and
   should carry a short comment saying so.
   Two glyph decisions are already made and must not be re-litigated: the pickaxe is on MINT and
   the server is on JOB (sketch 012 recommended the opposite and Jakub overrode it). `Icons.dns`
   is the Material server-rack glyph and matches the sketch's two-stacked-rects drawing, so no
   FontAwesome import is needed.

4. `Color badgeGlyphColor(Color fill)` — returns whichever of `Colors.white` or
   `GeniusWalletColors.textOnBrand` has the HIGHER `contrastRatio` against `fill`, computed with
   `Color.computeLuminance()`. Do not hand-maintain a per-kind glyph colour. This is the whole
   reason the badge stays AA-correct when `gw.statusSuccess` flips from `#0AD89C` (dark, where
   ink wins at ~10.6:1) to `#07875F` (light, where white wins at ~4.5:1) — a fixed table would
   silently fail one appearance. Note in a comment that sketch 011's finding is that the badge is
   a filled circle with a knocked-out glyph, so glyph-vs-FILL is the ratio that gates AA, not
   fill-vs-surface, and that a hardcoded white glyph on `statusError` is exactly the regression
   quick task `260720-k81` shipped and 05-VERIFICATION recorded as Gap 1.

5. `Widget badgeGlyph(TransactionBadgeSpec spec, {required Color color, double size = 11})` —
   returns `Icon(spec.icon, size: size, color: color)` when `spec.icon != null`, else
   `SvgPicture.asset(spec.svgAsset!, width: size, height: size, colorFilter:
   ColorFilter.mode(color, BlendMode.srcIn))`. This exists because 12-04's filter chips must
   paint the SAME glyph as the row badge (a Mint chip showing a different mark from the Mint
   badge breaks the link between the filter and the list), and one of the nine glyphs is an SVG
   rather than an `IconData`, so callers cannot just read `spec.icon`. `TransactionBadge` below
   is its first consumer.

6. `class TransactionBadge extends StatelessWidget` taking `{required TransactionBadgeKind kind,
   Color? ringColor}`. Renders an 18px circle: `Container(width: 18, height: 18)` with
   `BoxDecoration(color: spec.fill, shape: BoxShape.circle, border: Border.all(color: ringColor
   ?? gw.surfaceElevated, width: 2))`, child = `badgeGlyph(spec, color: badgeGlyphColor(spec.fill),
   size: 11)`. Wrap in `Semantics(label: spec.label)`. Read `gw` fail-soft
   (`Theme.of(context).extension<GWColors>() ?? GWColors.dark()`).
   The ring colour defaults to the panel surface so the badge reads as a hole punched through
   the coin art — it is deliberately NOT white; a white ring is the k81/Gap-1 regression.
   Sizes are fixed literals on purpose: no dimension in this widget may be derived from
   `constraints` (see the freeze note in `<risk>`).

No separate semantic-label function is needed — use `badgeSpec(...).label`.

Imports: `flutter/material.dart`, `flutter_svg/flutter_svg.dart`,
`genius_wallet/theme/genius_wallet_colors.dart`, `genius_wallet/theme/gw_colors.dart`.
Keep the file under ~140 lines. No abstraction beyond what is listed here.
