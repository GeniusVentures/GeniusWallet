# Phase 44.1: Bridge burn per chain ABI - Context

**Gathered:** 2026-10-28 by the planner, no discuss session. (B) = settled by Braian; (D) = planner decision, not yet reviewed.
**Status:** Ready for planning

<domain>
## Phase Boundary

The GNUS burn (`GeniusApi.bridgeOut` and `getBrigeOutGasCost` -> `Web3.createBridgeOutTransaction`) picks the
`bridgeOut` form each chain's diamond has deployed, sends the 5-argument form with the SDK account as
destination, and refuses before signing where neither form exists. Callers: `JobSubmission` (compute panel and
gnus handler) and the token bridge screen. Evidence: `.planning/research/v4.0-bridge-abi.md`.

</domain>

<decisions>
## Implementation Decisions

- **D-01 (B):** The fix lives in the shared burn, so the job submit, the gnus handler and the token bridge screen all get it. No caller picks a form.
- **D-02 (D):** One owner: new `packages/genius_api/lib/web3/bridge_out_abi.dart` holds both ABIs and selectors, the loupe lookup and its cache, the destination derivation and the call builder. `Web3.bridgeOutAbi` moves there; the 3-arg ABI JSON is unchanged.
- **D-03 (D, confirms Braian's recommendation):** The form comes from the diamond loupe `facetAddress(bytes4)` (selector `0xcdffacc6`) on the GNUS token contract: non-zero for `0xa5a5aa20` -> 5-arg (preferred when both exist), else non-zero for `0xe26d65a6` -> 3-arg, else none. Cached per `chainId|lowercased contract` for the app session. Only a definitive answer is cached; an RPC failure or timeout (`rpcReadTimeout`) is an error, not cached and not "unavailable". Re-checked 2026-10-28 over publicnode: Sepolia 5-arg only (facet `0xef01a64d...6bcb`), Amoy 3-arg only, Base Sepolia neither. `ponytail:` no invalidation; a mid-session diamond upgrade needs a restart, and a removed facet makes the gas estimate revert before signing.
- **D-04 (D, confirms):** Neither form -> refused before the private key is read or anything is signed, with one exported message constant.
- **D-05 (D, confirms):** `sgnsDestination` = X, the first 32 bytes of the SDK account (`0x` + 128 hex, X||Y, validated by `sdkAddressOrNull`); `destinationYOdd` = the low bit of Y's last byte. On a 5-arg chain a null, malformed or all-zero-X account is refused; a zero destination is never sent. A 3-arg chain does not need the account.
- **D-06 (D):** The destination is passed by value. `GeniusApi.bridgeOut` gains `String? sgnsAccount`; `JobSubmission` passes `expectedNode` (the node account the gnus handler confirmed), so a switch between confirm and burn cannot credit another account. Null (compute panel, token bridge screen) -> `getSelectedAccountAddress()` read inside `bridgeOut`. The gas estimate reads the selected account itself (it only sizes gas). Every test fake that overrides `bridgeOut` gains the parameter (Dart's override rule).
- **D-07 (D):** gnus handler: a chain with neither form is `-32013` with `data.reason: "bridge_unavailable"`, thrown where the pre-confirm gas estimate fails, so no confirm shows and nothing burns. Carried as `GasEstimateFailed.bridgeUnavailable`; every other estimate failure stays `-32010`. The contract text gets the exception.
- **D-08 (B):** Sign -> save hash -> broadcast order and the unconfirmed-send handling are unchanged: `broadcastSigned` is not touched.
- **D-09 (D):** User copy has no "node" or "SDK" (Earn terminology). Unavailable: "GNUS bridging is not available on this network." No account: "Your Genius account is not ready. Try again in a moment." Lookup failed: "Could not check this network's bridge. Try again." Wording is Claude's discretion within that rule.
- **D-10 (D):** The Sepolia check is a kept, opt-in network test (skipped unless `GW_SEPOLIA_CHECK=1`). Probe 2026-10-28 from `0x...dEaD`: 5-arg with amount 0 -> `0x` (accepted); amount 1 GNUS -> "Insufficient tokens." for zero and non-zero destination alike (the balance check runs first, so the destination slot is only proven from a holder, `GW_SEPOLIA_FROM`); 3-arg -> "Diamond: Function does not exist".
- **D-11 (D):** A real 5-arg burn is a human step on the token bridge screen (the job submit cannot burn live until SDK-CA). Its receipt and relayer pickup are recorded, or the gap is stated.
- **D-12 (D):** Where the user sees the refusal. The compute panel already shows a failed estimate's reason verbatim, so it needs nothing. The token bridge screen today turns any failed estimate into a disabled "Couldn't estimate gas" button, which would hide the reason; it gets a `BridgeCtaState.bridgeUnavailable` rung (error tone, label "Not available on this network") chosen when the estimate's error is the unavailable constant.

### Claude's Discretion

</decisions>
