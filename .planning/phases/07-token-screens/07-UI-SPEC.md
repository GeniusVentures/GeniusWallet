# Phase 7 — UI Design Contract

> Visual and interaction contract for the token-detail re-skin. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **RE-SKIN ONLY.** This phase does NOT contract new features. It LOCKS how the already-shipped
> redesign tokens (`GWColors` extension, `gw_*` primitives, `ResponsiveDrawer`, `ActionButton`) apply
> to the existing `token_info_screen.dart` surface and its two drawers. No new visual language is
> invented here. Scope is fenced by `07-CONTEXT.md` (authoritative): Send/Swap stay inert, address
> book and a real send flow are OUT, the chart re-skin is inherited from Phase 5, and the ONLY chart
> work is finding-24's lifecycle guard.

## Spacing Scale

The established `GeniusWalletConsts.space*` token set (already on develop). All raw pixel literals on
this surface migrate to these tokens — no new values are introduced.

| Token | Value | Usage on this surface |
|-------|-------|-----------------------|
| space2 | 4px | (available) tightest inline gaps |
| space3 | 6px | (available) half-step |
| space4 | 8px | Action-row button gap (`spacing: 8` → `space4`); info-tile inner padding |
| space6 | 12px | (available) half-step |
| space8 | 16px | Action-section column gap (`spacing: 16` → `space8`); Convert/Info card padding |
| space10 | 20px | Page scroll padding + desktop Row/Column gap (`EdgeInsets.all(20)` / `spacing: 20` → `space10`) |
| space12 | 24px | Section breaks |
| space16 | 32px | QR-drawer vertical rhythm (`SizedBox(height: 32)` → `space16`) |
| space24 | 48px | Major breaks |
| space32 | 64px | Page-level spacing |

**Exceptions:** the scale intentionally carries half-steps (space3=6, space6=12, space10=20) beyond a
strict 8-point grid — this is the shipped design-system vocabulary, not a Phase 7 invention. Do NOT
add off-scale literals; replace the file's remaining raw values (`20.0`, `8.0`, `16`, `32`) with the
nearest token above.

**Radius:** `GeniusWalletConsts.borderRadiusCard` = `radiusLg` (15px) for cards and `ActionButton`;
`borderRadiusButton` = `radiusPill` (48px) for pill buttons. Keep the existing `ActionButton` radius
(`borderRadiusCard`).

## Typography

Roles map to the shipped `Theme.of(context).textTheme` (Inter). Do NOT hardcode `TextStyle` sizes on
this surface except the existing `ActionButton` label (13/w500), which is a component-internal style
already in the design system. Color always comes from the style/theme (appearance-aware), never a
literal.

| Role | textTheme token | Size | Weight | Line Height | Usage |
|------|-----------------|------|--------|-------------|-------|
| Action label | (component) | 13px | w500 | 1.2 | The 4 action buttons' captions (Receive/Send/Swap/More) |
| Body | `bodyLarge` | 16px | w400 | 1.5 | Convert "Total" readout, info-tile values |
| Label / title | `titleMedium` | ~16–18px | w600 | 1.3 | "Info" / "Convert" section titles, info-tile trailing values, network/address |
| Heading | `headlineSmall` | ~24px | w600 | 1.2 | Receive-drawer "Your {network} Address" |

Weights used: **regular (w400)** + **semibold (w600)**, with the component-level **medium (w500)** on
the action-button captions only. No other weights.

## Color

60/30/10 discipline, all via the appearance-aware `GWColors` extension (dark / light shown):

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` — `#0B0D12` / `#DCE0E6` | Page/scaffold background |
| Secondary (30%) | `surfaceElevated` — `#0C0E14` / `#FFFFFF` | Info card, Convert card, both drawers (via `GWCard`/`GWDecorations.surface`) |
| Accent (10%) | `brandPrimaryOnSurface` — `#0AAEE6` / `#0A6885` | Action-button icon glyphs; info-tile leading icons; copy/link affordances. (Raw `brandPrimary #14C8FF` only on filled/gradient chrome that already meets contrast — never as on-surface text/icon.) |
| Destructive | `statusError` — `#FF4D4D` / `#D92D2D` | Not used this phase — no destructive action exists on this surface |
| Secondary text | `textSecondary` — `#8A8F9D` / `#5A606E` | Action-button captions, info-tile labels, subtitles |
| Always-light chip | raw `Colors.white` | Receive-QR background (both modes) and the token-logo `CircleAvatar` backing only (§4.4 exception — logos/QR need a fixed light backing regardless of appearance) |

**Accent reserved for:** action-button icon glyphs, info-tile leading icons, and copy/link
affordances. NOT for every interactive element, NOT for button fills, NOT for the disabled state.

**Rainbow-icon cleanup (re-skin):** `_MarketDataInfo` currently paints its leading icons with raw
Material `Colors.amber[300]` / `Colors.lightBlue[300]` / `Colors.orange[300]` / `Colors.red[300]` and
uses `cs.primary` / `cs.surface` / `cs.onSurfaceVariant`. Re-skin these to a single restrained,
appearance-aware treatment (`brandPrimaryOnSurface` for glyphs on `surfaceElevated`, `textSecondary`
for labels) — the multi-hue set violates the 10% accent discipline and is not WCAG-verified in light
mode. This is a skin change, not a restructure.

## Copywriting Contract

This surface is display + two functional affordances (Receive, More→Bridge). There is no submit form,
no empty/error state to author, and no destructive action. Copy is preserved from develop; only the
disabled-affordance line is a decision.

| Element | Copy |
|---------|------|
| Primary CTA | **"Receive"** (the one functional primary action; opens the Receive drawer) |
| Secondary actions (inert) | **"Send"**, **"Swap"** — rendered, disabled, do nothing this phase (D-01; Swap → Phase 8, Send → its own future phase) |
| Gated action | **"More"** — enabled only on a connected GNUS bridge token; disabled otherwise (finding 37) |
| Receive-drawer title | "Receive {token name}" (preserved) |
| Receive-drawer body | "Your {network} Address" / "Use this address to receive tokens." (preserved) |
| More-drawer | title "More Options"; row label "Bridge Tokens" (preserved) |
| Missing market value | "N/A" (preserved); missing token name → "Unknown Token" (preserved) |
| Empty state heading | none — this surface always has a token context; no empty state authored |
| Empty state body | none |
| Error state | none authored here — the chart owns its own error branch (Phase 5, inherited); finding-24 is a lifecycle guard, not a new error surface |
| Destructive confirmation | none — no destructive action on this surface |

**Disabled-affordance decision (planner's call per CONTEXT):** whether the disabled "More"/"Send"/"Swap"
buttons get a tooltip (e.g. "Not available for this token") is left to the planner. The contract
requires only that the disabled state be **visually distinct AND WCAG-legible** (below).

## Interaction & Behavior Contract

Behavior is develop's; these are the hard interaction locks for the re-skin (not new features).

1. **Finding 37 — "More" disabled on non-GNUS tokens (LOCK, don't regress).** `onPressed` stays
   `isGnusBridgeEnabled ? (...) : null` (already correct at `token_info_screen.dart:179`). Tapping
   "More" on a non-GNUS token must do NOTHING (disabled button), never open an empty drawer. The
   re-skin must not reintroduce the always-enabled + `if (isGnusBridgeEnabled)` empty-child pattern
   the finding flagged. Verify preserved after re-skin.
2. **Finding 24 — chart lifecycle guard (the ONLY chart work).** Wrap the post-`await` `setState` in
   `_fetchHistoricalData`'s success path (`crypto_live_chart.dart:~71`) and in the timer-driven
   `_addNewPricePoint` (`:~103`) with `if (!mounted) return;` / `if (mounted)`. Leaving the token
   screen mid-fetch or while the refresh timer fires must throw no `setState after dispose`. This is
   a lifecycle fix, not a visual change.
3. **Receive QR light-background (HARD CONTRACT, finding 16/6).** `CryptoAddressQR`'s `backgroundColor`
   must resolve to a **solid light surface in both appearance modes** (raw `Colors.white`; upgrade the
   current `Colors.white.withValues(alpha: 0.8)` to opaque, or keep ≥0.9 so it stays light over a dark
   drawer). QR modules render default black. NEVER bind the QR background to an appearance-aware token
   (`textPrimary*`, `surface*`) — that is exactly the regression finding 16 documents. Must scan with
   a real phone camera in dark mode.
4. **Send & Swap stay inert (D-01).** Both render (re-skinned) but perform no action this phase. They
   present as disabled `ActionButton`s (no `onPressed`); do NOT wire a send flow or a swap. No
   enabled-looking button may be dead — inert == disabled treatment.
5. **Drawers stay drawers (D-03).** Receive and More remain `ResponsiveDrawer` (bottom sheet ≤768px,
   desktop side dialog ≥768px — note finding-26's 768 threshold, not 800). No promotion to routes.
6. **Disabled-state visibility (WCAG).** Every disabled control on this surface (Send, Swap, gated
   More) must be visibly distinct from its enabled state AND remain legible in both light and dark
   (per the project WCAG contrast rule; ties to the shipped disabled-state-visibility todo). Do not
   let a disabled button read as an enabled one, and do not let it vanish.
