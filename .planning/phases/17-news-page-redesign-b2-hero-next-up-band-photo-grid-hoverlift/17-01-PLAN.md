  <name>Task 1: The B2 magazine screen — hero + "Next up" band + photo grid</name>
  <files>lib/dashboard/news/view/crypto_news_screen.dart</files>
  <action>
Full rewrite of `CryptoNewsScreen` to the B2 layout. What shipped:

  - **Page frame.** `Align(topCenter)` over a `ConstrainedBox(maxWidth: GeniusBreakpoints.xxl)`,
    `GWPageHeader(title: 'Crypto News')` with a trailing `_UpdatedStamp`, then a `GWSearchField`, then
    an `Expanded` `FutureStateWidget<List<NewsArticle>>`. Left padding (sides 12, top space32) puts the
    'Crypto News' title at the SAME X as Transactions and Markets.
  - **`_NewsMagazine`.** `hero = items.first`, `nextUp = items.skip(1).take(3)`,
    `rest = items.skip(1 + nextUp.length)`. Wraps a `SingleChildScrollView`
    (`AlwaysScrollableScrollPhysics`, scrollbars off, top `space6` padding so the hero's hoverLift
    isn't clipped by the scroll viewport's hard edge). A `LayoutBuilder` at `_bandBreakpoint = 760`:
    wide → `IntrinsicHeight(Row[ Expanded(flex:3, hero), spacer, Expanded(flex:2, Next up | empty) ])`;
    narrow → `Column[ hero, Next up ]`. Below the band: `_grid(...)`.
  - **`_HeroCard`.** `GWCard(hoverLift: true, onTap: launchWebSite(link))`, photo left / text right when
    wide (`IntrinsicHeight` + `CrossAxisAlignment.stretch`), photo-on-top `16/9` when narrow. Renders
    title + `dek` + `_MetaLine`. The inner `IntrinsicHeight` is load-bearing — it self-bounds the
    stretch Row so a single filtered result returning the bare hero into the page's vertical scroll
    cannot demand height=Infinity (the earlier freeze).
  - **`_NextUp` / `_NextUpRow`.** A `GWSectionTitle('Next up')` over headline-only rows (numbered
    1..3, no photo), each an `InkWell` → `launchWebSite`.
  - **`_NewsGridCard`.** Full-photo card: 168px photo on top, then title + `dek` + `_MetaLine`, in a
    `GridView.builder(SliverGridDelegateWithMaxCrossAxisExtent(maxCrossAxisExtent: 360,
    mainAxisExtent: 312))` — a FIXED tile height, not an aspect ratio, so nothing overflows as the
    photo scales.
  - **Search → "Results".** Hero + "Next up" ALWAYS come from the full feed; the bottom section
    retitles to "Results" while searching and to "More news" while browsing. A search MISS no longer
    blanks the page — the hero band stays frozen and an inline "No headlines match …" line reports the
    miss. Search is debounced 220ms so the shrink-wrapped grid doesn't re-lay-out on every keystroke
    (the old per-key rebuild dropped characters and matched a half-typed query).
  - **Empty / error.** A genuinely empty feed → `GWEmptyState('No news right now', action Refresh')`.
    The fetch collapses network failures to an empty list, so `GWErrorState` is a rare last resort.
  </action>
