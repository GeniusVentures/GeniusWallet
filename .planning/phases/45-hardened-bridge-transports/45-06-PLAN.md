  <name>Task 1: Swift installers in the two existing Runner files</name>
  <files>ios/Runner/AppDelegate.swift, macos/Runner/MainFlutterWindow.swift</files>
  <action>
Per D-05, D-09 and D-16, follow the channel contract from plan 05 exactly: `install {webViewId, origins, shim}` returns a bool, `uninstall {webViewId}`, and native sends `message {webViewId, message, source}`.
- `install`:
  - Look up the view with `WebViewFlutterWKWebViewExternalAPI.webView(forIdentifier:withPluginRegistry:)`. Use the app delegate as the registry on iOS and the `FlutterViewController` on macOS.
  - Add `WKUserScript(source: shim, injectionTime: .atDocumentStart, forMainFrameOnly: true)`.
  - Add a handler named `gnusBridge`. Its class holds the channel weakly.
  - Return false if the view is not found.
- Handler:
  - Drop the message unless `message.frameInfo.isMainFrame` and `message.body` is a String.
  - The source is `securityOrigin.protocol + "://" + securityOrigin.host`, plus `":" + port` when port is not 0. The Dart `GnusOrigin` parser canonicalises it; the Swift side does no other normalisation.
- `uninstall` calls `removeScriptMessageHandler(forName: "gnusBridge")`. `WKUserContentController` retains handlers.
- Add no new Swift file, because a new file would need an Xcode project edit. The two copies are accepted (Rule of Three). No logging of bodies.
  </action>

  <done>Both files have the main-frame guard and a main-frame-only user script. Both use the same method names and argument keys as the Kotlin side.</done>
