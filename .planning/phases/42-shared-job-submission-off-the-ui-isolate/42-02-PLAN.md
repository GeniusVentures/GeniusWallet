## Known limit (recorded, not verified by this plan)

Research Open Question 1 / Pitfall 1: the SDK holds its global mutex for the whole cost call (which makes a live coin-price request) and the whole process call (which re-prices first). The main isolate still makes synchronous SDK calls: `AppBloc`'s 1 s processing-status tick (`lib/bloc/app_bloc.dart:253-259`, `api.getProcessingStatus()`) and the balance reads. A poll that fires while a worker holds the mutex blocks the UI thread until the job call returns. This plan removes the freeze caused by the call itself running on the UI isolate; it does not remove a shorter hitch from a poll landing inside a call. `flutter test` cannot show either. The claim for criterion 3 is therefore limited to "the cost and process calls no longer run on the UI isolate", and the real feel is checked only by the phase 48 device walk. Pausing the poll while a job call is in flight would be a separate decision for Braian; it is not part of this phase.
