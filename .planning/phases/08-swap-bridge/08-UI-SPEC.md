> Visual and interaction contract for the Swap & bridge re-skin. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>

> It LOCKS how the shipped redesign tokens (`GWColors`, `gw_*` primitives, `ResponsiveDrawer`,
> `GWPageHeader`, `GWButton`) apply to `swap_screen.dart`, `bridge_screen.dart`, `swap_field.dart`,
> `swap_settings_drawer.dart`, and `gw_swap_fab.dart`, and how the already-shipped 031-B status-led

## Spacing Scale

The established `GeniusWalletConsts.space*` set (already on develop). No new values.

| Token | Value | Usage on this surface |
|-------|-------|------------------------|
| space2 | 4px | Flip-button icon inset details |
| space4 | 8px | Field-internal small gaps (amount ↔ token pill) |
| space6 | 12px | Field-internal row gaps (label → amount row → foot row) |
| space8 | 16px | Card internal padding baseline (`a-field` 18/18/20 rounds to space8/space8/space10 — see exception below) |
| space10 | 20px | Card internal padding on the focused (A1) column; page horizontal padding |
| space12 | 24px | Route-details-card ↔ CTA gap; section breaks |
| space16 | 32px | Focused-column vertical padding (`focus-wrap` top) |
| space32 | 64px | Navbar → page-header gap (unified with Transactions/Markets/Swap today — unchanged) |

**Exceptions:** the sketch's literal card padding (`18px 18px 20px` base / `20px 20px 22px` for A1's
`.focus-col`) does not land exactly on the 4pt scale. Round to the nearest token: **space8 (16px)
horizontal, space10 (20px) vertical** for the focused card padding — this is a ≤4px rounding, not a
new value, and keeps the card inside the existing scale rather than adding an off-grid literal.

**Radius:** cards use `radiusLg` (15px, `borderRadiusCard`) — NOT the sketch's `--radius-2xl` (16px);
15px is the shipped card radius used everywhere else (`GWCard` default) and the 1px delta is
imperceptible. The CTA button and route-details card use `radiusMd` (12px). The flip control is a
44px circle-ish rounded square — use `radiusMd` (12px) plus a 4–5px `surfaceElevated`-colored border
to punch the seam hole (mirrors the sketch's `border:5px solid var(--surface-elevated)` — implement as
a `Container` decoration border, not a literal color surface stack).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|

| Body | 14px (`bodySm`) | 400 | 20/14 (1.43) | USD value under the amount, subtitle under "Swap"/"Bridge" |

Implement as `GeniusWalletTypography.numericDisplay.copyWith(fontSize: 38, height: 1.0)` so it inherits tabular-figure features and weight, only overriding size/height. |

Weights used: **regular (400)** + **semibold (600)**, with **medium (500)** on labels only (matches

do not hardcode a button text style (the current code's raw `TextStyle(color: deepBlueTertiary,
fontWeight: w500)` is exactly the anti-pattern this phase removes).

## Color

60/30/10 discipline, all via the appearance-aware `GWColors` extension (dark / light):

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` — `#0B0D12` / `#DCE0E6` | Page/scaffold background |
| Secondary (30%) | `surfaceElevated` — `#0C0E14` / `#FFFFFF` | You-Pay/You-Receive cards, route-details card, settings drawer, token picker |
| Accent (10%) | brand CTA gradient `#0AD89C → #0AAEE6` (`GeniusWalletGradient.brandCta`) | The Swap/Bridge/Retry/Review CTA fill, the flip-control fill, MAX button text+fill (`brandFill` wash + `brandPrimaryOnSurface`/`brandSecondary`) |
| Destructive | `statusError` — `#FF4D4D` / `#D92D2D` | Insufficient-balance CTA state, route-fetch-error notice (D-09) |
| Secondary text | `textSecondary` — `#8A8F9D` / `#5A606E` | Field labels, balance line, route-detail keys, tune/back icon buttons (idle) |
| Success (route detail) | `statusSuccess` — `#0AD89C` / `#07875F` | Price-impact "good" value in the route-details card |

**Accent reserved for:** the primary CTA fill, the flip-control circle, and the MAX button — NOT for
field borders, NOT for the token-selector pill (stays `surfaceMenu`/`borderSubtle`, matching every
other pill in the app), NOT for disabled states.

**CTA state → color mapping (locks the sketch's state ladder onto real tokens):**

| State | Background | Text | Enabled? |
|-------|-----------|------|----------|
| Enter an amount | `surfaceMenu` | `textPrimary38` | disabled |
| Insufficient balance | `statusError` @ ~12–14% alpha fill (`statusErrorFill` if it exists, else `statusError.withValues(alpha:0.12)`) | `statusError` | disabled |
| Finding best route… | `surfaceMenu` | `textSecondary` | disabled (this is the CTA text; the "You Receive" field is what shows the spinner/stale-clear per D-09, not the button) |
| Swap / Review bridge (ready) | `GeniusWalletGradient.brandCta` | `textOnBrand` (`#000B18`) | enabled |
| Submitting | `surfaceMenu` (same as loading) + inline spinner glyph before the label | `textSecondary` | disabled |
| Route error (D-09) | `GeniusWalletGradient.brandCta` (button reads "Retry", stays interactive — it is not itself in error, the field above it is) | `textOnBrand` | enabled |

Route-error notice banner (D-09, finding 22): background `statusError` @ ~12% alpha, icon + text in
`statusError`, `radiusMd` container, `space6`/`space8` padding — matches the shipped `.note.err`
pattern in sketch 120 and should reuse whatever inline-notice pattern the app already has (check for
an existing `GWInlineNotice`/banner primitive before hand-rolling a new `Container`; if none exists,
this is additive-only, not a restructure).

**WCAG note (D-15, hard project rule):** every pairing above must hold AA in both modes and in the
disabled state. `textPrimary38` (38% alpha) on `surfaceMenu` for the disabled CTA label is the
existing shipped disabled-treatment used elsewhere (Phase 7's `ActionButton`) — reuse it rather than
inventing a new disabled tone. Verify the "Insufficient balance" text-on-fill pairing and the route
"Price impact good" green-on-elevated pairing in BOTH themes during the phase walk; do not assume the
sketch's numbers transfer 1:1 (light-mode `statusSuccess`/`statusError` are deliberately DARKENED
relative to their dark-mode/sketch values — see `lib/theme/gw_colors.dart`'s light overrides — use the
`GWColors` getters, never the sketch's literal hex).

## Screen Contracts

### Swap tab — sketch 105 A1 (LOCKED, D-07)

- Centred column, **max-width 560px** (up from today's 500px).
- Soft brand-sheen wash behind the column: two overlapping low-alpha radial glows (~`rgba(10,174,230,.10)` and `rgba(10,216,156,.08)` in dark; scale down for light-mode legibility — verify during the walk that the wash never competes with card contrast) — implement as a `Positioned`/`DecoratedBox` behind the column, `z-index` below the cards, `pointerEvents: none` equivalent (`IgnorePointer`).
- `GWPageHeader(title: "Swap", trailing: <tune IconButton>)` **extended with an optional `subtitle`
  parameter** (default `null` — additive, does not change Transactions/Markets/News, which pass no
  subtitle and render identically to today). Swap passes `subtitle: "Trade any token across chains"`.
- Two `SwapField` cards (You Pay / You Receive), the flip control in the seam between them (not offset
  above), route-details card, CTA — in that vertical order, matching today's structure.
- CTA state ladder per the Color section above.

### Bridge screen — sketch 120 B1 · Swap-twin (LOCKED, D-10)

- Same 560px-equivalent centred column as Swap (bridge has no cross-chain token picker, so it can stay
  narrower if the two-card layout reads tighter — not a hard pixel lock like Swap's 560px, since this
  wasn't Round-2-refined the way Swap was; use judgement, default to matching Swap's column width for
  visual consistency).
- **Header:** back-arrow + "Bridge" title. Reuse the **already-shipped Phase 7 back-arrow AppBar
  convention** (`token_info_screen.dart:96-124`: 48px `toolbarHeight`, `surfaceSunken` background, 0
  elevation, `automaticallyImplyLeading: false`, custom 30×30 chevron `InkWell` + left-aligned title,
  content-width-aligned padding) rather than inventing sketch 120's separate 34×34 `pagehead .back`
  button style — one back-arrow pattern for the whole app, not two.
- Network route bar directly under the header: source-chain chip · arrow · "Bridge" pill (centered on
  the arrow) · destination-chain chip. Destination chip is tappable (opens a network picker sheet,
  mirroring the existing dropdown's data but re-skinned as a `ResponsiveDrawer`/bottom-sheet list, not
  a `DropdownButton`).
- Two cards: "You Pay" (GNUS, fixed — bridge is GNUS-only per D-12/`isGnusBridgeEnabled`) / "You
  Receive on {destination network}" — flip control is **decorative-only or omitted** (bridge direction
  is fixed: source→destination is chosen via the network picker, not a flip; do not port the flip
  control's *function*, only reuse its visual seam treatment if a divider is wanted).
- Route/gas card: "You receive", "Estimated gas cost", "Est. time" rows — **gas only, no rate, no
  slippage row** (D-11 — bridge is 1:1).
- CTA ladder matches Swap's, GNUS-denominated copy.
- Disabled-at-zero-balance and `isGnusBridgeEnabled`-gated entry (D-12) are preserved exactly — this
  screen is still reached only from GNUS token → More → Bridge Tokens, pushed as `/bridge`, not
  promoted to a nav tab.

### Swap non-happy states (sketch 120 "Swap · states")

Three additional CTA/field states beyond the base ladder, all on the **same** `swap_screen.dart` —
not separate screens:

1. **Submitting** — CTA disabled, `surfaceMenu` fill, inline spinner + "Submitting swap…"; fields
   stay populated and read-only during this window.
2. **Route error (finding 22, D-09, HARD CONTRACT)** — on `_fetchRoute`'s catch: the "You Receive"
   field MUST show `—` (not the last-known amount), in `textPrimary38`; the route-details card is
   hidden (`display:none` equivalent); a red inline notice appears (copy above); CTA becomes enabled
   "Retry", not disabled. **The current code's silent snackbar-only catch (`swap_screen.dart:165-172`)
   does not satisfy this — the field-level `—` + notice is required, the snackbar may stay as a
   supplementary toast but is not sufficient alone.**
3. **Insufficient** — CTA disabled, `statusError` fill/text, "Insufficient {symbol} balance"; the
   receive field and route card still show the (unaffordable) quote so the user sees why.

### Result receipt (sketch 120 "Result · receipt", reusing 031-B)

The sketch illustrates a fuller "pill + sections + status badge" receipt than what actually shipped in
Phase 12's `showTransactionDetails` (identity icon + centered amount + one flat rows card, Status
shown as a colored text row, not a badge/pill). **The shipped implementation is the canonical target
for D-03/D-04 — do not build toward the sketch's fuller treatment; that would be redesigning the
receipt, which D-03 explicitly forbids.** Both swap and bridge results route through the same function
call. The sketch's Pending/Failed illustrative copy ("Your swap is confirming on-chain…") is
**aspirational and NOT authorized copy** — D-02 requires the swap TODO stay unwired, so a swap
transaction is always recorded `TransactionStatus.completed` immediately; there is no real pending/
failed swap state to author copy for in this phase. Bridge, however, DOES have a real
success/error branch from `bridgeOut(...)`'s response (`bridgeTokensResponse.isSuccess`) — map that
directly to the receipt's existing Completed/Failed status handling, no new states invented.

## Interaction & Behavior Contract

Behavior is develop's (mechanics untouched); these are the hard interaction locks for the re-skin.

1. **D-01/D-02 — the swap deliberately does not execute (LOCK, don't "fix").** `swap_screen.dart:340`
   stays `// TODO: invoke Squid API`. The button still records a `Transaction` and shows a
   toast+receipt as if a swap happened. The re-skin must not add any word, icon, or animation implying
   on-chain settlement (no "Confirming on Ethereum…", no block-explorer-style progress). This is a
   re-skin of existing copy, not new copy.
2. **D-09/finding 22 — route error never leaves a stale quote (HARD CONTRACT).** See Screen Contracts
   above. This is the one net-new interaction state this phase must add (the current code has no
   equivalent branch).
3. **D-11 — bridge mechanics untouched.** 1:1, gas-only, `getBrigeOutGasCost` on the existing 300ms
   debounce, `bridgeOut(..., shouldMintTokens: true)` on submit. The re-skin changes only the widget
   tree, never the API calls or their parameters.
4. **D-12 — bridge stays a back-arrow sub-screen.** No tab, no swap/bridge toggle control anywhere.
   Entry point (GNUS token → More → Bridge Tokens, gated by `isGnusBridgeEnabled` and non-zero balance)
   is unchanged.
5. **D-13 — Swap Settings drawer must not clash visually against the redesigned Swap tab.** Re-skin
   its `TextField` and CTA button (see Component Inventory) so it reads as the same design language
   the tune icon opens it from.
6. **D-14 — the global swap FAB must not read as pre-redesign chrome.** Already satisfied by the
   shipped `gw_swap_fab.dart` (see Component Inventory); confirm during the walk, don't re-paint.
7. **D-04/D-06 — one receipt, no orphans.** Both `SwapSuccessDrawer.show(...)` (swap) and the inline
   `AlertDialog` (bridge, `bridge_screen.dart:233-514`) are replaced by
   `showTransactionDetails(context, transaction)`. `swap_fail_drawer.dart` has no production caller
   today — delete it, don't leave it as dead weight a future finding rediscovers (the Phase 18 trap
   named in CONTEXT.md). Update `lib/dev/dev_tools_bubble.dart`'s three references to the deleted
   drawers.
8. **D-05 — `lib/reown/swap_result_drawer.dart` is untouched.** No import, no reference, no
   consolidation. Phase 10's territory.
9. **Finding 28 — bridge shows toast AND result receipt, not one or the other.** The existing
   `ToastManager.instance.showToast(...)` call stays; it now fires alongside (not instead of) the
   `showTransactionDetails` call.
10. **WCAG AA in both modes, all states, including disabled (D-15, hard project rule).** Every color
    pairing in this document must be verified live during the phase walk, not assumed from the sketch's
    dark-mode-only numbers. Disabled CTA states must stay visibly distinct from enabled ones — reuse
    the shipped `textPrimary38`-on-`surfaceMenu` disabled treatment rather than inventing a new one.
11. **No Windows/macOS parity split (D-16).** Both screens are ordinary Flutter widgets; nothing here
    needs a platform branch.
