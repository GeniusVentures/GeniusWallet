# Phase 36 — UI Design Contract

> Visual and interaction contract for the child-wallet bindings' read-only list. Generated by
> gsd-ui-researcher (unattended run — no user available; every open call below is made in favour of
> reusing existing tokens/components and the `/network` route's SHAPE, with the reason recorded).
>
> **THIS IS A NEW SCREEN, BUT NOT A NEW VISUAL LANGUAGE.** Every token, row shape, state component
> and menu pattern below already ships on `develop`. This document locks which existing pieces
> compose the new `/child-wallets` route and the new "Child wallets" menu item, and specifies the
> handful of genuinely new elements (the identity banner, the child row, the lag note) in terms of
> those existing pieces. Scope is fenced by `36-CONTEXT.md`: no write operation (register, fund,
> recover, revoke, detach, replace-main) has UI in this phase — Phase 37 owns all of that, including
> any pending-state chrome.

**shadcn initialization gate:** not applicable — Flutter desktop/mobile app. `Tool: none`. Registry

**Why `/network` is cited for ROUTING only, never for VISUALS (resolved, not asked).**
`36-CONTEXT.md`'s "Established Patterns" cites `/network` (`router.dart:198`,
`lib/network/network_page.dart`) as the precedent for "SDK features get top-level routes." That
citation is read narrowly: `NetworkStatusPage` is a **pre-redesign, never-re-skinned** screen — its
body is a bare `Scaffold`/`AppBar`/`ListTile` tree painting `Colors.green`/`Colors.red`/`Colors.blue`
directly (`network_page.dart:117-166`), which is exactly what AGENTS.md's "no `Colors.*` outside
`lib/theme/`" rule forbids for new code. This phase inherits `/network`'s **routing shape** —
a top-level `GoRoute` built with a cubit/api passed in via `BlocProvider.value`/constructor, pushed
with a Material `AppBar`, not a shell tab — and nothing about its body's styling. `SettingsScreen`
(`lib/settings/settings_screen.dart:171`, `GWScreen(appBar: AppBar(title: const Text('Settings')))`)
is the correctly-re-skinned analogue for the CHROME this phase should actually copy, and is cited
below wherever "matches Settings" appears.

## Color

60/30/10 discipline, all via `GWColors`. No new token is added by this phase.

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` (via `GWScreen`'s `GWCanvasBackground`) | Page background (unchanged) |
| Secondary (30%) | `surfaceWell` | The identity banner's recessed-well fill — "a recessed well or track on a card, bar or page" is this token's own documented purpose (`gw_colors.dart:122-124`), and naming which main you are viewing is exactly that: a context track, not a card |
| Secondary, list division | `borderSubtle` | 1px hairline `Divider` between child rows — same "one surface with hairline dividers, no per-row cards" recipe Phase 12 already established for Transactions |
| Accent (10%) | **none used** | This screen has no primary/write action (read-only by CHILD-01/CHILD-02 scope) — there is nothing here for the app's gradient/brand accent to mark. The manual-refresh icon is plain `gw.textSecondary`, never accent, so it does not visually compete with the accent-bearing action buttons Phase 37 adds to this same screen |
| Destructive | `statusError`/`statusErrorText` | Query-failure state only — `GWErrorState`'s own default icon/title colour (component default, unchanged); no destructive ACTION exists this phase |
| Secondary text | `textSecondary` | Row/banner subtitles (mono addresses), balance unit suffix, lag note, empty/error messages |
| Primary text | `textPrimary` | Row/banner titles, balance amount |
| Brand fill (identity only) | `brandPrimaryStrong` | The identity banner's own leading avatar fill (see Component Inventory) — this is the SAME fill `AccountAvatar` already uses for every wallet avatar in the app (`account_drawer.dart:672`), not a new accent use; it identifies "this is an avatar," the same job it does everywhere else |

**Accent reserved for:** nothing on this screen. This is a deliberate, stated zero — not an
oversight — because CHILD-01/CHILD-02/VER-01 scope this phase to reads only. A future reviewer
should not add a gradient "refresh" or "view" affordance here on the assumption every screen needs
one; Phase 37 owns the write actions that will actually earn the accent.

No new color pairing needs fresh contrast math: `surfaceWell`, `borderSubtle`, `textSecondary`,
`textPrimary`, `statusError`/`statusErrorText` and `brandPrimaryStrong`/`textOnBrand` are all
pre-measured, existing pairings (see `gw_colors.dart`'s own field docs and `AccountAvatar`'s
pre-existing consumer). No raw hex, no `Colors.*`, appears in this contract.

## Screen Contracts

### `/child-wallets` (new top-level `GoRoute`, sibling of `/network`)

```
GoRoute('/child-wallets')
└ GWScreen(appBar: AppBar(title: Text('Child wallets')), scroll: false)
    SafeArea > Padding(space10 h / space8 v) > ConstrainedBox(maxWidth 1200, centered)
    Column
    ├ Identity banner (surfaceWell well, ALWAYS rendered — D-08)
    │   [36px avatar] [space6] [Expanded: mainWalletName / shortAddress] [refresh IconButton]
    ├ SizedBox(space8)
    ├ Expanded(
    │     ListView.separated(children: ChildWalletRow, separator: Divider(borderSubtle))
    │     (or) GWEmptyState('No child wallets registered under this account.')   — connected, empty
    │     (or) GWEmptyState('Node not running')                                   — disconnected
    │     (or) GWErrorState("Couldn't load child wallets", onRetry: ...)          — query failure
    │   )
    └ [if populated or connected-empty] SizedBox(space6) + lag note
        "Balances come from the node's synced view and can lag." (bodySm/textSecondary)
```

- **Visual focal point:** the identity banner's title (the main's linked wallet name) — the screen
  answers "whose children am I looking at," so that name is the first thing the eye should land on,
  ahead of any individual child row. This mirrors the same "name the account before the list" order
  `AccountSwitcherDrawer` already establishes (Phase 35, "Sending from"/"Node running as" headers
  read before their rows).
- The lag note is **omitted**, not merely styled empty, in the disconnected and error branches — a
  note about balance freshness is meaningless when there is no data or no connection to have lagged.
- Row order is the order the SDK returns (D-07) — no client-side sort.
- **No confirm step, no navigation away, no destructive action anywhere on this screen** — it is
  read-only by construction (CHILD-01/CHILD-02/VER-01 scope).

### `SDKAccountRow`'s menu (`lib/account/sdk_account_manager.dart`)

No layout change to the row or the `MenuAnchor` trigger. One new `MenuItemButton` in the existing
`menuChildren` list, positioned and styled per the Component Inventory row above. The row's own
`GWSelectRow` body, avatar, title/subtitle and the four pre-existing menu items are otherwise
byte-identical to today.

## UI Considerations

Applicable state considerations resolved: 11 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Connected, zero children registered | ✅ covered | `GWEmptyState('No child wallets registered under this account.')`, D-08. |
| empty | Node not running | ✅ covered | `GWEmptyState('Node not running')`, D-08 — header still renders (never hidden). |
| loading | Initial list read / manual refresh / 10s poll tick | ✅ covered (N/A by construction) | D-15: all child-wallet reads are synchronous, main-isolate CRDT reads — there is no async gap for a spinner to occupy, the same reasoning `GeniusBalanceDisplay`'s own un-spun 10s poll already relies on. No loading state is rendered at any point. |
| error | Query failure (`GENIUS_NODE_ERROR_REGISTRATION` or other non-OK) | ✅ covered | `GWErrorState("Couldn't load child wallets", onRetry: ...)`, D-08. |
| populated | 1+ children, mixed linked/unlinked/zero-balance | ✅ covered | Specified in Screen Contracts and the Component Inventory row-shape entry. |
| partial | Child with no linked wallet | ✅ covered | Row reads "Unlinked" + short address (D-04), neutral placeholder avatar — same geometry as a linked row, no layout jitter. |
| partial | Child with a zero GNUS balance | ✅ covered | Balance renders as literal `0.00 GNUS`, never a "syncing" placeholder — the SDK cannot distinguish the two (D-09), so the UI must not guess either. |
| overflow / long-text | Long linked-wallet name (banner title or row title) | ✅ covered | `maxLines: 1` + ellipsis on both, matching `GWSelectRow`'s/`SDKAccountRow`'s existing title overflow handling — no new truncation rule invented. |
| long-text | Lag note on a narrow (mobile) width | ✅ covered | The note is a plain wrapping `Text`, not `maxLines: 1` — it is a full sentence meant to be read, not a label, so 2-line wrap is the correct behaviour, not an overflow. |
| overflow | Long child count squeezing the trailing balance at narrow width | ✅ covered | Row title/subtitle sit in `Expanded`, trailing balance is a fixed-content `Text` outside the flex — the balance never gets pushed off-screen or overlapped, the same shape `GWSelectRow`'s `trailing` slot already guarantees. |
| zero-one-many | 0, 1, or N children | ✅ covered | `GWScreen(scroll: false)` + an `Expanded` `ListView` — the list scrolls independently of the page chrome for any N, rather than nesting an unbounded list inside `GWScreen`'s own scroll view (which would either fail to lay out or silently cap at N=1 screen's worth). |
| zero-one-many | Menu-item gate: exactly one SDK row (the one the node runs as) can ever open this screen at a time | 🧪 backstop | { statement: "Exactly one SDKAccountRow's 'Child wallets' item is enabled at any moment — the currently-selected row — and every other row's item is visibly dimmed via the menu's existing disabled treatment", verification: backstop } |
