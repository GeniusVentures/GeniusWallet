## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → Sentry | Free-text feedback message (≤2000 chars) is uploaded to a third-party ingestion service. |
| device disk → Sentry | Auto-attached `sgnslog.log`/`sgnslog2.log` (whole or last 1 MiB) leave the device with the report. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Information Disclosure | auto-attached SDK logs → Sentry | medium | accept | Pre-existing mechanic, unchanged (M-01). This re-skin REDUCES the risk of surprise: the new receipt row (D-03) surfaces exactly which files, sizes, and TAIL trims will be sent before the user taps Send — consent is now explicit, not buried in one grey sentence. |
| T-19-02 | Tampering | user feedback message → captureFeedback | low | accept | Message is passed to `SentryFeedback(message:)` verbatim exactly as today; validation/sanitization is Sentry-side. `maxLength: 2000` bounds the field. No new sink introduced. |
| T-19-03 | Information Disclosure | `feedback_type` tag | low | accept | New tag value is a fixed enum ('bug'|'idea'|'question'), never free text — no user data leaks through the new dimension. |
</threat_model>
