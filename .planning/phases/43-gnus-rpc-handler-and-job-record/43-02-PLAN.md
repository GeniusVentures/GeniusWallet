Additions to lib/gnus_bridge/gnus_job_store.dart (names final unless the analyzer forces a change):
- `factory GnusJobStore.app()` -> `GnusJobStore(Hive.box<String>(gnusJobsBoxName))`. The only place outside `lib/hive/` that names the box; widgets never call `Hive.box` (AGENTS.md layering).
- `GnusJob? byJobId(String jobId)`: exact match on a non-null `jobId` (every record has a null `jobId` until SDK-JOBID lands, so this returns null today).
- `GnusJob? byIdempotencyKey(String origin, String key, {DateTime? notBefore})`: the newest record whose `origin` and `idempotencyKey` both match exactly and, when `notBefore` is given, whose `submittedAt` is not before it.
- `({List<GnusJob> jobs, String? nextCursor}) page({required String sdkAddress, required int limit, String? cursor})`: records whose `sdkAddress` equals the argument (both lowercased), ordered by `submittedAt` descending then lowercased `burnTxHash` descending; starts strictly after the cursor position; `nextCursor` is the cursor of the last returned record when more remain, else null. Throws `FormatException` for a cursor it cannot decode.
- Cursor encoding (Claude's discretion): `base64Url` of the UTF-8 string `<submittedAt microsecondsSinceEpoch>|<lowercased burnTxHash>`. Opaque to the page.
- All lookups scan decoded `box.values`; a value that fails `GnusJob.decode` is skipped and counted in one `debugPrint` of the count only. Mark the scan with a `// ponytail:` comment: linear scan, fine to a few thousand jobs; upgrade is a secondary index key per origin and idempotency key pointing at the burn hash.

lib/hive/constants/cache.dart: `const String gnusJobsBoxName = 'gnusJobs';`

Handler additions (lib/gnus_bridge/gnus_rpc_handler.dart):
- `gnus_listJobs` params `{limit?, cursor?}` -> `{jobs: [Job], nextCursor}`.
- `gnus_getJob` params exactly one of `{jobId}`, `{burnTxHash}`, `{idempotencyKey}` -> `Job` map plus `result: null`, or `null` when nothing matches.
- A private in-flight state: a bool for the one burn the wallet allows at a time, and the `origin|idempotencyKey` it belongs to.

| handler -> Hive | records persist across restarts and back the replay decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-08 | Tampering / Repudiation | submit replay (reload, double click, WalletConnect timeout) | high | mitigate | idempotency lookup by origin and key within 24 h from the persisted record; body hash compared so a reused key with a new job is refused; restart test proves it holds on disk |
| T-43-09 | Tampering | concurrent submits double-burn | high | mitigate | one in-flight lock set synchronously before the first await, held through confirm and burn, released in `finally`; a retry of the in-flight key gets -32005, not a premature replay |
| T-43-10 | Information disclosure | cross-origin probing of results by guessed key | low | mitigate | `byIdempotencyKey` and `getJob` by key are scoped to the caller's origin |
| T-43-11 | Information disclosure | listJobs/getJob exposing another node account's jobs | medium | mitigate | page and getJob filter on the current `selectedSDKAccount` |
| T-43-12 | Denial of service | corrupt or oversized store values | low | mitigate | a value that fails decode is skipped; cursor and selector lengths are capped; store growth is bounded by phase 44 rate limits (linear scan marked `ponytail:`) |
| T-43-13 | Tampering | forged cursor | low | accept | the cursor only positions inside the current node's own records; a malformed one is -32602 |
