# Phase 26 Plan 08: Money moved, but not as asked Summary

Three states — paused, partial, refunded — now say in plain words where the money is, and the one
that can be acted on carries the aggregator's own link to act with.

Executed after the original agent went dormant mid-plan; see `26-07-SUMMARY.md` and STATE for the
branch-ownership note.

## Deviations from Plan

**[Precondition unmet, fixed as directed]** The plan's tracer required 26-05's outcome to expose the
status response's recovery URL. It did not — `status()` returned a bare `SwapStatus`. Per the
precondition's own instruction, the adapter now captures it: `SwapSettlement { status, recoveryUrl }`
reads `axelarTransactionUrl` off the same body. **Nothing is composed from the hash**, proven by
mutation (below).

**[Design] Only the paused state offers a button.** The plan's Task 1 implies a button wherever a
link exists. A refunded swap's funds are already returning and a partial swap has already delivered,
so `offersRecoveryAction` gates it to `needsGas`. A control that cannot act is worse than none.

**[Beyond the plan's file list]** `test/dev/mock_transactions_sticky_test.dart` asserted a
hand-written fixture count (`11`); the three new dev rows made three unrelated cases red instead of
saying so. It now reads the fixture list's own length. `transaction_receipt_copy_test.dart` needed a
taller viewport — see below.

**Two failures that looked like defects and were not.** The receipt case reporting a "dropped
consumer" for `refunded` was the default 800×600 viewport: the added sentence pushed the Status row
below the built area. And six `packages/genius_api` files showed as modified twice — my own
`dart format` over that whole tree reflowing a generated FFI binding the package excludes from
analysis. Reverted both times; formatting is now scoped to touched files.
