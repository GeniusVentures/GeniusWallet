<objective>
Re-skin the SDK account manager (GAP-03) in place — drawer chrome, account rows, footer actions, and
the mnemonic/private-key entry dialogs — structure unchanged, only tokens and components change. The
underlying native SDK FFI calls are untouched; this plan re-skins chrome only.

Purpose: Criterion 5 (half) — the SDK account manager opens from the shell and wears the extended
design language with develop's behavior intact. Security-sensitive: the key-entry dialogs handle
mnemonic/private-key material; the re-skin must not introduce any logging of that input (V6, §Security).

Appearance correctness (04-02 D-02): `GeniusWalletColors` static getters are NOT an `InheritedWidget`, so a
re-skinned widget that reads them does not rebuild on a live appearance toggle and renders stale. This surface
therefore reads all appearance-aware colors from the `GWColors` `ThemeExtension` (fail-soft, in `build()` —
`Theme.of(context).extension<GWColors>() ?? GWColors.dark()`, lib/theme/gw_colors.dart) so it flips LIVE; only
mode-invariant brand/status tokens (brandPrimary, delete-red) remain on the static getters.

Output (artifacts this plan produces): a token-correct, appearance-aware `sdk_account_manager.dart`.
</objective>
