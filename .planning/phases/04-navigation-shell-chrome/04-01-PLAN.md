<objective>
Wire the appearance-aware theme app-wide — the phase linchpin (D-01). This plan is THEME-ONLY:
reconcile `theme.dart` so `getThemeData()` builds a real light AND dark `ThemeData`, make the OS
setting the first-launch default (D-03), wrap `MaterialApp.router` so a toggle repaints the whole
app, and undo the Phase-3 gallery workaround. It ends with the D-02 gallery re-walk gate, which
must pass before ANY shell/screen re-skin (04-02+) begins.

Purpose: Phase 3's verification proved that mounting `gw_*` components against develop's hardcoded
`ThemeData(brightness: Brightness.dark)` produces observable defects (text/icons not flipping,
button font unstyled) that are NOT port defects — they are the absence of the theme this plan lands.
Every later plan builds on a theme that actually flips.

Output (artifacts this plan produces): an appearance-aware `theme.dart`; a `gw_appearance.dart`
`load()` that honors the OS setting on first launch; a `MaterialApp`-level `ValueListenableBuilder`
wrap; a reverted gallery `Scaffold`; and a recorded dark-only component count from the re-walk.

NO shell, nav, Settings, drawer, or screen re-skin happens in this plan (D-01, hard boundary).
</objective>
