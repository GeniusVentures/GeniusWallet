<objective>
Re-skin the Settings screen (GAP-02) in place — structure, rows, and behavior unchanged, only tokens
and components change. Map develop's `Card`/`DropdownButton`/`TextFormField`/`SwitchListTile`/
`FilledButton`/`OutlinedButton` widgets to Phase 3 `gw_*` primitives per UI-SPEC §3.1.

Purpose: Criterion 5 (half) — Settings opens from the shell and wears the extended design language
with develop's behavior intact. A mechanical re-skin; no structural question (IA-clean per GAP-01).

Appearance-aware access path (04-02): this screen is one of 04-02's DEFERRED `migration_surface`
readers — 04-02 left it untouched precisely because THIS re-skin rebuilds it. So the screen's OWN
appearance-aware color/text reads must resolve from the `GWColors` ThemeExtension in `build()` —
`final gw = Theme.of(context).extension<GWColors>() ?? GWColors.dark();` — not from the
`GeniusWalletColors` static getters. Per 04-02 D-02, a widget reading the static getters renders
stale on a LIVE appearance toggle (they are not an InheritedWidget); reading the extension registers
the Theme dependency that forces a rebuild. Mode-invariant status colors (statusSuccess/statusError)
stay on the static getters. The GWSelect/GWSwitch/GWTextField components' own migration is handled
elsewhere; here we migrate the SCREEN's own chrome/text reads only.

Output (artifacts this plan produces): a token-correct, appearance-aware `settings_screen.dart` that
re-skins LIVE on toggle.
</objective>
