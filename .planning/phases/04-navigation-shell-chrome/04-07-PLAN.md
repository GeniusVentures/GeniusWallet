<objective>
Re-skin the build-time exception recovery screen (BEH-02, findings 11/12) — the visual only. Replace
the hardcoded-dark `Material(color: deepBlueTertiary)` recovery screen with a branded, appearance-aware
one (`GWErrorState`/`GWIcon` + `GWButton`, `surfaceBase`), keeping the "Go to Dashboard" handler and the
`ErrorWidget.builder`/`FlutterError.onError` wiring untouched. Verify the window-close SDK shutdown.

RECOVERY-SCREEN ROBUSTNESS (read before touching colors): this screen renders on a BUILD-TIME exception,
via a GLOBAL `ErrorWidget.builder` that can replace ANY widget that throws in `build()` — including a
widget ABOVE `MaterialApp`/`Theme` (a provider, the router, or the theme itself). There is therefore NO
guaranteed `Theme` ancestor at the point this screen mounts. So this plan DELIBERATELY does NOT adopt the
04-02 D-02 `Theme.of(context).extension<GWColors>()` context-read pattern here — that read returns null
(→ dark fallback) in exactly the theme-layer-crash cases the screen exists to survive, and it couples the
recovery screen to the subsystem that may be broken. Instead it uses the appearance-aware
`GeniusWalletColors` STATIC GETTERS, which resolve off the `GWAppearance` global singleton (loaded in
`main()` before `runApp`) with no `BuildContext`/`InheritedWidget` dependency. Consequence: the screen is
mode-appropriate at mount time but does NOT live-flip on an in-place appearance toggle — that is a
deliberate NON-GOAL for a crash screen (nobody toggles appearance mid-crash). This is the intentional
INVERSE of the 04-02 migration: context-reads are correct for normal const components; static getters are
correct for the recovery screen.

Purpose: Criterion 6 — a build-time exception renders the branded recovery screen rather than the red
error box, and closing the window shuts the SDK down on every platform. This closes BEH-02 for Phase 4.

Scope note (D-08): BEH-02's `!_dirty`/`GlobalSwapFabHost` sub-clause is DEFERRED out of Phase 4 to the
swap-FAB phase — the crashing component is not built here. This plan MUST NOT scope any
`GlobalSwapFabHost` work. Criterion 1's general clause (boot, every route, no exception) is walked in
04-03; its `!_dirty`-via-`GlobalSwapFabHost` sub-clause is N/A this phase (D-08).

Output (artifacts this plan produces): a re-skinned recovery screen in `main.dart`.
</objective>
