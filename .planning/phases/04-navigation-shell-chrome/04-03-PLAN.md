Purpose: Criterion 2 — the shell wears the skin and every route stays reachable. Depends on 04-01's
theme (a re-skinned shell that still reads `deepBlueCardColor` would reintroduce the dark-only surface
problem 04-01 exists to close). CRITICAL access-path constraint (04-02 D-02): both shell widgets are
`const`-instanced (`appBar: const _DesktopTopBar()`, `bottomNavigationBar: const _MobileTabBar()`), so
they must read appearance-aware surfaces/text/borders from the `GWColors` ThemeExtension (04-02) in
`build()` — NOT the `GeniusWalletColors` static getters. A const widget reading the static getters does
not rebuild on a live appearance toggle (Flutter short-circuits identical const children before `build()`
re-runs) and renders stale; reading `Theme.of(context).extension<GWColors>()` registers the InheritedWidget
dependency that forces the rebuild. `responsive_overlay.dart` is one of the DEFERRED readers in 04-02's
`migration_surface` — deferred precisely because THIS plan rebuilds the surface, so 04-03 owns its GWColors
migration.

Output (artifacts this plan produces): a token-correct, appearance-aware `responsive_overlay.dart`.

This plan starts only after the 04-01 D-02 re-walk gate has closed (D-01/D-02).
</objective>
