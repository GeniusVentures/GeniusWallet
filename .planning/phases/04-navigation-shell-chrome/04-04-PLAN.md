Appearance-color access path (04-02 alignment): this drawer surface is one of 04-02's DEFERRED
`migration_surface` readers — 04-02 deferred it precisely because THIS plan rebuilds it. The drawer row
is built by `_buildDrawerRow` (a non-const `ListTile`) inside a `BlocBuilder<AppBloc, AppState>` that
does NOT depend on `Theme`; reading appearance-aware colors from `GeniusWalletColors` static getters
therefore renders STALE on a live toggle while the drawer is open (the 04-02 D-02 failure applies even
though the row is non-const, because no Theme dependency is registered). So all appearance-aware
surface/text/border colors MUST be read via `Theme.of(context).extension<GWColors>() ?? GWColors.dark()`
(the fail-soft pattern from 04-02, lib/theme/gw_colors.dart). Mode-invariant brand/status tokens
(brandPrimary, textOnBrand, statusError) stay on the static getters. GWColors already carries every
appearance-aware field this surface needs (surfaceElevated/surfaceMenu, textPrimary, textPrimary70,
textSecondary, borderSubtle) — no new GWColors field is required.

Second revision (widened scope): the drawer row and its rename/delete dialogs render through three SHARED
chrome components that 04-02 explicitly deferred into its `migration_surface` list rather than migrating —
`lib/components/cards/gw_card.dart`, `lib/components/overlays/gw_dialog.dart`, and
`lib/components/bottom_drawer/bottom_drawer.dart` (04-02-SUMMARY's Deferred Long-Tail Boundary). Each still

04-02 fixed for the other 11 components. Because this plan re-skins the drawer row (which may adopt
`GWCard`) and re-skins the delete/rename dialogs onto `GWDialog` (its first real, non-gallery consumer),
this is the correct plan to migrate all three in place (Task 1). A fourth file joins this same migration —
`lib/components/bottom_drawer/responsive_drawer.dart` — see below. `GWCard` and `GWDialog` are used app-wide
— migrating them changes how EVERY current and future screen renders those surfaces, which is intended
(they should be appearance-aware everywhere) — but every migrated read in this task keeps its color VALUE

`GWColors` already carries every field these four files need (`surfaceMenu`, `textPrimary`,
