<objective>
Fix the two bugs the 04-01 D-02 gallery re-walk surfaced before any screen re-skin (04-03..07) begins.
(1) Introduce a `GWColors` `ThemeExtension` that carries the appearance-aware color tokens currently
exposed as STATIC GETTERS on `GeniusWalletColors`, attach it to the `ThemeData` that `getThemeData()`
already builds per mode, and migrate the components the re-walk proved stale to read those tokens from
`Theme.of(context)` — so `const` widgets re-skin on a LIVE appearance toggle. (2) Bundle the Inter font
so text loads offline instead of fetching over the network via `google_fonts`.

Purpose: The 04-01 re-walk proved the theme now flips app-wide, but `const` subtrees keep stale colors
(their `build()` never re-runs because `GeniusWalletColors.*` is not an `InheritedWidget`), and Inter
text falls back to a platform font offline. Both undermine the "live re-skin" foundation every later
Phase-4 plan builds on. This plan is corrective and MUST land before the 04-03..07 re-skins.

Output (artifacts this plan produces): a `GWColors` ThemeExtension wired into `theme.dart`; a set of
const-safe migrated components; a bundled Inter font family with the network path removed; and a
re-run D-02 gallery re-walk that supersedes/closes the 04-01 gate.

SCOPE BOUNDARY (re-skin, never restructure): this plan changes only the color ACCESS PATH and the font
LOADING path. Zero color values change; zero widget structure/order/behavior changes. The long tail of
appearance-aware reads in surfaces that 04-03..07 already rebuild is DEFERRED to those plans (recorded
explicitly below, not silently capped).
</objective>
