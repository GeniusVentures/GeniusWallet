# Phase 35 — UI Design Contract

> Visual and interaction contract for the unified header switcher. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **THIS IS A MERGE + RESTRUCTURE, NOT A NEW VISUAL LANGUAGE.** Every token, row shape, badge and
> footer button below already exists on `develop` (Phase 34 shipped the badges; account_drawer.dart
> already contains `_AccountSectionHeader`/`_AccountSectionNote`/`_RowBadge`/`GWSelectRow` rows;
> sdk_account_manager.dart already contains the SDK row body and its four-item menu). This document
> does not invent a component — it locks which existing pieces move into one drawer, in which order,
> and the handful of copy/behaviour deltas D-01..D-14 require. Scope is fenced by `35-CONTEXT.md`:
> SWT-06 (pending-op switch lock) and child wallets are out of this phase.

## Color

60/30/10 discipline, all via `GWColors`. No new token is added by this phase.

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surfaceBase` | Page background behind the header (unchanged) |
| Secondary (30%) | `surfaceWell` (`#06080C` dark / `#EFF2F6` light) | The header control-track fill the chip sits inside (unchanged); `surfaceMenu`/panel fill for the drawer (shell-owned) |
| Accent (10%) | `brandPrimaryOnSurface` | The "SDK" (linked) badge label only |
| Accent, second use | `brandSecondary` (`#2BF5B4`) | The "ACTIVE ON NODE" badge label only |
| Warning | `statusWarningText` (`#92400E` light / `#FFC42E` dark) | "SDK PENDING" badge label only |
| Destructive | `statusErrorText` | "Delete" menu items on both row kinds (unchanged) |
| Secondary text | `textSecondary` | Section captions' faint uppercase title, row subtitles, empty-state notes, the "no wallets/no SDK accounts" notes |
| Explanation text | `textPrimary80` | Section caption body sentence (already the deliberate choice in `_AccountSectionHeader` — 12.4:1, not `textPrimary38`) |
| Primary text | `textPrimary` | Row titles, chip label |

**Accent reserved for:** the two SDK-state badge labels (SDK / ACTIVE ON NODE) and the single
"Add wallet" gradient footer button. **Not** for section headers, **not** for the chip's idle state,
**not** for either menu's non-destructive items. This mirrors the reservation Phase 34 already
locked for these exact badges — this phase adds no new accent use.

No new color pairing needs fresh contrast math: every foreground/background pair above shipped and
was measured in Phase 34 (`34-02-SUMMARY.md`) or Phase 3/23 (`_AccountSectionHeader`'s own comment
cites 12.4:1). The one net-new text element — the "Sending from {walletName}" line on Swap — uses
`bodySm`/`textSecondary` on `surfaceElevated`, an existing pairing already verified in this exact
file family (Phase 8 UI-SPEC §Color, "Secondary text" row, 5.97:1 dark / 6.30:1 light).

| Empty state (no wallets at all) | "No wallets yet." (`_AccountSectionNote`, unchanged, D-08 keeps existing labels) |

## Screen Contracts

### Desktop control track (`responsive_overlay.dart:_buildActionRowWidgets`)

Today's track holds 3–4 fields (`NetworkDropdownSelector` · [`SDKAccountManagerButton`] ·
`AccountDropdownSelector` · `ReownConnectButton`), each separated by a 1px/22px `_trackDivider`
inside one `surfaceWell` pill. This phase collapses the SDK chip and the wallet chip into **one**
field:

```
[ NetworkDropdownSelector ] | [ AccountSwitcher ] | [ ReownConnectButton ]
```

- The conditional `if (sdkAccounts.isNotEmpty)` wrapper around the SDK chip is deleted — `AccountSwitcher`
  always renders (D-04), so the track never has a "phantom gap" for an absent chip (closes the
  `ponytail:` note at `responsive_overlay.dart:37-41` as a side effect, not a goal of this phase).
- Track height, `surfaceWell` fill, `borderSubtle` edge, `radiusPill` shape: **unchanged**.
- `AccountSwitcher` itself keeps the existing chip internals (`navContextChipStyle`, 25px avatar,
  label hidden below `GeniusBreakpoints.small`, `Icons.arrow_drop_down` trailing) — see Component
  Inventory.

### Mobile header (`mobile_header.dart:WalletPill`)

**No visual change to the trigger.** The 44px circular `WalletPill`, its `WalletIdentityAvatar`,
its `Semantics` label and the fixed 100px header cluster width are all unchanged (D-02). The single
edit is `onTap`: `AccountDrawer.show(context, includeNetwork: true)` becomes
`AccountSwitcherDrawer.show(context, includeNetwork: true)` — same `includeNetwork` contract (a
network field prepended, per D-03), same title-when-network-included behaviour, new two-section body
underneath.

### The switcher drawer

`ResponsiveDrawer.show` — side panel ≥`GeniusBreakpoints.medium` (768px), bottom sheet below,
`bodyPadding: EdgeInsets.zero` (rows own their own inset via the `ListView`'s
`EdgeInsets.all(space10)`, unchanged from today's `_AccountDrawerBody`). Title: `"Wallet and network"`
when opened with `includeNetwork: true` (mobile), else `"Accounts"` (desktop) — **unchanged strings**,
so `test/account/account_drawer_show_test.dart`'s `find.text('Accounts')` pin is not broken by this
phase (only the body composition changes).

```
ListView (padding: space10)
├ [if includeNetwork] Network field + _AccountSectionHeader-equivalent (unchanged from today)
├ _AccountSectionHeader('Sending from', 'Sends, swaps and balances use this wallet.')
├ …ownWallets.map(_buildDrawerRow)                          — GWSelectRow, SDK/SDK PENDING/
│                                                              ACTIVE ON NODE badges, own menu
│  (or) _AccountSectionNote('No wallets yet.')
├ SizedBox(space8)
├ _AccountSectionHeader('Node running as', 'The GNUS node processes and earns as this account.')
├ …sdkAccounts.map(_buildAccountRow)                          — GWSelectRow, + View balance menu item
│  (or) _AccountSectionNote('Node not running')                — node disconnected
│  (or) _AccountSectionNote('No SDK accounts yet')             — connected, zero accounts
├ SizedBox(space8)
└ GWButton('Add from phrase or key', secondary, sm)            — under the Node section, D-09
Footer (shell-owned, outside the ListView):
└ GWButton('Add wallet', gradient, lg, expand)                 — D-09
```

Row order within "Sending from" is unchanged from today's `ownWallets` order. Row order within
"Node running as" is unchanged from today's `sdk_account_manager.dart` order (selected/start-account
sorting, if any, stays as-is — this phase does not reorder SDK accounts).

### Send review drawer (`send_transaction_details.dart`)

The `GWCopyRow(label: 'From', value: fromAddress)` row (line 78) becomes
`GWCopyRow(label: 'From', value: fromAddress, caption: fromWalletName)` — the row grows one line
(wallet name above the mono address), the copy icon and its full-address copy behaviour are
unchanged. `send_screen.dart:269`'s call site gains one new argument, `fromWalletName:
cubit.walletDetailsState.selectedWallet?.walletName ?? ''` (or the cubit's existing wallet accessor —
planner's call on the exact plumbing, not a visual question).

### Swap screen (`swap_screen.dart`)

No confirm step (D-13, explicit). One new line above the existing CTA button
(`swap_screen.dart:777` area), per the Component Inventory row above. The line never appears without
a selected wallet (swap already requires one to compute a quote), so no empty-state variant is
needed here.
