# Deployed `bridgeOut` ABI per chain (checked 2026-10-28)

Raised in review of PR #294. Read-only check over public RPCs: diamond loupe `facetAddress(bytes4)` and
`facetFunctionSelectors(address)`, plus an `eth_call` of the 3-arg form on Sepolia.

- Wallet encodes `bridgeOut(uint256 amount, uint256 id, uint256 destChainID)`, selector `0xe26d65a6`,
  `id` hardcoded 0 (GNUS), destination 15305752297694 (SuperGenius testnet).
- Current `gnus-ai-contracts` `GNUSBridge.sol` (facet, commit 36069bdc, 2026-06-18):
  `bridgeOut(uint256,uint256,uint256,bytes32 sgnsDestination,bool destinationYOdd)`, selector
  `0xa5a5aa20`; reverts on a zero destination.

| Chain | 3-arg | 5-arg |
|---|---|---|
| Ethereum 1, Polygon 137, BNB 56, Base 8453 | no | no |
| Sepolia 11155111 | no (reverts "Function does not exist") | yes |
| Amoy 80002 | yes | no |
| BNB Testnet 97 | yes | no |
| Base Sepolia 84532 | no | no |

So the wallet's burn works only on Amoy and BNB Testnet today. The 5-arg form would take
`sgnsDestination` = X (first 32 bytes of the SDK account's 64-byte X||Y key, which is what
`getSelectedAccountAddress()` already returns) and `destinationYOdd` = low bit of Y's last byte, per
SuperGenius `BridgeRelayer.cpp`. Not verified: a real 5-arg transaction, the relayer being live per chain.
The wallet's chainstack RPCs for Amoy and BNB Testnet return 401 (publicnode used instead).

Open: version-select per chain (by loupe lookup or a static table) and the 5-arg encoding, before any
claim of compatibility with the new bridge. Not fixed in PR #294.

## Crediting rule (2026-10-28)

Owner: `walletCreditsBurn` in `packages/genius_api/lib/web3/bridge_out_abi.dart`, applied in `GeniusApi.bridgeOut`
for every caller. 5-arg chain: the relayer mints from `BridgeOutInitiated` to `sgnsDestination`; the wallet never
calls `GeniusSDKMint`. 3-arg chain: the relayer ignores `BridgeSourceBurned`, so the wallet mints after a successful
burn, under the account gate as the confirmed account; a failed or mismatched mint keeps the hash as a recoverable
outcome (`bridgedNotProcessed` on the job paths, "Not confirmed yet" on the token bridge screen). Dependency:
SuperGenius `MintFunds` dedups on chainId+hash, and wallet and relayer pass different chain ids, so cross-node dedup is
unconfirmed. If the relayer starts handling 3-arg events, the rule must change.
